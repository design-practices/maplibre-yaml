Map and story documents can now be written in JSON or TOML as well as YAML, with the same validation and the same line-and-column diagnostics in every format. `<ml-map>` and `<ml-scrollytelling>` read all three from `src` (by extension or content type), inline `<script type="application/toml">` (and the YAML and JSON types), the `config` attribute and property, and `update(text)`. The format comes from the label when there is one and is sniffed otherwise. The TOML reader is a separate chunk downloaded the first time a page meets a TOML document, so YAML and JSON pages download nothing new. Errors name their format ("JSON syntax error", "TOML syntax error"), carry a new `format` field, and TOML syntax errors use the new `toml-syntax` code; TOML gets hints for unquoted colours, `null` (omit the key) and dotted keys. Changed: the `config` attribute and `update(string)` now read text through the same parser as `src`, so they accept YAML and TOML too, and a duplicate key in JSON there is an error instead of the last value winning. New in core: `parseDocumentText(text, options)`, `convertDocument(text, { to })` (converts the authored document between the three formats, keeping key order and inline expressions, and reports comments, expanded anchors and dropped nulls) and `normalizeDocumentValue(value)`. In every format a root `$schema` key is accepted (and removed before rendering), nested tables under `locale` flatten to dotted keys, and date values become text; the published JSON Schemas accept both. An inline script of an unsupported type is named in the error card instead of "No configuration provided".

The CLI's `validate`, `preview` and `emit` read all three formats; `mlym validate <folder>` also finds JSON and TOML documents by their content (a broken one still joins the run and fails), skipping other JSON and TOML files, with `--verbose` listing what it skipped and a clear message for a folder with no documents. New: `mlym convert <file> --to yaml|json|toml [--out] [--strict]`. Astro's `loadMapConfig`, `loadScrollytellingConfig`, `loadYAML` and `loadFromGlob` pick the format by extension, dev reload watches `.toml`, and content-collection schemas normalize entries first, so TOML collection entries with nested locale tables or dates validate.
