PMTiles, FlatGeobuf, GeoParquet and Cloud Optimized GeoTIFF (COG) files now work from YAML alone, with no page JavaScript: in plain HTML from the CDN, under Vite and Astro, in `<ml-map>` and `<ml-scrollytelling>`, and in v1 and v2 documents. A full basemap can come from a single `.pmtiles` file too. Keep `type:` as the MapLibre source type and point `url:` at the file: a `.pmtiles` file (or `pmtiles://` URL) on a `vector`, `raster` or `raster-dem` source; a `.fgb`, `.parquet` or `.geoparquet` file on a `geojson` source; a `.tif`/`.tiff` file (or `cog://` URL) on a `raster` or `raster-dem` source. Add `format:` only for a URL without a telling extension. Core registers the `pmtiles://` and `cog://` protocols once on the maplibre-gl module it renders with, before any map is created, and keeps a page's own registration; so a basemap style loaded from a URL can use `pmtiles://` as well, and relative URLs inside such a style (the file inside `pmtiles://`, TileJSON, tiles, sprite and glyphs) resolve against the style.json itself. The Protomaps basemap shorthand, `mapStyle: { pmtiles: data/nyc.pmtiles, flavor: dark, lang: es }` (`basemap:` in v2; also accepted as `defaultMapStyle` and by the Astro map builders' `mapStyle` option), builds the Protomaps basemap style in the page around a Protomaps `.pmtiles` extract, with no API key and no tile server: the `light`, `dark`, `white`, `grayscale` or `black` flavor, labels in `lang:` or else in the page's language, OpenStreetMap and Protomaps attribution, and Protomaps' hosted fonts and icons unless `glyphs:` and `sprite:` name your own copies. The document's layers draw on top, and `before:` and story chapters can name the basemap's layers by id. FlatGeobuf and GeoParquet files are read into an ordinary GeoJSON source, so popups, legends, `classify:`, `fitTo` and clustering work unchanged; `load: viewport` reads only the features in view from a large file (one with a FlatGeobuf spatial index, or a GeoParquet `bbox` covering column and location-sorted row groups), and size guards keep a too-big file from freezing the tab. GeoParquet reads only the columns the document uses (`columns:` chooses them, `columns: all` reads every one), opens a file with a single request, and reads WKB geometry from snappy, zstd, gzip, lz4 or brotli files. A COG on a `raster` source draws as imagery; on a `raster-dem` source it is elevation for `hillshade` layers and 3D `terrain:`. A COG holding a single band of values (a vegetation index, a temperature) is coloured with `colorRamp: { palette, min, max }`, using the `classify:` palette names or your own `colors:`, and `fitTo` frames a COG's own extent. COGs must be in Web Mercator (EPSG:3857): a file in another projection is refused with the `gdalwarp` command that converts it, and a GeoTIFF that isn't cloud-optimized still draws, with an author hint giving the `gdal_translate -of COG` command. `base` now applies to the file inside a `pmtiles://` or `cog://` URL and to the basemap shorthand's `pmtiles:`, `glyphs:` and `sprite:`, so relative paths work on GitHub Pages project sites. When a file fails, the map's notice says why in plain words, and the rest of the map still draws: a server without range requests (`python -m http.server`), CORS, a wrong path that returned a web page, a missing file, a file in the wrong projection, a Zstandard-compressed FlatGeobuf, GeoArrow-encoded GeoParquet geometry (with the command that rewrites it as WKB), a Parquet file without geometry metadata, a PMTiles file that isn't a Protomaps basemap, a file too large to read whole, or a Content Security Policy that refuses the COG reader's `blob:` workers (the notice names `worker-src 'self' blob:`). Validation reports, each with the fix: `type: pmtiles` / `flatgeobuf` / `geoparquet` / `cog` / `mbtiles`; a format on the wrong source type; live data (`refresh:` / `stream:`) on a FlatGeobuf or GeoParquet source; `format: parquet` (did you mean `geoparquet`); a misspelt basemap flavor, key or palette; and a basemap `pmtiles:` that isn't a `.pmtiles` file. `mlym emit` writes PMTiles sources as `pmtiles://` URLs, a Protomaps basemap as the full style it generates, and COG sources as `cog://` URLs (with `#dem`, the `colorRamp:` as `#color:`, and `tileSize: 256`); the exported style then needs those protocols registered. It converts FlatGeobuf and GeoParquet files to inline GeoJSON, and classify breaks computed at export read both. The readers are bundled inside core, so there is nothing extra to install, and they are not part of core's main script: a page downloads a reader only when a map uses its format (see the entry on on-demand format readers). Cloud-native support adds about 15 KB gzip to the CDN build `register.browser.js`. Across the whole 0.9 release, including thematic maps, translatable UI strings and number formatting, `register.browser.js` grows from about 124 KB to about 167 KB gzip compared with 0.8.1.
