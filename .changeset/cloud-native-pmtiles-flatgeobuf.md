PMTiles, FlatGeobuf and Cloud Optimized GeoTIFF (COG) now work from YAML alone — no page JavaScript, in plain HTML from the CDN, under Vite/Astro, in `<ml-map>`, `<ml-scrollytelling>` and v1/v2 documents. Keep `type:` as the MapLibre source type and point `url:` at the file: a `.pmtiles` file (or `pmtiles://` URL) on a `vector`, `raster` or `raster-dem` source, a `.fgb` file on a `geojson` source, a `.tif`/`.tiff` file (or `cog://` URL) on a `raster` or `raster-dem` source; add `format:` only for a URL without a telling extension. Core registers the PMTiles protocol once on the maplibre-gl module it renders with, before any map is created (a page's own `pmtiles` registration is kept), so a basemap style loaded from a URL can use `pmtiles://` too: a Protomaps basemap, or one hosted next to the site as a single PMTiles extract. Inside such a style, relative URLs (the file inside `pmtiles://`, TileJSON, tiles, sprite and glyphs) resolve against the style.json itself, and a missing file gets a notice instead of a blank basemap. Core reads FlatGeobuf into an ordinary GeoJSON source, so popups, legends, `fitTo` and clustering work unchanged; `load: viewport` reads only the features in view from large indexed files, and size guards keep a too-big file from freezing the tab. A COG on a `raster` source draws as imagery; on a `raster-dem` source it is elevation that drives `hillshade` layers and 3D `terrain:` (core sets the `#dem` mode, `encoding` and `tileSize: 256` the COG reader needs); a single band of values (a vegetation index, a temperature) is coloured with `colorRamp: { palette, min, max }`, using the same palette names as `classify:` (or your own `colors:`), with a did-you-mean for a misspelt palette; and `fitTo` frames a COG's own extent. COGs must be in Web Mercator (EPSG:3857): one in another projection, which would otherwise draw as a blank rectangle, is refused with the `gdalwarp -t_srs EPSG:3857 -of COG` command that converts it, and a GeoTIFF that isn't cloud-optimized still draws, with an author hint giving the `gdal_translate -of COG` command. Core reads COGs with `@geomatico/maplibre-cog-protocol`, registering `cog://` once on the maplibre-gl module it renders with (a page's own `cog` registration is kept); a site whose Content Security Policy refuses `blob:` workers gets a notice naming `worker-src 'self' blob:`. `base` now applies to the file inside a `pmtiles://` or `cog://` URL, and to a `.tif` path (these 404'd on GitHub Pages project sites). Failures — a server without range requests (`python -m http.server`), CORS, a wrong path that returned a web page, a missing file, a projected or Zstandard-compressed FlatGeobuf, a COG in the wrong projection, a file too large to read whole — appear in the map's notice in plain words. `type: pmtiles` / `flatgeobuf` / `cog` / `mbtiles` and a format on the wrong source type (a `.tif` on a `geojson` source) are validation errors with the fix; GeoParquet (`.parquet`) is recognized and reported as "not supported yet", so documents written today keep their meaning when it lands. `mlym emit` writes PMTiles sources as `pmtiles://` URLs and COG sources as `cog://` URLs (with `#dem`, the `colorRamp:` as `#color:`, and `tileSize: 256`; the exported style needs the COG protocol registered, as it needs PMTiles') and converts FlatGeobuf files to inline GeoJSON. The readers ship inside core, so there is nothing extra to install, and installing core no longer pulls in OpenLayers, which the flatgeobuf package lists as an optional dependency, nor geotiff.js. They are not part of core's main script: a page downloads a reader only when a map uses its format (see the entry on on-demand format readers). Cloud-native support adds about 10 KB gzip to the CDN build `register.browser.js`; the readers themselves (about 8 KB gzip for PMTiles, 12 KB for FlatGeobuf, 221 KB for COG: the plugin, geotiff.js and its codecs) load only when needed. Across the whole 0.9 release, including thematic maps, translatable UI strings and number formatting, `register.browser.js` grows from about 124 KB to about 161 KB gzip (+37 KB) compared with 0.8.1.
