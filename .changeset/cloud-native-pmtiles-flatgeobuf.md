PMTiles and FlatGeobuf now work from YAML alone — no page JavaScript, in plain HTML from the CDN, under Vite/Astro, in `<ml-map>`, `<ml-scrollytelling>` and v1/v2 documents. Keep `type:` as the MapLibre source type and point `url:` at the file: a `.pmtiles` file (or `pmtiles://` URL) on a `vector`, `raster` or `raster-dem` source, a `.fgb` file on a `geojson` source; add `format:` only for a URL without a telling extension. Core registers the PMTiles protocol once on the maplibre-gl module it renders with (a page's own `pmtiles` registration is kept), and reads FlatGeobuf into an ordinary GeoJSON source, so popups, legends, `fitTo` and clustering work unchanged; `load: viewport` reads only the features in view from large indexed files, and size guards keep a too-big file from freezing the tab. `base` now applies to the file inside a `pmtiles://` URL (these 404'd on GitHub Pages project sites). Failures — a server without range requests (`python -m http.server`), CORS, a wrong path that returned a web page, a missing file, a projected FlatGeobuf, a file too large to read whole — appear in the map's notice in plain words. `type: pmtiles` / `flatgeobuf` / `mbtiles` and a format on the wrong source type are validation errors with the fix; GeoParquet (`.parquet`) and COG (`.tif`, `cog://`) are recognized and reported as "not supported yet", so documents written today keep their meaning when they land. `mlym emit` writes PMTiles sources as `pmtiles://` URLs and converts FlatGeobuf files to inline GeoJSON. The decoders are bundled in this release: the CDN build grows by about 26 KB gzip (about 19 KB of it the pmtiles and flatgeobuf readers), with no extra downloads.
