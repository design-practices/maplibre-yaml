A changed document updates the running map in place. Assigning a different `config` or `src` to `<ml-map>` (or calling `reload()`, or changing `base`) now validates the whole document, then changes only what differs from the document the map shows: layers and sources by id, properties through MapLibre's setters, the legend, panel, markers and popups after them. The map object, its camera, your listeners and the layers you added through `getMap()` stay as they were; the camera moves only when the document's own camera changed (`camera="host"` on the element, or `camera: 'host'` on `MapRenderer`, keeps an update from ever moving it). An invalid document leaves the map untouched and reports why. A changed `mapStyle` still rebuilds the map, at the current camera, with no blank frame. The new element method `update(doc)` does the same as `config` and resolves with the outcome (`applied`, `rejected`, `fallback` or `superseded`) and a summary of what changed; `getDocument()` returns the document the map shows. The events are `ml-map:update-applied` (`{ summary }`), `ml-map:update-rejected` (`{ kind, errors }`) and `ml-map:state-change` (`{ values, changed }`), with `onml-map:*` props for React 19 and `update:applied`, `update:rejected` and `state:change` on `MapRenderer`. Trust is fixed per map: an update applies under the `capabilities` the renderer was built with and neither raises nor lowers them. Before 0.10, every new document rebuilt the map from scratch, reset the camera to the document's and made `getMap()` return a new object; pages that relied on the reset re-apply the document camera on `ml-map:update-applied`.

Hosts can read and write the document's `state:` values: `setState(values)` writes declared keys (an undeclared key throws), `getState()` returns the current values, and the params panel and `setState` are one state, each reflecting the other. A changed document's new default replaces a value unless a reader wrote it. Fixed: `state:` values now survive every style load, including a host's own `getMap().setStyle()` — before, a style change dropped them and layers reading `global-state` fell back to the style's own defaults (ml-u0l). The update engine ships as a separate `chunks/update.js` next to the script, downloaded on the first update.
