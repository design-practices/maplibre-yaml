The CDN build now loads format readers on demand, from files next to `register.js`. The PMTiles, FlatGeobuf, GeoParquet and COG readers and the Protomaps basemap style generator are not inside `dist/register.browser.js` (about 174 KB gzip). They are separate files in `dist/chunks/`, which the browser fetches relative to the script only when a map uses that format: `pmtiles.js` (about 8 KB gzip), `flatgeobuf.js` (about 12 KB), `geoparquet.js` (about 23 KB), `geoparquet-brotli.js` (about 68 KB, only for a brotli-compressed GeoParquet file), `cog.js` (about 131 KB), and `protomaps-basemap.js` (about 7 KB). Four more files hold image codecs for COGs, `cog-deflate.js`, `cog-jpeg.js`, `cog-lerc.js` and `cog-zstd.js` (about 5 to 48 KB each); they load only when an image is decoded outside the COG reader's background workers, so drawing a COG normally fetches none of them. A page without such a map downloads nothing extra, and on a map that uses one, only that format's sources wait for its reader: the rest of the map draws without it. Loading from unpkg or jsDelivr needs no change. If you host maplibre-yaml yourself, copy the whole `dist/` folder rather than a single file: when a reader can't be downloaded (a missing file, offline, a content blocker), the map's notice names the file and says what to do, and every other layer still draws; `reload()`, or the next tile the map asks for, downloads the reader again. The npm build splits the same way (`dist/formats/`, with shared code in `dist/shared/`), so Vite, Astro and webpack apps get the readers as lazy chunks of their own build; Node use (`mlym emit`, server rendering) works as before. `mlym preview` serves the reader files next to the bundle.
