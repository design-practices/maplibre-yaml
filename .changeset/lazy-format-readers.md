The CDN build now loads format readers on demand, from files next to `register.js`. The PMTiles, FlatGeobuf, GeoParquet and COG readers and the Protomaps basemap style generator are not inside `dist/register.browser.js` (about 167 KB gzip). They are separate files in `dist/chunks/`, which the browser fetches relative to the script only when a map uses that format: `pmtiles.js` (about 8 KB gzip), `flatgeobuf.js` (about 12 KB), `geoparquet.js` (about 23 KB), `geoparquet-brotli.js` (about 68 KB, only for a brotli-compressed GeoParquet file), `cog.js` (about 131 KB), `cog-deflate.js`, `cog-jpeg.js`, `cog-lerc.js` and `cog-zstd.js` (image codecs, fetched only when a COG needs one outside the reader's workers), and `protomaps-basemap.js` (about 7 KB). A page without such a map downloads nothing extra. Loading from unpkg or jsDelivr needs no change. If you host maplibre-yaml yourself, copy the whole `dist/` folder rather than a single file: when a reader can't be downloaded (a missing file, offline, a content blocker), the map's notice names the file and says what to do, and every other layer still draws. The npm build splits the same way (`dist/formats/`, with shared code in `dist/shared/`), so Vite, Astro and webpack apps get the readers as lazy chunks of their own build; Node use (`mlym emit`, server rendering) works as before. `mlym preview` serves the reader files next to the bundle.
