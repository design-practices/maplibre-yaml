Streams (`stream:` on a GeoJSON source) now behave as documented when the connection drops or never opens. An SSE stream the browser is reconnecting from no longer shows "The data for layer … didn't load (SSE connection error)": a drop is reported only if reconnecting gives up. `reconnect: false` now keeps a dropped SSE stream closed instead of letting the browser reconnect it, and says once that the stream closed. `reconnectMaxAttempts`, `reconnectDelay` and `reconnectMaxDelay` now take effect for WebSocket and SSE streams (they were ignored, and the first retry didn't wait); the browser's own SSE retries count toward `reconnectMaxAttempts`. Under `updateStrategy: merge`, stream messages now merge into the features of an inline `data:` block instead of replacing them on the first message. A stream whose first connection fails no longer removes its layer: the layer keeps its starting data, the map's notice says once that it isn't getting live updates, and the stream keeps retrying per the reconnect options. For code using the streaming classes directly: `BaseConnection` now emits `reconnecting` before every attempt and waits before the first one, makes at most `reconnectConfig.maxRetries` attempts, and has a public `reconnect()`; SSE and WebSocket drops are reported as `disconnect`, not `error`; and `StreamManager.connect()` still rejects when the first connection fails but keeps retrying in the background until `disconnect(id)`.
