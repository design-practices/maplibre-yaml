GeoParquet and FlatGeobuf files are now read whole when they are small and by view when they are large, with a limit you can see and change. Before, the GeoParquet guard counted only the compressed bytes of the columns a map reads, so an 857,000-row file that downloads as 47 MB passed it and was decoded on the page (142 MB of decoded columns, over 4 GB of memory and a page frozen for seconds). Both formats now check, before reading any data, how many features the file holds (GeoParquet's footer, FlatGeobuf's header) and, for GeoParquet, how large the columns it reads are once decoded. Up to 400,000 features (and 50 MB transferred, 100 MB decoded) a file loads whole, as in 0.9.1 — a 275,000-parcel borough still draws whole. Above that, a file that can be read in parts (a GeoParquet file with a `bbox` column and sorted row groups, an indexed FlatGeobuf) is read by view, and any other is refused with a notice that names the count and how to fix it. `load: { maxFeatures: N }` is the one override: above 400,000 it raises the whole-file limit for that source. The 100 MB decoded limit still applies, so a citywide parcel file is never loaded whole however high `maxFeatures` goes. Every notice and author hint about a large file now names its cause and each way to make it draw, with a command to run: add `load: viewport`; raise `maxFeatures` — offered only up to 600,000 features loaded whole or 250,000 in a view, with the memory it costs, since a raise past that froze the page for seconds; make the file readable by view (a `gpio sort hilbert` command that adds a `bbox` column and sorts it along a Hilbert curve, or an `ogr2ogr` command that adds a FlatGeobuf spatial index); or convert it to PMTiles, drawn at every zoom (a one-line `uv run --with tylertoo` command; a FlatGeobuf file is first converted with `gpio`, so no GDAL Parquet driver is needed); and it links the GeoParquet, FlatGeobuf and PMTiles guides. A refusal no longer tells a source that already says `load: viewport` to add it, or a host without range requests to read by view: it names what blocks reading by view (no `bbox` column, unsorted row groups, no spatial index, the hosting). A FlatGeobuf served compressed is now measured by its decompressed bytes, and the note that a large file is being read by view now reaches the page while the author is developing, not only the console.
