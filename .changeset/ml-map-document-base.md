New `base` attribute (and `base` property) on `<ml-map>` for sites published under a subpath, such as a GitHub Pages project site at `https://<user>.github.io/my-repo/`. With `base="/my-repo/"`, the paths to your own files in the document load from under it on every page: `/data/cities.geojson`, `data/cities.geojson` and `./data/cities.geojson` all load `/my-repo/data/cities.geojson`, so the YAML no longer needs the repo name written into every path. It applies to `src` and to every URL field of the document: `mapStyle`/`style.basemap` (and an inline style's `sprite`, `glyphs` and sources), source `url`, `tiles`, video `urls`, a GeoJSON `data` path and `stream.url`, `images:`, marker `icon:`, and popup `href` links. Full URLs (`https://…`, `//…`, `blob:`, `data:`) are never changed, and a path that already starts with the base is not doubled. Without `base`, nothing changes. When a `/…` path 404s on a page under a subpath and no base is set, the map's notice (and the error card for a `src` that 404s) now suggests the `base` to add. The resolver is exported as `resolveDocumentUrl`, `applyDocumentBase` and `normalizeDocumentBase` for hosts that render documents themselves.
