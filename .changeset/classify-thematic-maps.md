Thematic maps from YAML: a layer's new `classify:` block makes a choropleth, graduated symbols or a category map without hand-writing a `step`/`match` expression. Give explicit `breaks:` (MapLibre `step` convention: n breaks make n + 1 classes, and a value equal to a break takes the class above), or `method: quantile | equal | jenks` with `classes:` to compute breaks from a GeoJSON source's data when it loads, or `categories:` for a `match` with an `other:` colour (a `value: colour` map keeps the order you wrote, numeric codes included). Map a rate instead of a count with `normalize:` (and `multiply:`, e.g. `100000` for "per 100,000"): the division is guarded, so a missing, zero or non-numeric divisor counts as no data rather than Infinity, and breaks and legend labels are in the rate's units. Colours come from a named palette (the ColorBrewer set, `viridis`, `cividis`, `okabe-ito`; case-insensitive, with a did-you-mean that prefers the palette a short name starts) or a `colors:` list; `radius:` sizes circles per class. Missing, empty and non-numeric values draw a `noData:` colour (light grey by default) or are hidden, instead of the black MapLibre paints when a `step` input is null or a string; numeric strings from CSV-derived GeoJSON are read as numbers. `hover.highlight` works on classified layers like on any other.

Computed breaks need the whole dataset, so vector tile sources and FlatGeobuf sources read by view take explicit `breaks:`. Validation explains why for tiles and for `load: viewport` in any form. A FlatGeobuf file large enough to switch itself to reading by view draws in its no-data colour, with a notice asking for `breaks:`, rather than classes computed from the features in view. When the loaded data has no usable value for `field:` or `normalize:` (a misspelt or differently capitalized name, or text under numeric classes), the console and, while you develop, the map's author notes name the field, suggest the closest property name and list the data's properties.

A map or story with a classified layer gets a legend automatically, even without a `legend:` block (`legend: false` turns it off). It lists each class with its real edges, formatted with the shared `formatNumber` (MapLibre `number-format` option names, the page's language by default), and "No data"/"Other" lines that only appear when they occur, translatable as `maplibre-yaml.Classify.NoData`/`.Other` in `locale:`. A legend block with its own `items:` lists them first and the generated classes after them; validation and the author notes point out the combination, since hand-written items usually describe the colours a layer had before it was classified. The Astro `FullPageMap` no longer warns that such a map has no legend entries. `classify:` compiles to plain MapLibre (class `exports`) and records the classes in the layer's `metadata["maplibre-yaml:classify"]`, in v1 and v2 alike; `mlym emit` bakes computed breaks into the style, loading a `url:` source's data at export (a FlatGeobuf file too, recognized by its extension or the source's `format: flatgeobuf`) and failing clearly when it cannot. `<ml-map>` fires `ml-map:layer-classified` with the classes as drawn.
