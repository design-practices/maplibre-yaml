title: "React & other frameworks"
description: Use the <ml-map> element in React 18 and 19 (with TypeScript, Vite and Next.js), Vue and Svelte.
---

`<ml-map>` is a standard custom element, so React, Vue, Svelte and other
frameworks render it like any other tag. There is no wrapper component to
install: register the element once, import MapLibre's CSS, and point `src` at
a YAML file. Render the element in your components; the
[JavaScript API](/integrations/vanilla-js/) (`MapRenderer`) is not the
framework path.

## Quick start \{#setting-up}

This makes a new Vite + React app that shows a map from a YAML file. In an
app you already have, skip the first command.

**1. Create the app and install the packages:**

```bash
npm create vite@latest my-map -- --template react-ts
cd my-map
npm install
npm install @maplibre-yaml/core maplibre-gl
```

**2. Register the element and import MapLibre's CSS once.** Add these lines
at the top of `src/main.tsx`:

```tsx
// src/main.tsx
import { setWorkerUrl } from "maplibre-gl";
import workerUrl from "maplibre-gl/dist/maplibre-gl-worker.mjs?worker&url";
import "maplibre-gl/dist/maplibre-gl.css";
import "@maplibre-yaml/core/register";

// maplibre-gl 6 is ESM-only and cannot find its worker inside a bundle;
// point it there before the first map renders (v4/v5: drop these lines).
setWorkerUrl(workerUrl);
```

**3. Give TypeScript the element's typings.** Create `src/ml-map.d.ts` (any
`.d.ts` file under `src/` works) with this one line:

```ts
/// <reference types="@maplibre-yaml/core/react" />
```

Without it, `npm run build` stops with *Property 'ml-map' does not exist on
type 'JSX.IntrinsicElements'*.

**4. Save the map document as `public/map.yaml`.** Vite serves the files in
`public/` from the site root, so this one is at `/map.yaml`:

```yaml title="public/map.yaml"
type: map
id: earthquake-map
config:
  center: [-160, 20]
  zoom: 1
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"
layers:
  - id: earthquakes
    type: circle
    source:
      type: geojson
      url: "https://earthquake.usgs.gov/earthquakes/feed/v1.0/summary/all_week.geojson"
    paint:
      circle-radius: ["interpolate", ["linear"], ["get", "mag"], 1, 2, 7, 20]
      circle-color: "#e74c3c"
      circle-opacity: 0.7
    interactive:
      click:
        popup:
          - h3:
              - property: place
```

**5. Render it.** Save this component as `src/SrcMap.tsx`:

{/* snippet: examples/react/src/snippets/SrcMap.tsx */}
```tsx
import "@maplibre-yaml/core/register";

// public/map.yaml is served at /map.yaml.
export function SrcMap() {
  return <ml-map src="/map.yaml" style={{ display: "block", height: "400px" }} />;
}
```

and render it from `src/App.tsx`:

{/* snippet: examples/react/src/snippets/QuickStartApp.tsx */}
```tsx
// src/App.tsx: the whole file. It replaces the starter's demo page.
import { SrcMap } from "./SrcMap";

export default function App() {
  return <SrcMap />;
}
```

**6. Run `npm run dev`** and open the address it prints
(http://localhost:5173). The page shows the past week's earthquakes as red
circles, sized by magnitude, on a world map; click one to see where it
happened.

Files that `src` and the YAML's `url:`s point at go in the framework's static
folder: `public/` in Vite and Next.js, `static/` in SvelteKit. Under another
bundler, the worker lines differ:
[Installation](/getting-started/installation/#supported-maplibre-gl-versions).
To try map documents before you put them in your app, use the
[playground](/playground/).

## Common tasks

### React: events and the map instance

React 18 cannot attach listeners for custom events through props, so use a
ref. The same code works on React 19, and the listeners are typed from
`MLMapEventMap`. `mapReady()` resolves with the MapLibre map once the
document has loaded:

{/* snippet: examples/react/src/snippets/YamlMap.tsx */}
```tsx
import "@maplibre-yaml/core/register";
import type { MLMap, MLMapEventMap } from "@maplibre-yaml/core/register";
import { useEffect, useRef, useState } from "react";

export function YamlMap({ src }: { src: string }) {
  const ref = useRef<MLMap>(null);
  const [clicked, setClicked] = useState<string | null>(null);
  const [zoom, setZoom] = useState<number | null>(null);

  useEffect(() => {
    const el = ref.current!;
    const onClick = (event: MLMapEventMap["ml-map:layer-click"]) =>
      setClicked(String(event.detail.feature?.properties?.name));
    const onError = (event: MLMapEventMap["ml-map:error"]) =>
      console.error(event.detail.error ?? event.detail.errors);
    el.addEventListener("ml-map:layer-click", onClick);
    el.addEventListener("ml-map:error", onError);

    // mapReady() resolves with the MapLibre map once the document loaded.
    let cancelled = false;
    el.mapReady().then(
      (map) => {
        if (cancelled) return;
        setZoom(map.getZoom());
        map.on("zoomend", () => setZoom(map.getZoom()));
      },
      () => {} // a failed document also fires ml-map:error
    );

    return () => {
      cancelled = true;
      el.removeEventListener("ml-map:layer-click", onClick);
      el.removeEventListener("ml-map:error", onError);
    };
  }, []);

  return (
    <>
      <ml-map ref={ref} src={src} style={{ display: "block", height: "400px" }} />
      <p>
        Zoom {zoom?.toFixed(1) ?? "…"} · clicked: {clicked ?? "nothing yet"}
      </p>
    </>
  );
}
```

### React: a map from a config object

When your code builds the document, pass it as `config`. A JSON string works
on React 18 (which sets it as the attribute) and React 19 (which sets the
property):

{/* snippet: examples/react/src/snippets/ConfigMap.tsx */}
```tsx
import "@maplibre-yaml/core/register";
import type { MapBlock } from "@maplibre-yaml/core";

export function ConfigMap({ config }: { config: MapBlock }) {
  // A JSON string works on React 18 (set as the attribute) and React 19
  // (set as the property). An equal string never re-renders the map.
  return (
    <ml-map
      config={JSON.stringify(config)}
      style={{ display: "block", width: "100%", height: "400px" }}
    />
  );
}
```

A *changed* `config` builds a fresh map, which also resets the camera. An
equal one does nothing, so a component that rebuilds the same document on
every render doesn't rebuild the map. For very large inline GeoJSON, keep the
value stable (module-level or memoized): the comparison serializes it. An
invalid document shows the "Configuration Error" card, as a YAML file would.

### React 19: object config and event props

React 19 sets custom-element props as properties and attaches `on*` props as
listeners, using the rest of the name as the event type:
`onml-map:load={handler}` listens for `ml-map:load`. With the typings, each
handler gets its event's `detail` type. React 18 ignores these props, and the
typings reject an object `config` there:

{/* snippet: examples/react/src/react19/EventPropsMap.tsx */}
```tsx
import "@maplibre-yaml/core/register";
import type { MapBlock } from "@maplibre-yaml/core";

// React 19 only: `config` takes the object itself (React 19 sets it as a
// property), and `onml-map:*` props attach listeners, typed per event.
export function EventPropsMap({
  config,
  onLoad,
  onLayerClick,
}: {
  config: MapBlock;
  onLoad: () => void;
  onLayerClick: (layerId: string) => void;
}) {
  return (
    <ml-map
      config={config}
      onml-map:load={() => onLoad()}
      onml-map:layer-click={(event) => onLayerClick(event.detail.layerId)}
      onml-map:error={(event) =>
        console.error(event.detail.error ?? event.detail.errors)
      }
      style={{ display: "block", height: "400px" }}
    />
  );
}
```

The colon makes these namespaced JSX attributes. Vite and TypeScript compile
them; if your JSX compiler rejects namespaced attributes, spread them in:
`{...{ "onml-map:load": handler }}`.

### React: slot children

React can render your own controls into the map's corners
([slots](/integrations/web-components/#slots-your-own-chrome-over-the-map)).
The element moves slot children into the map, so render them
unconditionally: React may update what is inside them, but must not add or
remove the slotted elements themselves. Toggle one with `hidden` or CSS
instead.

{/* snippet: examples/react/src/snippets/SlotControls.tsx */}
```tsx
import "@maplibre-yaml/core/register";
import type { MLMap } from "@maplibre-yaml/core/register";
import { useRef } from "react";

export function MapWithControls({ src }: { src: string }) {
  const ref = useRef<MLMap>(null);
  const zoomBy = (delta: number) => {
    const map = ref.current?.getMap();
    map?.easeTo({ zoom: map.getZoom() + delta, duration: 300 });
  };

  // Children with slot="top-left" (and the other corners, or "legend") are
  // placed in the map's corner, stacked with the built-in chrome. Render
  // slot children unconditionally: the element moves them into the map, so
  // React may update their contents but must not add or remove them.
  return (
    <ml-map ref={ref} src={src} style={{ display: "block", height: "400px" }}>
      <div slot="top-left" className="map-buttons">
        <button type="button" aria-label="Zoom in" onClick={() => zoomBy(1)}>
          +
        </button>
        <button type="button" aria-label="Zoom out" onClick={() => zoomBy(-1)}>
          −
        </button>
      </div>
    </ml-map>
  );
}
```

### React: mounting and unmounting

Unmounting removes the element, and the element then destroys its MapLibre
map: no leaked canvas, and a remount creates exactly one new map.
StrictMode's double-run effects do not re-create the element, so keep
listener setup in an effect that has a cleanup, as shown above. A `config`
assigned from an effect (after the element has connected) is waited for, so
it renders without a passing "No configuration provided" error.

### Story maps \{#story-maps}

`<ml-scrollytelling>` works the same way: the same register import defines
it, `src` points at a story file in `public/`, and its events are
`ml-scrollytelling:chapter`, `ml-scrollytelling:action` and
`ml-scrollytelling:error` (listen with a ref, as above). The typings cover
`<ml-map>` only, so in TypeScript a `<ml-scrollytelling>` tag needs your own
declaration. Writing the story file:
[Writing a story file](/schema/scrollytelling/).

## What differs between frameworks

`src` works the same everywhere. Three things differ: how a `config` object
reaches the element, how you listen for `ml-map:*` events, and TypeScript.

| | `config` object | `ml-map:*` events | TypeScript |
|---|---|---|---|
| React 19 | Set as a **property**: the object (keep it stable) or a JSON string | `onml-map:load={…}` props, or a ref + `addEventListener` | [`@maplibre-yaml/core/react`](#typescript-with-react): typed `config` and event props |
| React 18 | Set as an **attribute**: a JSON string only (an object becomes `"[object Object]"`) | A ref + `addEventListener` | `@maplibre-yaml/core/react`: an object `config` is a type error |
| Vue 3 | Set as a property: pass the object | `@ml-map:load="…"` | Works (add `isCustomElement`, [below](#vue)) |
| Svelte 5 | Set as a property: pass the object | `bind:this` + `addEventListener` | Works out of the box |

A JSON string plus a ref-based listener works on both React majors.

### TypeScript with React

React's JSX types do not know `<ml-map>`, so without the typings `tsc`
reports *Property 'ml-map' does not exist on type 'JSX.IntrinsicElements'*.
The reference line in the [quick start](#setting-up) adds them
(`import "@maplibre-yaml/core/react";` in any module works too; it is empty
at runtime). They adapt to `@types/react` 18 or 19, type `useRef<MLMap>(null)`
so `mapReady()` and `getMap()` are typed, and accept slot children and an
inline `<script type="text/yaml">`. `MLMap` and `MLMapEventMap` come from
`@maplibre-yaml/core/register`.

## Next.js

Client components still render on the server (App Router included). From
`@maplibre-yaml/core` 0.9.1, the register module is safe to import there: on
the server it only loads, and it defines the element when the client bundle
runs in the browser. Import it at the top of a `"use client"` file:

```jsx
"use client";
import "@maplibre-yaml/core/register";

export default function YamlMap({ src }) {
  return <ml-map src={src} style={{ display: "block", height: "400px" }} />;
}
```

The server sends a plain `<ml-map>` tag, which upgrades in the browser. Put
`map.yaml` in `public/`, and import the MapLibre CSS in `app/layout`. On
maplibre-gl 6, call `setWorkerUrl()` with your bundler's URL for the worker in
the same file as the register import
([Installation](/getting-started/installation/#supported-maplibre-gl-versions)).

On 0.9.0 and earlier, that import fails the build with
`ReferenceError: HTMLElement is not defined`. There, register the element
from an effect instead:

```jsx
"use client";
import { useEffect } from "react";

export default function YamlMap({ src }) {
  useEffect(() => {
    import("@maplibre-yaml/core/register");
  }, []);

  return <ml-map src={src} style={{ display: "block", height: "400px" }} />;
}
```

## Vue

Point `src` at a file in `public/`, and reach the map through a template ref:

```vue
<template>
  <ml-map
    ref="mapEl"
    src="/map.yaml"
    style="width: 100%; height: 400px; display: block;"
    @ml-map:error="(e) => console.error(e.detail.error ?? e.detail.errors)"
  />
</template>

<script setup>
import "@maplibre-yaml/core/register";
import { onMounted, ref } from "vue";

const mapEl = ref(null);

onMounted(async () => {
  const map = await mapEl.value.mapReady();
  map.flyTo({ zoom: 3 });
});
</script>
```

For a document built in code, bind the object: `:config="doc"` (Vue sets it
as a property). Tell Vue's compiler that `ml-*` tags are custom elements.
Without this, every render logs *Failed to resolve component: ml-map* in
development:

```js
// vite.config.js
import { defineConfig } from "vite";
import vue from "@vitejs/plugin-vue";

export default defineConfig({
  plugins: [
    vue({
      template: {
        compilerOptions: { isCustomElement: (tag) => tag.startsWith("ml-") },
      },
    }),
  ],
});
```

Vue templates reject `<script>` tags, so an inline `<script type="text/yaml">`
doesn't work there; use `src` or `config`. `vue-tsc` accepts `<ml-map>` by
default; under `strictTemplates` it reports the element as unknown.

## Svelte

Point `src` at a file in `static/` (SvelteKit) or `public/` (Vite), and
reach the map through `bind:this`:

```svelte
<script>
  import "@maplibre-yaml/core/register";
  import { onMount } from "svelte";

  let mapEl;

  onMount(() => {
    const onError = (e) => console.error(e.detail.error ?? e.detail.errors);
    mapEl.addEventListener("ml-map:error", onError);
    mapEl.mapReady().then((map) => map.flyTo({ zoom: 3 }), () => {});
    return () => mapEl.removeEventListener("ml-map:error", onError);
  });
</script>

<ml-map bind:this={mapEl} src="/map.yaml" style="width: 100%; height: 400px; display: block;"></ml-map>
```

For a document built in code, pass the object: `{config}` (Svelte 5 sets it
as a property). Close the tag explicitly: Svelte 5 warns about self-closing
non-void elements such as `<ml-map />`. `onml-map:load={…}` attaches a
listener, but Svelte warns that attribute names should not contain `:`, so
use `bind:this` as shown. `svelte-check` accepts `<ml-map>` and its
attributes out of the box. With `lang="ts"`, type the binding as
`let mapEl: MLMap` (imported from `@maplibre-yaml/core/register`).

SvelteKit renders components on the server too. From `@maplibre-yaml/core`
0.9.1 the register import above works there as it is. On 0.9.0 and earlier
it fails with `HTMLElement is not defined`; move it into `onMount`:
`onMount(() => { import("@maplibre-yaml/core/register"); })`.

## Troubleshooting

Problems every map shares are in [Troubleshooting](/troubleshooting/).

- **`ReferenceError: HTMLElement is not defined`** during a server render or
  build: `@maplibre-yaml/core` 0.9.0 or earlier, imported on the server.
  Upgrade, or register the element from an effect ([Next.js](#nextjs)).
- **The map is blank and the element's `config` attribute reads
  `[object Object]`**: React 18 sets `config` as an attribute. Pass
  `JSON.stringify(doc)`.
- **The map reports *Worker failed to load***: maplibre-gl 6 needs the
  `setWorkerUrl()` lines in your entry file ([quick start](#setting-up)).
- **The map shows *YAML syntax error … `<!doctype html>`***: the YAML file
  isn't in the static folder, so the server answered with your app's HTML
  page. Move it to `public/` (or `static/` in SvelteKit).
- **Vue logs *Failed to resolve component: ml-map***: add the
  `isCustomElement` option ([Vue](#vue)).
- **TypeScript: *Property 'ml-map' does not exist on type
  'JSX.IntrinsicElements'***: add the typings reference
  ([TypeScript with React](#typescript-with-react)).
