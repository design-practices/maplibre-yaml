import { Steps } from "@astrojs/starlight/components";

The `<ml-map>` element draws a map document on an HTML page. It is a web
component (a custom HTML element), so it works in any page: load it from a
CDN, point its `src` at a YAML file, and give it a height. There is no
JavaScript to write.

This page is for plain HTML pages. On an Astro site, use the
[Astro components](/integrations/astro/); in React, Vue or Svelte, see
[React & other frameworks](/integrations/react/).

## Quick start

<Steps>

1. **Create `index.html`**

   ```html
   <!DOCTYPE html>
   <html lang="en">
     <head>
       <meta charset="utf-8" />
       <meta name="viewport" content="width=device-width, initial-scale=1" />
       <title>My map</title>
       <link
         rel="stylesheet"
         href="https://unpkg.com/maplibre-gl@6/dist/maplibre-gl.css"
       />
       <!-- Tell the browser where to find maplibre-gl -->
       <script type="importmap">
         { "imports": { "maplibre-gl": "https://unpkg.com/maplibre-gl@6/dist/maplibre-gl.mjs" } }
       </script>
       <!-- Registers <ml-map> -->
       <script
         type="module"
         src="https://unpkg.com/@maplibre-yaml/core@0.9/register.js"
       ></script>
     </head>
     <body>
       <ml-map src="map.yaml" style="display: block; height: 400px;"></ml-map>
     </body>
   </html>
   ```

2. **Create `map.yaml` next to it**

   ```yaml
   type: map
   id: quakes
   config:
     mapStyle: "https://tiles.openfreemap.org/styles/liberty"
     center: [-120, 37]
     zoom: 4
   layers:
     - id: quakes
       type: circle
       source:
         type: geojson
         url: "https://earthquake.usgs.gov/earthquakes/feed/v1.0/summary/all_week.geojson"
       paint:
         circle-radius: 5
         circle-color: "#dc2626"
   ```

3. **Serve the folder and open it**

   ```bash
   npx serve .
   ```

   Open the address it prints (for example http://localhost:3000). The map
   shows California with the past week's earthquakes as red dots.

</Steps>

Open the page from a web server, not by double-clicking it: a page opened as
`file://` can't fetch `map.yaml`, and the map shows "Open this page through a
local web server" instead. The [Quick start](/getting-started/quick-start/)
walks through the same page step by step, and
[Your first map, explained](/getting-started/first-map/) explains each line
of the YAML.

## Common tasks

### Load a map from a YAML file \{#method-1-external-yaml-file-recommended}

`src` is the address of the map document, relative to the page. Keeping the
YAML in its own file keeps the page short, and lets you check the file with
`npx maplibre-yaml@latest validate map.yaml` before you publish.

```html
<ml-map src="maps/city.yaml" style="display: block; height: 400px;"></ml-map>
```

Paths *inside* the YAML (`url: "data/points.geojson"`) resolve against the
page, not the YAML file
([Loading data › How paths are read](/guides/data-sources/#relative-paths)).
Changing `src` loads the new document, and `reload()` loads the same one
again.

Give every `<ml-map>` `display: block` and a height. A custom element is
inline and zero-height by default, so without them the map is invisible, and
the element shows a note asking for a height in its place.

### Sites under a subpath (GitHub Pages)

On a GitHub Pages project site (`https://<user>.github.io/<repo>/`), add
`base="/<repo>/"` and leave the YAML as it is. `src` and every path to a file
of your own then load under the subpath. Which paths it covers and how to
preview it locally:
[Publishing & subpaths](/guides/publishing/#html-pages-the-base-attribute).

```html
<ml-map src="maps/city.yaml" base="/<repo>/" style="display: block; height: 400px;"></ml-map>
```

### Put your own controls over the map \{#slots-your-own-chrome-over-the-map}

Children with a `slot` attribute go in a corner of the map: `top-left`,
`top-right`, `bottom-left` or `bottom-right`, stacked with the built-in
legend and params panel. A `slot="legend"` child replaces the built-in
legend. Buttons, captions and credits sit over the map without any
positioning CSS:

```html
<ml-map src="map.yaml" style="display: block; height: 400px;">
  <div slot="top-right" class="my-controls">
    <button data-action="zoom-in">+</button>
    <button data-action="reset">Reset</button>
  </div>
  <p slot="bottom-left">Data: USGS</p>
</ml-map>

<script type="module">
  const el = document.querySelector("ml-map");
  const home = await el.mapReady().then((map) => ({
    center: map.getCenter(),
    zoom: map.getZoom(),
  }));
  document.querySelector(".my-controls").addEventListener("click", (e) => {
    const map = el.getMap(); // read at click time: reload() makes a new map
    const action = e.target.closest("[data-action]")?.dataset.action;
    if (action === "zoom-in") map.zoomIn();
    if (action === "reset") map.jumpTo(home);
  });
</script>
```

Slot children are shown once the map loads, and stay through `reload()` and
a new document. How they stack and behave is under
[`<ml-map>` slots](/reference/elements/#ml-map-slots).

### Reach the MapLibre map \{#accessing-the-maplibre-instance}

`mapReady()` resolves with the MapLibre map once the document has loaded (at
once if it already has), and rejects if the document fails. From there,
anything MapLibre can do works:

```html
<script type="module">
  const el = document.querySelector("ml-map");
  const map = await el.mapReady();

  map.flyTo({ center: [-122.42, 37.77], zoom: 9 });
  map.on("moveend", () => console.log("now at", map.getCenter()));
</script>
```

Layers you add with MapLibre's own `map.addLayer()` are yours to manage; keep
their ids different from the document's. `getMap()` returns the map without
waiting (`null` before it loads), and `getRenderer()` returns the
[`MapRenderer`](/integrations/vanilla-js/) behind the element.

### React to map events \{#event-reference}

The element dispatches bubbling `ml-map:*` events: when the map loads, when a
layer's data arrives or refreshes, when a feature is clicked or hovered, and
more. Each carries its data on `event.detail`:

```html
<script type="module">
  const el = document.querySelector("ml-map");
  el.addEventListener("ml-map:layer-click", (event) => {
    const { layerId, feature } = event.detail;
    console.log(layerId, feature.properties.title);
  });
</script>
```

All eighteen events, with each `detail`, are under
[`<ml-map>` events](/reference/elements/#ml-map-events).

### When something goes wrong

`<ml-map>` shows problems on the page, not only in the console: an **error
card** in place of a map that can't render, a **notice** over a map when part
of it didn't load, and **author hints** in that notice while you develop
(`localhost`), or anywhere with the `debug` attribute. `quiet` hides the
notice on a finished site; the error card always shows. What each one means,
and the common fixes, are in
[Troubleshooting](/troubleshooting/#reading-what-the-map-tells-you). A page
script can read the same problems from `ml-map:error`:

```js
el.addEventListener("ml-map:error", (event) => {
  // A document that can't load or validate: errors, each { path, message }.
  // A failure while the map runs: error, with fatal true or false.
  console.error(event.detail.errors ?? event.detail.error);
});
```

### Multiple maps on one page

Each `<ml-map>` is independent and loads its own document. The page needs the
import map and `register.js` only once:

```html
<div style="display: grid; grid-template-columns: 1fr 1fr; gap: 20px;">
  <ml-map src="map-1.yaml" style="display: block; height: 400px;"></ml-map>
  <ml-map src="map-2.yaml" style="display: block; height: 400px;"></ml-map>
</div>
```

### Story maps: `<ml-scrollytelling>`

The same `register.js` also defines `<ml-scrollytelling>`, which shows a
`type: scrollytelling` story file: a sticky map with chapters scrolling over
it. See [Story maps in plain HTML](/integrations/scrollytelling-html/).

## Troubleshooting

Most problems look the same whichever way the map is on the page; they are in
[Troubleshooting](/troubleshooting/):
[the map has no height](/troubleshooting/#the-map-has-no-height),
[`<ml-map>` isn't defined](/troubleshooting/#ml-map-isnt-defined),
[an error card instead of the map](/troubleshooting/#an-error-card-instead-of-the-map),
and [the basemap draws but your layer doesn't](/troubleshooting/#the-basemap-draws-but-your-layer-doesnt).

### Events not firing

An `ml-map:load` listener added after the map has loaded never runs: the
event has already happened. Use `await el.mapReady()` instead, which resolves
whether the map loaded before or after you ask. If the map never loads, an
`ml-map:error` listener tells you why.

## Alternatives

`src` with a YAML file, above, is the recommended way. Use these when it
doesn't fit.

### Inline YAML (script tag) \{#method-2-inline-yaml-script-tag}

For a page that must be one file, put the YAML in a `<script type="text/yaml">`
inside the element. Start the YAML on the line after the opening tag, and
keep every line at the same depth relative to the first (indenting the whole
block to match your HTML is fine):

```html
<ml-map style="display: block; height: 400px;">
  <script type="text/yaml">
type: map
id: inline-map
config:
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"
  center: [-74.006, 40.7128]
  zoom: 12
  </script>
</ml-map>
```

`<script type="application/yaml">` works the same way, and
`<script type="application/json">` takes the document written as JSON:

```html
<ml-map style="display: block; height: 400px;">
  <script type="application/json">
    { "type": "map", "id": "inline-json",
      "config": { "mapStyle": "https://tiles.openfreemap.org/styles/liberty",
                  "center": [-74.006, 40.7128], "zoom": 12 } }
  </script>
</ml-map>
```

### A document built in JavaScript (`config`) \{#method-3-json-attribute-programmatic}

When your code builds the document (from a form, or an API response), set
the `config` property to the object, or the `config` attribute to a JSON
string:

```html
<ml-map id="dynamic-map" style="display: block; height: 400px;"></ml-map>

<script type="module">
  const doc = {
    type: "map",
    id: "dynamic",
    config: {
      mapStyle: "https://tiles.openfreemap.org/styles/liberty",
      center: [-74.006, 40.7128],
      zoom: 12,
    },
  };
  document.getElementById("dynamic-map").config = doc;
  // or: el.setAttribute("config", JSON.stringify(doc));
</script>
```

The document is validated like a YAML file; an invalid one shows the error
card. A *changed* `config` builds a fresh map (and resets the camera); one
equal to the document already shown does nothing. A `config` assigned right
after the element upgrades renders without a passing "No configuration
provided" error.

### With npm and a bundler \{#npm-with-build-tools}

Install `@maplibre-yaml/core` and `maplibre-gl`, import
`@maplibre-yaml/core/register` and MapLibre's CSS once in your entry file, and
point maplibre-gl 6 at its worker:
[Installation: using a bundler](/getting-started/installation/#using-a-bundler-vite).
Put the YAML and data files in the bundler's `public/` folder. The element
then works in your HTML as above.

### In a framework \{#framework-compatibility}

React, Vue, Svelte and other frameworks render `<ml-map>` like any other tag.
How each passes `config`, listens for events and types the element is on
[React & other frameworks](/integrations/react/).

### Format v2 documents

A [format v2](/guides/format-v2/) document (`version: 2`, with `style:` and
`runtime:`) works in every way shown on this page and draws the same map as
its format v1 twin.

### Your own JavaScript instead of the element

To parse and render a document from your own code, into a `<div>` you
control, see the [JavaScript API](/integrations/vanilla-js/).
