The `<ml-map>` web component is the simplest way to add maps to any HTML page. No JavaScript required for basic usage - just HTML and a YAML configuration file.

## Quick Start

Get a map on your page in 3 steps.

<Steps>

1. **Add the scripts and styles**

   ```html
   <head>
     <!-- MapLibre GL CSS -->
     <link
       href="https://unpkg.com/maplibre-gl@5/dist/maplibre-gl.css"
       rel="stylesheet"
     />

     <!-- Tell the browser where to find maplibre-gl -->
     <script type="importmap">
       { "imports": { "maplibre-gl": "https://esm.sh/maplibre-gl@^5" } }
     </script>
     <!-- Register the web component -->
     <script
       type="module"
       src="https://unpkg.com/@maplibre-yaml/core/register.js"
     ></script>
   </head>
   ```

2. **Create a YAML configuration file**

   Create `map.yaml` in your project:

   ```yaml
   type: map
   id: quick-map
   config:
     center: [-74.006, 40.7128]
     zoom: 12
     mapStyle: "https://demotiles.maplibre.org/style.json"
   layers:
     - id: marker
       type: circle
       source:
         type: geojson
         data:
           type: FeatureCollection
           features:
             - type: Feature
               geometry:
                 type: Point
                 coordinates: [-74.006, 40.7128]
               properties:
                 name: "New York"
       paint:
         circle-radius: 10
         circle-color: "#3b82f6"
   ```

3. **Add the map component**

   ```html
   <ml-map src="map.yaml" style="width: 100%; height: 400px; display: block;">
   </ml-map>
   ```

4. **View in browser**

   Serve your files with any web server (e.g., `npx serve .`) and open in browser!

</Steps>

<Aside type="tip">
  The `display: block` style is important - custom elements are inline by
  default, which can cause sizing issues.
</Aside>

## Installation Options

### CDN (Recommended for Quick Start)

The import map is required: it tells the browser where to find `maplibre-gl`, which the register bundle keeps external.

```html
<script type="importmap">
  { "imports": { "maplibre-gl": "https://esm.sh/maplibre-gl@^5" } }
</script>
<script
  type="module"
  src="https://unpkg.com/@maplibre-yaml/core/register.js"
></script>
```

<Aside type="note" title="maplibre-gl version">
  maplibre-yaml works with maplibre-gl **v4 and v5** (v5 recommended for new
  projects); the peer range is `^3.0.0 || ^4.0.0 || ^5.0.0`. maplibre-gl v6 is
  not supported yet, and it is what unpinned installs and CDN URLs now resolve
  to — so pin the major your project uses in the import map, the CSS URL, and
  `npm install`, and keep all three on the same major.
</Aside>

### npm (With Build Tools)


## Configuration Methods

There are three ways to configure `<ml-map>`, each suited for different use cases.

<Aside type="note">
  `<ml-map>` expects a **single map block document** — a YAML file whose top
  level is `type: map`. It does not accept a root document (one with a
  `pages:` key); those are multi-page site configurations meant for the Astro
  integration and will fail validation if passed to `<ml-map>`.
</Aside>

<Aside type="note" title="Format v2 renders identically">
  A **Format v2** document (one with `version: 2` and the `style:` / `runtime:`
  split) renders through `<ml-map>` exactly like its v1 twin — the two forms
  collapse to the same internal model, so nothing on this page changes when you
  adopt v2. See [Format v2](/guides/format-v2/) for the style/runtime split.
</Aside>

<Aside type="caution" title="`emit` is inert under `<ml-map>` today">
  The `click.emit` interaction — which hands feature data to a host-supplied
  handler — does **not** fire from a plain `<ml-map>` mount. The component
  defaults to an untrusted capability policy and registers no host handlers, so
  every `emit` fails closed (a silent no-op), even in a document you authored
  yourself. This is intentional fail-closed behavior, not a bug: `emit` targets
  the `attachInteractions` path, and wiring it into the renderer is tracked
  follow-up work (bead `ml-1lz`). The map-acting interactions (`popup`,
  `flyTo`, `zoomToFeature`, `hover.highlight`) work under `<ml-map>` as usual.
  See [Interactions & Eject](/guides/interactions/) for the full `emit` story.
</Aside>

### Method 1: External YAML File (Recommended)

The simplest and cleanest approach - keep your configuration in a separate YAML file:

```html
<ml-map src="/maps/my-map.yaml" style="height: 400px; display: block;"></ml-map>
```

**my-map.yaml:**

```yaml
type: map
id: my-map
config:
  center: [-74.006, 40.7128]
  zoom: 12
  mapStyle: "https://demotiles.maplibre.org/style.json"
layers:
  - id: points
    type: circle
    source:
      type: geojson
      url: "https://example.com/data.geojson"
    paint:
      circle-radius: 8
      circle-color: "#3b82f6"
```

**Why this is best:**

- ✅ Clean separation of configuration and markup
- ✅ No JavaScript required
- ✅ YAML indentation is never an issue
- ✅ Easy to edit without touching HTML
- ✅ Files can be validated independently
- ✅ Works in all frameworks

### Method 2: Inline YAML (Script Tag)

For self-contained examples or documentation:

```html
<ml-map style="height: 400px; display: block;">
  <script type="text/yaml">
type: map
id: inline-map
config:
  center: [-74.006, 40.7128]
  zoom: 12
  mapStyle: "https://demotiles.maplibre.org/style.json"
layers:
  - id: marker
    type: circle
    source:
      type: geojson
      data:
        type: FeatureCollection
        features:
          - type: Feature
            geometry:
              type: Point
              coordinates: [-74.006, 40.7128]
            properties:
              name: "New York"
    paint:
      circle-radius: 10
      circle-color: "#3b82f6"
  </script>
</ml-map>
```

**Why this works:**

- Browser doesn't process `<script type="text/yaml">` content
- Whitespace and indentation are preserved exactly
- Works in plain HTML, Astro, MDX and Svelte templates; in React, pass the
  YAML as a string child (`<script type="text/yaml">{yaml}</script>`)
- **Not in Vue templates:** Vue's compiler rejects `<script>` tags in a
  template — use `src` or `config` there (see
  [Framework Compatibility](#framework-compatibility))
- Good for examples that need to be self-contained

### Method 3: JSON Attribute (Programmatic)

For dynamic or generated configurations:

```html
<ml-map
  id="dynamic-map"
  style="height: 400px; display: block;"
></ml-map>

<script type="importmap">
  { "imports": { "maplibre-gl": "https://esm.sh/maplibre-gl@^5" } }
</script>
<script type="module">
  import "https://unpkg.com/@maplibre-yaml/core/register.js";

  const config = {
    type: "map",
    id: "programmatic",
    config: {
      center: [-74.006, 40.7128],
      zoom: 12,
      mapStyle: "https://demotiles.maplibre.org/style.json",
    },
    layers: [],
  };

  // Set as property (object)
  document.getElementById("dynamic-map").config = config;

  // Or as attribute (JSON string)
  // document.getElementById("dynamic-map").setAttribute("config", JSON.stringify(config));
</script>
```

**When to use this:**

- Generating config from user input
- Loading config from an API
- Building configs programmatically
- Framework-based dynamic rendering

<Aside type="note" title="When the config arrives after the element">
  The element upgrades as soon as `register.js` loads, before the line that
  assigns `config`. Since 0.7 an element with no configuration waits until
  the end of the next frame before it reports "No configuration provided.",
  so a `config` assigned right after the import (or from a framework effect)
  renders without a transient error, and a `mapReady()` called in between
  waits for it. A `config` assigned *before* `register.js` loads is picked up
  when the element upgrades. On 0.6, the error card flashed in both cases.
</Aside>

## Component Lifecycle

### Initialization Flow

```
1. Element added to DOM
2. connectedCallback() fires
3. Config attribute/property read
4. Config validated against schema
5. MapLibre GL map created
6. Layers added
7. 'ml-map:load' event dispatched
```

### Lifecycle Events

```javascript
const mapEl = document.querySelector("ml-map");

// Map loaded and ready
mapEl.addEventListener("ml-map:load", (event) => {
  console.log("Map ready!");
});

// Error during initialization or runtime. Configuration/validation failures
// carry `errors` (an array of { path, message }); runtime failures carry `error`.
mapEl.addEventListener("ml-map:error", (event) => {
  console.error("Map error:", event.detail.error ?? event.detail.errors);
});

// Layer data loaded
mapEl.addEventListener("ml-map:layer-data-loaded", (event) => {
  const { layerId, featureCount } = event.detail;
  console.log(`${layerId}: ${featureCount} features`);
});

// Layer data loading
mapEl.addEventListener("ml-map:layer-data-loading", (event) => {
  console.log(`Loading ${event.detail.layerId}...`);
});

// Layer data error
mapEl.addEventListener("ml-map:layer-data-error", (event) => {
  console.error(`${event.detail.layerId} error:`, event.detail.error);
});
```

### Event reference

Every event `<ml-map>` dispatches (all bubble; payload on `event.detail`):

| Event | Detail | Fires when |
|-------|--------|------------|
| `ml-map:loading` | `{ url }` | A `src` document fetch begins |
| `ml-map:load` | `{}` | The document is fully loaded — basemap and every layer |
| `ml-map:error` | `{ error, fatal }` or `{ errors }` | Initialization or runtime failure (`fatal: true` aborts the document); a document that fails to parse or validate carries `errors` — the structured `{ path, message }[]` the error card shows — instead |
| `ml-map:layer-added` | `{ layerId }` | A layer was added to the map |
| `ml-map:layer-removed` | `{ layerId }` | A layer was removed |
| `ml-map:layer-data-loading` | `{ layerId }` | A layer's data fetch begins |
| `ml-map:layer-data-loaded` | `{ layerId, featureCount }` | A layer's data landed |
| `ml-map:layer-data-error` | `{ layerId, error }` | A layer's data fetch failed |
| `ml-map:layer-click` | `{ layerId, feature, lngLat }` | A feature on an interactive layer was clicked |
| `ml-map:layer-hover` | `{ layerId, feature, lngLat }` | A feature on an interactive layer was hovered |
| `ml-map:markers-added` | `{ count }` | The `markers:` pins were added |
| `ml-map:marker-click` | `{ index, at }` | A standalone marker was clicked |
| `ml-map:marker-icon-error` | `{ index, icon }` | A marker `icon:` failed (unsafe scheme or load error); the default pin was substituted |
| `ml-map:image-error` | `{ name, url }` | An `images:` entry failed (unsafe scheme, CORS, load or register error) |
| `ml-map:parameter-change` | `{ key, value }` | A params-panel control wrote a state key |
| `ml-map:layer-visibility` | `{ layerId, visible }` | A params-panel checkbox toggled a layer |

## Slots: your own chrome over the map

Author markup placed inside `<ml-map>` with a `slot` attribute rides the
element's corner system — the same one the legend and the params panel use —
so page chrome (buttons, captions, a custom legend) sits over the map without
hand-rolled absolute positioning:

```html
<ml-map src="/configs/map.yaml">
  <div slot="top-right" class="my-controls">
    <button data-action="zoom-in">+</button>
    <button data-action="reset">⟲</button>
  </div>
  <div slot="bottom-left">Data: city open data portal</div>
</ml-map>

<script type="module">
  const el = document.querySelector("ml-map");
  const home = await el.mapReady().then((map) => ({
    center: map.getCenter(),
    zoom: map.getZoom(),
  }));
  document.querySelector(".my-controls").addEventListener("click", (e) => {
    const map = el.getMap(); // read at click time — reload() makes a new map
    const action = e.target.closest("[data-action]")?.dataset.action;
    if (action === "zoom-in") map.zoomIn();
    if (action === "reset") map.jumpTo(home);
  });
</script>
```

| Slot | Placement |
|------|-----------|
| `top-left`, `top-right`, `bottom-left`, `bottom-right` | Mounted into that corner of the map |
| `legend` | **Replaces** the built-in legend, at the document's `legend.position` (default `top-left`) |

How it behaves:

- **Stacking, not overlap.** Pieces sharing a corner stack in registration
  order: the built-in legend first, then the params panel, then slot
  children in document order. Bottom corners grow upward. A corner also
  steps past a MapLibre control (e.g. `navigation`) already in it.
- **Mounted on load.** Slot children are hidden until the map's `load`, then
  moved into their corner. They stay the same elements, so event listeners
  you attached keep working.
- **They survive the map.** `reload()`, a new `config`/`src`, and an error
  card all tear the map down but park slot children back on the element;
  the next successful render mounts them again. Slot children added after
  load are picked up on the next render (`reload()`).
- **Pointer events.** Empty corner areas pass gestures through to the map;
  your slot content receives clicks normally.
- An unknown slot name logs a warning and the child is left where it is.

Only children with a recognized `slot` are moved. Other children you place
inside `<ml-map>` (including the inline `<script type="text/yaml">`) are left
alone: the element removes only what it created itself — its map container
and its error card.

<Aside type="note">
Slots are page markup, not part of the map document: they never appear in
`mlym emit` output, and there is nothing to eject. See the
[eject classes guide](/guides/eject-classes/).
</Aside>

<Aside type="caution" title="Astro: spread the slot attribute inside expressions">
Inside a `{condition && (...)}` expression, Astro's compiler reads a literal
`slot="top-right"` as its own named-slot directive and strips it (wrapped in
a `Fragment`, the child disappears entirely). Write
`{...{ slot: "top-right" }}` there instead; a literal `slot` outside an
expression is passed through unchanged.
</Aside>

## Accessing the MapLibre Instance

For advanced customization, access the underlying MapLibre GL map. Since 0.7,
`mapReady()` is the idiomatic way in — it resolves with the live map once the
document has loaded (immediately if it already has) and rejects if the
document fails, so there is no load-listener or null-guard boilerplate:

```javascript
import maplibregl from "maplibre-gl"; // resolved by the import map (or your bundler)

const mapEl = document.querySelector("ml-map");
const map = await mapEl.mapReady();

// Now you can use any MapLibre GL API
map.flyTo({
  center: [-122.4194, 37.7749],
  zoom: 14,
  duration: 2000,
});

// Add custom controls
map.addControl(new maplibregl.NavigationControl());

// Add custom sources and layers
map.addSource("custom-source", {
  type: "geojson",
  data: { type: "FeatureCollection", features: [] },
});
map.addLayer({
  id: "custom-layer",
  type: "fill",
  source: "custom-source",
  paint: { "fill-color": "#ff0000" },
});
```

The event-based form (`ml-map:load` listener + `getMap()`) still works and
suits code that must re-run on every reload.

<Aside type="caution">
  `getMap()` returns `null` until the `ml-map:load` event fires — guard it,
  or use `await mapEl.mapReady()` which handles the timing for you.
</Aside>

## Controlling Live Data

Polling runs on the `refreshInterval` declared in YAML, and every refresh
fires `ml-map:layer-data-loading` / `ml-map:layer-data-loaded`, so you can
follow it from the element:

```javascript
const mapEl = document.querySelector("ml-map");

mapEl.addEventListener("ml-map:layer-data-loaded", (event) => {
  const { layerId, featureCount } = event.detail;
  console.log(`${layerId} refreshed: ${featureCount} features`);
});
```

<Aside type="caution" title="No programmatic refresh control yet">
  Earlier versions of this page showed `mapEl.pauseRefresh()`,
  `resumeRefresh()` and `refreshNow()`. Those methods are **not** exposed on
  `<ml-map>` (or `MapRenderer`) today — calling them throws. Exposing
  pause/resume/refresh is tracked as bead `ml-few`.
</Aside>

This example demonstrates a complete implementation using the `src` attribute with event handlers for status updates.

**index.html:**

```html

<html>

      rel="stylesheet"
    />
    <script type="importmap">
      { "imports": { "maplibre-gl": "https://esm.sh/maplibre-gl@^5" } }
    </script>
    <script
      type="module"
      src="https://unpkg.com/@maplibre-yaml/core/register.js"
    ></script>
    <style>
      * {
        margin: 0;
        padding: 0;
        box-sizing: border-box;
      }
      body {
        font-family: system-ui, sans-serif;
      }

      .container {
        display: flex;
        flex-direction: column;
        height: 100vh;
      }

      header {
        padding: 15px 20px;
        background: #1f2937;
        color: white;
        display: flex;
        justify-content: space-between;
        align-items: center;
      }

      h1 {
        font-size: 1.25rem;
        font-weight: 600;
      }

      .status {
        font-size: 0.875rem;
        color: #9ca3af;
      }

      .status.loading {
        color: #fbbf24;
      }
      .status.error {
        color: #ef4444;
      }
      .status.ready {
        color: #22c55e;
      }

      ml-map {
        flex: 1;
        display: block;
      }
    </style>
  </head>
  <body>
    <div class="container">
      <header>
        <h1>🌍 Earthquake Monitor</h1>
        <div class="status" id="status">Initializing...</div>
      </header>

      <ml-map id="earthquake-map" src="earthquake-config.yaml"></ml-map>
    </div>

    <script type="module">
      const statusEl = document.getElementById("status");
      const mapEl = document.getElementById("earthquake-map");

      // Event handlers
      mapEl.addEventListener("ml-map:loading", (event) => {
        statusEl.textContent = "Loading configuration...";
        statusEl.className = "status loading";
      });

      // Fires on the first load and again on every refresh. The first one
      // arrives before ml-map:load, which only fires once every layer is in.
      mapEl.addEventListener("ml-map:layer-data-loading", () => {
        statusEl.textContent = "Loading earthquake data...";
        statusEl.className = "status loading";
      });

      mapEl.addEventListener("ml-map:layer-data-loaded", (event) => {
        const { featureCount } = event.detail;
        const time = new Date().toLocaleTimeString();
        statusEl.textContent = `${featureCount} earthquakes · ${time}`;
        statusEl.className = "status ready";
      });

      mapEl.addEventListener("ml-map:layer-data-error", (event) => {
        statusEl.textContent = `Data error: ${event.detail.error.message}`;
        statusEl.className = "status error";
      });

      mapEl.addEventListener("ml-map:error", (event) => {
        statusEl.textContent = `Error: ${event.detail.error?.message || event.detail.errors?.[0]?.message}`;
        statusEl.className = "status error";
      });
    </script>
  </body>
</html>
```

```yaml
      circle-radius:
        - interpolate
        - ["linear"]
        - ["get", "mag"]
        - 0
        - 4
        - 5
        - 20
      circle-color:
        - interpolate
        - ["linear"]
        - ["get", "mag"]
        - 0
        - "#22c55e"
        - 3
        - "#eab308"
        - 5
        - "#ef4444"
      circle-opacity: 0.8
      circle-stroke-width: 1
      circle-stroke-color: "#ffffff"
    interactive:
      hover:
        cursor: pointer
      click:
        popup:
          - h3:
              - property: title
          - p:
              - str: "Magnitude: "
              - property: mag
          - p:
              - str: "Depth: "
              - property: depth
              - str: " km"
```

- ✅ No YAML parsing code needed - component handles it
- ✅ Simpler, more readable HTML
- ✅ YAML file is separate and easy to edit
- ✅ Event handlers provide rich status feedback

## Framework Compatibility

`<ml-map>` is a standard custom element, so any framework can render it. Import
`@maplibre-yaml/core/register` once (it defines the element) and import
`maplibre-gl/dist/maplibre-gl.css` in your entry point. Three things differ
from framework to framework: how `config` reaches the element, how you listen
for `ml-map:*` events, and TypeScript.

| Framework | `config` object | `ml-map:*` events | TypeScript |
|-----------|-----------------|-------------------|------------|
| React 19 | Set as a **property**: pass the object or a JSON string | `onml-map:load={…}` prop, or a ref + `addEventListener` | [`@maplibre-yaml/core/react`](#typescript-with-react) |
| React 18 | Set as an **attribute**: you must `JSON.stringify` it (an object becomes `"[object Object]"`) | Ref + `addEventListener` only | [`@maplibre-yaml/core/react`](#typescript-with-react) |
| Vue 3 | Set as a property: pass the object | `@ml-map:load="…"` | Works (add `isCustomElement`, below) |
| Svelte 5 | Set as a property: pass the object | `bind:this` + `addEventListener` | Works out of the box |

`src="/map.yaml"` works the same everywhere. The React snippets below are
files from [`examples/react`](https://github.com/design-practices/maplibre-yaml/tree/main/examples/react),
a Vite + TypeScript app that CI builds against React 18 and React 19 and
drives in a browser; a test fails if a snippet here and its file differ. The
Vue and Svelte snippets were verified with Vue 3.5 and Svelte 5 on Vite 8
(dev server and production build), and the Next.js one with Next.js 16.
`mapReady()` needs 0.7 or later. On 0.6, listen for `ml-map:load` and then
call `getMap()`.

<Aside type="note" title="Re-renders and the config value">
  A *changed* `config` tears down the map and builds a fresh one, which also
  resets the camera. An *equal* one is a no-op: since 0.7 the element
  compares the new value with the one it is showing (by its JSON), so a
  framework that hands it a fresh but identical object on every render (an
  inline `config={{ ... }}`, say) no longer rebuilds the map each time. The
  comparison serializes the document, so for very large inline GeoJSON a
  stable (module-level or memoized) value is still cheaper. On 0.6 every
  assignment rebuilt the map.
</Aside>

Since 0.7, a `config` property set before the element is attached (what React
19, Vue and Svelte do) is validated and given its schema defaults like every
other path: an invalid document shows the "Configuration Error" card. On 0.6
that path skipped validation.

Rendering a map from a config object, for React 18 and 19:

{/* snippet: examples/react/src/snippets/ConfigMap.tsx */}
```tsx
import "@maplibre-yaml/core/register";
import type { MapBlock } from "@maplibre-yaml/core";

export function ConfigMap({ config }: { config: MapBlock }) {
  // A JSON string works on React 18 (set as the attribute) and React 19
  // (set as the property). An equal string never re-renders the map.
  return (
    <ml-map
      config={JSON.stringify(config)}
      style={{ display: "block", width: "100%", height: "400px" }}
    />
  );
}
```

A JSON string works on both majors. React 18 sets it as the attribute before
the element connects. React 19 sets the `config` property, which parses the
string. On React 19 alone you can pass the object directly
(`config={config}`), shown further down.

**Events and the map instance.** React 18 cannot attach listeners for custom
events through props, so use a ref. The same code works on React 19, and the
listeners are typed from `MLMapEventMap`:

{/* snippet: examples/react/src/snippets/YamlMap.tsx */}
```tsx
import "@maplibre-yaml/core/register";
import type { MLMap, MLMapEventMap } from "@maplibre-yaml/core/register";
import { useEffect, useRef, useState } from "react";

export function YamlMap({ src }: { src: string }) {
  const ref = useRef<MLMap>(null);
  const [clicked, setClicked] = useState<string | null>(null);
  const [zoom, setZoom] = useState<number | null>(null);

  useEffect(() => {
    const el = ref.current!;
    const onClick = (event: MLMapEventMap["ml-map:layer-click"]) =>
      setClicked(String(event.detail.feature?.properties?.name));
    const onError = (event: MLMapEventMap["ml-map:error"]) =>
      console.error(event.detail.error ?? event.detail.errors);
    el.addEventListener("ml-map:layer-click", onClick);
    el.addEventListener("ml-map:error", onError);

    // mapReady() resolves with the MapLibre map once the document loaded.
    let cancelled = false;
    el.mapReady().then(
      (map) => {
        if (cancelled) return;
        setZoom(map.getZoom());
        map.on("zoomend", () => setZoom(map.getZoom()));
      },
      () => {} // a failed document also fires ml-map:error
    );

    return () => {
      cancelled = true;
      el.removeEventListener("ml-map:layer-click", onClick);
      el.removeEventListener("ml-map:error", onError);
    };
  }, []);

  return (
    <>
      <ml-map ref={ref} src={src} style={{ display: "block", height: "400px" }} />
      <p>
        Zoom {zoom?.toFixed(1) ?? "…"} · clicked: {clicked ?? "nothing yet"}
      </p>
    </>
  );
}
```

**React 19: object `config` and event props.** React 19 sets custom-element
props as properties and attaches `on*` props as listeners, using the rest of
the name as the event type: `onml-map:load={handler}` listens for
`ml-map:load`. With the typings, each handler gets its event's `detail` type.
React 18 ignores these props, and the typings reject an object `config` there:

{/* snippet: examples/react/src/react19/EventPropsMap.tsx */}
```tsx
import "@maplibre-yaml/core/register";
import type { MapBlock } from "@maplibre-yaml/core";

// React 19 only: `config` takes the object itself (React 19 sets it as a
// property), and `onml-map:*` props attach listeners, typed per event.
export function EventPropsMap({
  config,
  onLoad,
  onLayerClick,
}: {
  config: MapBlock;
  onLoad: () => void;
  onLayerClick: (layerId: string) => void;
}) {
  return (
    <ml-map
      config={config}
      onml-map:load={() => onLoad()}
      onml-map:layer-click={(event) => onLayerClick(event.detail.layerId)}
      onml-map:error={(event) =>
        console.error(event.detail.error ?? event.detail.errors)
      }
      style={{ display: "block", height: "400px" }}
    />
  );
}
```

The colon makes these namespaced JSX attributes. Vite and TypeScript compile
them; if your JSX compiler rejects namespaced attributes, spread them in:
`{...{ "onml-map:load": handler }}`.

**Slot children.** React can render your own controls into the map's corners
(see [Slots](#slots-your-own-chrome-over-the-map)). The element moves slot children into the map, so render
them unconditionally: React may update what is inside them, but must not add
or remove the slotted elements themselves. Toggle one with `hidden` or CSS
instead.

{/* snippet: examples/react/src/snippets/SlotControls.tsx */}
```tsx
import "@maplibre-yaml/core/register";
import type { MLMap } from "@maplibre-yaml/core/register";
import { useRef } from "react";

export function MapWithControls({ src }: { src: string }) {
  const ref = useRef<MLMap>(null);
  const zoomBy = (delta: number) => {
    const map = ref.current?.getMap();
    map?.easeTo({ zoom: map.getZoom() + delta, duration: 300 });
  };

  // Children with slot="top-left" (and the other corners, or "legend") are
  // placed in the map's corner, stacked with the built-in chrome. Render
  // slot children unconditionally: the element moves them into the map, so
  // React may update their contents but must not add or remove them.
  return (
    <ml-map ref={ref} src={src} style={{ display: "block", height: "400px" }}>
      <div slot="top-left" className="map-buttons">
        <button type="button" aria-label="Zoom in" onClick={() => zoomBy(1)}>
          +
        </button>
        <button type="button" aria-label="Zoom out" onClick={() => zoomBy(-1)}>
          −
        </button>
      </div>
    </ml-map>
  );
}
```

**Lifecycle.** Unmounting removes the element, and its `disconnectedCallback`
destroys the MapLibre map: no leaked canvas, and a remount creates exactly one
new map. StrictMode's double-run effects do not re-create the element, so
keep listener setup in an effect that has a cleanup, as shown above. In React
18 a ref or effect only runs after the element has connected, so a `config`
assigned there arrives late; since 0.7 the element waits for it (see the note
under [Method 3](#method-3-json-attribute-programmatic)), but the JSON-string
attribute, present at connect, remains the simplest React 18 path.

#### TypeScript with React

React's JSX types do not know `<ml-map>`, so without help `tsc` reports
*Property 'ml-map' does not exist on type 'JSX.IntrinsicElements'*. Core ships
the typings as a types-only entry. Reference it once, for example in Vite's
`src/vite-env.d.ts`:

```ts
/// <reference types="@maplibre-yaml/core/react" />
```

(`import "@maplibre-yaml/core/react";` in any module works too; the module
is empty at runtime.) It works with `@types/react` 18 and 19 and adapts to
the one you have installed:

| | `@types/react` 19 | `@types/react` 18 |
|---|---|---|
| `src` | `string` | `string` |
| `config` | `MapBlock` object or JSON `string` | JSON `string` only (an object would arrive as `"[object Object]"`) |
| `ref` | `useRef<MLMap>(null)`: `mapReady()`, `getMap()` typed | same |
| `onml-map:*` props | typed per event, for example `event.detail.layerId` on `onml-map:layer-click` | not typed (React 18 ignores them) |
| `children` | slot children, inline `<script type="text/yaml">` | same |

`MLMap` and `MLMapEventMap` are exported from `@maplibre-yaml/core/register`,
and `el.addEventListener("ml-map:layer-click", …)` is typed on any `MLMap`
without React. Core also declares `HTMLElementTagNameMap["ml-map"]`, so
`document.querySelector("ml-map")` and `document.createElement("ml-map")` are
typed as `MLMap` without a cast.

#### Next.js (App Router)

Client components still render on the server, and the element class extends
`HTMLElement`, which does not exist there. A top-level
`import "@maplibre-yaml/core/register"` in a `"use client"` file therefore
fails the build with `ReferenceError: HTMLElement is not defined`. Register the
element from an effect instead:

```jsx
"use client";
import { useEffect } from "react";

export default function YamlMap({ src }) {
  useEffect(() => {
    import("@maplibre-yaml/core/register");
  }, []);

  return <ml-map src={src} style={{ display: "block", height: "400px" }} />;
}
```

The server sends a plain `<ml-map>` tag, and it upgrades once the import
resolves. Import the MapLibre CSS in `app/layout`.

### Vue

Vue sets `config` as a DOM property, so pass the object as it is:

```vue
<template>
  <ml-map
    ref="mapEl"
    :config="config"
    style="width: 100%; height: 400px; display: block;"
    @ml-map:error="(e) => console.error(e.detail.error ?? e.detail.errors)"
  />
</template>

<script setup>
import "@maplibre-yaml/core/register";
import { onMounted, ref } from "vue";

defineProps(["config"]);
const mapEl = ref(null);

onMounted(async () => {
  const map = await mapEl.value.mapReady();
  map.flyTo({ zoom: 3 });
});
</script>
```

Tell Vue's compiler that `ml-*` tags are custom elements. Without this, every
render logs *Failed to resolve component: ml-map* in development:

```js
// vite.config.js
import { defineConfig } from "vite";
import vue from "@vitejs/plugin-vue";

export default defineConfig({
  plugins: [
    vue({
      template: {
        compilerOptions: { isCustomElement: (tag) => tag.startsWith("ml-") },
      },
    }),
  ],
});
```

`vue-tsc` accepts `<ml-map>` by default. Under `strictTemplates` it reports
the element as unknown.

### Svelte

Svelte 5 sets `config` as a property, so pass the object as it is:

```svelte
<script>
  import "@maplibre-yaml/core/register";
  import { onMount } from "svelte";

  let { config } = $props();
  let mapEl;

  onMount(() => {
    const onError = (e) => console.error(e.detail.error ?? e.detail.errors);
    mapEl.addEventListener("ml-map:error", onError);
    mapEl.mapReady().then((map) => map.flyTo({ zoom: 3 }), () => {});
    return () => mapEl.removeEventListener("ml-map:error", onError);
  });
</script>

<ml-map bind:this={mapEl} {config} style="width: 100%; height: 400px; display: block;"></ml-map>
```

Close the tag explicitly: Svelte 5 warns about self-closing non-void elements
such as `<ml-map />`. `onml-map:load={…}` attaches a listener, but Svelte warns
that attribute names should not contain `:`, so use `bind:this` as shown.
`svelte-check` accepts `<ml-map>` and its attributes out of the box. With
`lang="ts"`, type the binding as `let mapEl: MLMap` (imported from
`@maplibre-yaml/core/register`).

## Troubleshooting

### Component Not Rendering

**Symptoms:** `<ml-map>` element exists but shows nothing.

**Solutions:**

1. **Check registration**

   ```javascript
   // Verify component is registered
   console.log(customElements.get("ml-map")); // Should not be undefined
   ```

2. **Check dimensions**

   ```css
   ml-map {
     display: block; /* Required! */
     width: 100%;
     height: 400px;
   }
   ```

3. **Check config is valid JSON**
   ```javascript
   try {
     JSON.parse(mapEl.getAttribute("config"));
   } catch (e) {
     console.error("Invalid JSON config");
   }
   ```

### "Configuration Error" Card

**Symptoms:** The element shows a red "Configuration Error" card listing
field paths and messages (for example `id: Expected string, got undefined`).

**Cause:** The configuration failed to fetch, parse, or validate against the
schema.

**Debug:**

```javascript
mapEl.addEventListener("ml-map:error", (event) => {
  // Each entry is { path, message } — the path names the invalid field
  console.error("Config errors:", event.detail.errors);
});
```

**Common fixes:**

- Ensure `type: "map"` is present
- Ensure `id` is a string
- Ensure `config.center` is `[longitude, latitude]`
- Ensure `config.mapStyle` is a valid URL

### Events Not Firing

**Symptoms:** Event listeners never trigger.

**Solutions:**

1. **Add listeners before setting config**

   ```javascript
   const mapEl = document.getElementById('my-map');

   // ✅ Add listener first
   mapEl.addEventListener('ml-map:load', () => {});

   // Then set config
   mapEl.config = { ... };
   ```

2. **Check for errors**
   ```javascript
   mapEl.addEventListener("ml-map:error", (event) => {
     console.error("Error prevented load:", event.detail.error);
   });
   ```

### Map Loads but No Layers Visible

**Symptoms:** Base map shows, but data layers don't appear.

**Debug steps:**

1. **Check layer loading events**

   ```javascript
   mapEl.addEventListener("ml-map:layer-data-loading", (e) =>
     console.log("Loading:", e.detail.layerId)
   );
   mapEl.addEventListener("ml-map:layer-data-loaded", (e) =>
     console.log("Loaded:", e.detail.layerId, e.detail.featureCount)
   );
   mapEl.addEventListener("ml-map:layer-data-error", (e) =>
     console.error("Error:", e.detail.layerId, e.detail.error)
   );
   ```

2. **Check network requests** - Open browser DevTools → Network tab

3. **Verify GeoJSON URL** - Open the URL directly in browser

4. **Check for CORS issues** - Look for CORS errors in console

## Component API Reference

### Attributes

| Attribute | Type        | Description                                |
| --------- | ----------- | ------------------------------------------ |
| `src`     | string      | URL to external YAML configuration file    |
| `config`  | JSON string | Map configuration as stringified JSON      |

### Properties

| Property | Type               | Description                        |
| -------- | ------------------ | ---------------------------------- |
| `config` | Object or string   | Map configuration object (set/get) |

### Methods

| Method                          | Returns                   | Description |
| ------------------------------- | ------------------------- | ----------- |
| `mapReady()`                    | `Promise<maplibregl.Map>` | Resolves with the live map once the document loads (immediately if loaded); rejects on `ml-map:error` |
| `getMap()`                      | `maplibregl.Map \| null`  | The MapLibre GL map instance (`null` before a render) |
| `getRenderer()`                 | `MapRenderer \| null`     | The underlying renderer |
| `isLoaded()`                    | `boolean`                 | Whether the map finished loading |
| `reload()`                      | `Promise<void>`           | Re-render from `src` or the inline YAML script; slot children are kept |
| `addLayer(layer)`               | `Promise<void>`           | Add a layer (same shape as a document layer) |
| `removeLayer(layerId)`          | `void`                    | Remove a layer |
| `setLayerVisibility(id, on)`    | `void`                    | Show or hide a layer |
| `updateLayerData(id, geojson)`  | `void`                    | Replace a GeoJSON layer's data |

Refresh control (`pauseRefresh` / `resumeRefresh` / `refreshNow`) is not
exposed yet — see bead `ml-few`.

### Events

See the [event reference](#event-reference) above for the complete list —
sixteen events covering lifecycle, layer data, interactions, markers,
images, and the params panel.

## Upgrading to 0.6

Three behavior changes are worth knowing when you move to 0.6:

- **`!html` is trust-gated, not unconditional.** A popup `!html` value renders
  as raw markup only under a **trusted** capability policy; otherwise it is
  escaped and shown as text. Under `<ml-map>` (untrusted by default) `!html`
  content is escaped.
- **Malformed inline GeoJSON now warns.** A v1 document with malformed inline
  GeoJSON `data` emits a warning (promoted to an error under `mlym validate
  --strict` / CI). Pre-check inline geometry.
- **v2 `style.metadata` flows through.** In Format v2, `style.metadata` is
  carried to the emitted `style.json` root `metadata` slot.
