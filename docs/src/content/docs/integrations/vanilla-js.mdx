This page covers maplibre-yaml's JavaScript API: `YAMLParser` to parse and
validate a document, and `MapRenderer` to draw it into a `<div>` you control.
Use it when your own code drives the map. For a map with no JavaScript at
all, the `<ml-map>` element is simpler.

For a scroll-driven story map, the same setup gives you `<ml-scrollytelling>`:
see [Story maps in plain HTML](/integrations/scrollytelling-html/).

## Quick Start: Web Component (Recommended)

If you don't need to drive the map from code, use the `<ml-map>` element: one
HTML page and one YAML file, with no JavaScript to write. The
[Quick start](/getting-started/quick-start/) walks through it, and
[HTML pages: the `<ml-map>` element](/integrations/web-components/) covers the
element in full. A page that starts with `<ml-map>` can still reach the map
from a script later: `mapReady()` resolves with the MapLibre map, and
`getRenderer()` returns the `MapRenderer` this page describes.

## Quick Start: JavaScript API (More Control)

For cases where you need programmatic control or want to use the lower-level APIs:

<Steps>

1. **Create an HTML file**

   ```html
   <!DOCTYPE html>
   <html lang="en">
     <head>
       <meta charset="utf-8" />
       <meta name="viewport" content="width=device-width, initial-scale=1" />
       <title>My Map</title>
       <link
         href="https://unpkg.com/maplibre-gl@6/dist/maplibre-gl.css"
         rel="stylesheet"
       />
       <!-- Tell the browser where to find maplibre-gl -->
       <script type="importmap">
         { "imports": { "maplibre-gl": "https://unpkg.com/maplibre-gl@6/dist/maplibre-gl.mjs" } }
       </script>
       <style>
         body {
           margin: 0;
         }
         #map {
           width: 100%;
           height: 100vh;
         }
       </style>
     </head>
     <body>
       <div id="map"></div>
       <script type="module" src="map.js"></script>
     </body>
   </html>
   ```

2. **Create a YAML configuration file**

   Create `map.yaml` next to it:

   ```yaml
   type: map
   id: my-first-map
   config:
     center: [-74.006, 40.7128]
     zoom: 12
     mapStyle: "https://tiles.openfreemap.org/styles/liberty"
   layers:
     - id: points
       type: circle
       source:
         type: geojson
         data:
           type: FeatureCollection
           features:
             - type: Feature
               geometry:
                 type: Point
                 coordinates: [-74.006, 40.7128]
               properties:
                 name: "New York City"
       paint:
         circle-radius: 10
         circle-color: "#3b82f6"
   ```

3. **Create your JavaScript file**

   Create `map.js`:

   ```javascript
   import {
     YAMLParser,
     MapRenderer,
     toModel,
   } from "https://esm.sh/@maplibre-yaml/core@0.9?external=maplibre-gl";

   // Fetch and parse YAML configuration
   const response = await fetch("map.yaml");
   const yamlText = await response.text();

   // Parse and validate
   const result = YAMLParser.safeParseMapBlock(yamlText);

   if (!result.success) {
     console.error("Configuration errors:", result.errors);
     document.getElementById("map").innerHTML = `
          <div style="color: red; padding: 20px;">
            <h3>Configuration Error</h3>
            <pre>${JSON.stringify(result.errors, null, 2)}</pre>
          </div>
        `;
   } else {
     // Render the map: normalize the parsed document, then hand it to the renderer
     const renderer = MapRenderer.fromModel(
       document.getElementById("map"),
       toModel(result.data)
     );

     renderer.on("load", () => {
       console.log("Map loaded successfully!");
     });
   }
   ```

4. **Serve and view**

   ```bash
   npx serve .
   ```

   Open the address it prints (usually http://localhost:3000). Opening the
   HTML file directly does not work: a `file://` page cannot fetch `map.yaml`.

</Steps>

## Which Approach Should I Use?

**Use the Web Component (`<ml-map>`) if:**
- You want the simplest possible integration
- You don't need programmatic control
- You're embedding maps in static pages
- You want zero JavaScript code

**Use the JavaScript API (`YAMLParser` + `MapRenderer`) if:**
- You need to programmatically modify the map
- You want to build custom UI controls
- You need access to the MapLibre GL instance
- You're building a complex interactive application

<Aside type="tip">
  You can also use **both approaches together** - start with `<ml-map>` for basic rendering,
  then access the underlying `MapRenderer` via `mapElement.getRenderer()` when you need more control.
</Aside>

## Installation Options

**From a CDN**, with no build step: keep the import map from the quick start
above and import the API from esm.sh with `?external=maplibre-gl`, so the
library renders with the maplibre-gl you pinned instead of a second copy esm.sh
picks. The CDN page, versions in CDN URLs and hosting the files yourself are in
[Installation](/getting-started/installation/#browser-usage-cdn).

**With npm and a bundler**, install `@maplibre-yaml/core` and `maplibre-gl@^6`
([Installation](/getting-started/installation/#using-a-bundler-vite) has the
npm, pnpm and yarn lines and the supported maplibre-gl versions). In your
entry file, point maplibre-gl 6 at its worker before you render a map:
inside a bundle it cannot find its worker file by itself, and without these
lines every map fails with *"Worker failed to load"*. With Vite:

```javascript
// src/main.js
import { setWorkerUrl } from "maplibre-gl";
import workerUrl from "maplibre-gl/dist/maplibre-gl-worker.mjs?worker&url";
import { YAMLParser, MapRenderer, toModel } from "@maplibre-yaml/core";
import "maplibre-gl/dist/maplibre-gl.css";

setWorkerUrl(workerUrl);

const response = await fetch("./map.yaml");
const result = YAMLParser.safeParseMapBlock(await response.text());
if (result.success) {
  MapRenderer.fromModel(document.getElementById("map"), toModel(result.data));
} else {
  console.error("Configuration errors:", result.errors);
}
```

```html
<!-- index.html: the map container needs a height -->
<body>
  <div id="map" style="height: 100vh;"></div>
  <script type="module" src="/src/main.js"></script>
</body>
```

Put `map.yaml` and the data files it loads in Vite's **`public/`** folder.
A file next to `index.html` loads in `npm run dev` but is not copied by
`npm run build`. On maplibre-gl 4 or 5, leave out the worker lines.

## Loading YAML Configuration

### Recommended: External YAML Files

External files are the recommended approach for most projects:

```javascript
// Load from file
const response = await fetch("/configs/map.yaml");
const yamlText = await response.text();
const result = YAMLParser.safeParseMapBlock(yamlText);
```

**Benefits:**

- Clean separation of configuration and code
- Easy to edit without touching JavaScript
- Proper YAML indentation preserved
- Can be validated independently
- Cacheable by browsers

### Alternative: Inline YAML Strings

For simple cases where you want everything in one file:

```javascript
const yamlConfig = `type: map
id: inline-map
config:
  center: [-74.006, 40.7128]
  zoom: 12
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"
layers: []`;

const result = YAMLParser.safeParseMapBlock(yamlConfig);
```

<Aside type="caution" title="Template Literal Formatting">
A template literal keeps every space you type, so the YAML inside it must be
indented consistently **relative to its own first line**. A leading newline, a
trailing newline, or indenting the whole block to match your JavaScript are
all fine; what breaks parsing is a first line that sits at a different
indentation from the lines after it (for example, content that starts right
after the backtick while the remaining lines are indented to match the code).

</Aside>

## Core APIs

### YAMLParser

The parser validates YAML against the maplibre-yaml schema.

```javascript
import { YAMLParser } from "@maplibre-yaml/core";

// Safe parsing (recommended) - returns result object
const result = YAMLParser.safeParseMapBlock(yamlText);

if (result.success) {
  console.log("Valid config:", result.data);
} else {
  console.error("Errors:", result.errors);
  // errors: [{ path: 'config.center', message: 'Expected array' }, ...]
}

// Direct parsing - throws on error
try {
  const config = YAMLParser.parseMapBlock(yamlText);
} catch (error) {
  console.error("Parse error:", error.message);
}
```

Pick the method by document type. `parseMapBlock` / `safeParseMapBlock` take
one `type: map` document, and `parseScrollytellingBlock` /
`safeParseScrollytellingBlock` one `type: scrollytelling` story.
`parseYAMLConfig` / `safeParseYAMLConfig` (the same as `YAMLParser.parse` /
`safeParse`) parse a whole root document, a `pages:` list of pages and
blocks, and reject a bare map block. Every parser method, and the data
utilities (`DataFetcher`, `PollingManager`, `StreamManager`, `DataMerger`),
are in the [TypeScript API reference](/reference/api/maplibre-yaml/core/).

### MapRenderer

The renderer creates and manages the MapLibre GL map.

```javascript
import { YAMLParser, MapRenderer, toModel } from "@maplibre-yaml/core";

// Render a parsed map document (v1 or Format v2). Errors arrive through the
// `onError` option — there is no "error" event.
const block = YAMLParser.parseMapBlock(yamlText);
const renderer = MapRenderer.fromModel(container, toModel(block), {
  onError: (error, fatal) => {
    /* Handle error; fatal === false for runtime errors the map survives */
  },
});

// Events
renderer.on("load", () => {
  /* Map and every layer ready */
});
renderer.on("layer:click", ({ layerId, feature, lngLat }) => {
  /* Handle click */
});

// Methods
renderer.destroy(); // Clean up resources
```

`MapRenderer.fromModel(container, model, options?)` is the one-call way to
render a parsed document. The constructor is the lower-level form,
`new MapRenderer(container, config, layers?, options?, sources?)`, which takes
the document's parts (`block.config`, `block.layers`, …) rather than the whole
document.

The on-page error card, the "Part of this map couldn't load" notice, the
author hints and the "Loading map…" indicator belong to `<ml-map>`, not to
`MapRenderer`: with the renderer, every problem arrives through `onError`
(with `fatal` and a `context` naming the layer or source), and showing it is
up to your page. The same goes for opening already framed on a `fitTo`
source: `<ml-map>` starts the download before it builds the map, and hands it
over through the renderer's `sourceData` option.

### Full Event List

```javascript
// Map lifecycle (errors arrive through the onError option, not an event)
renderer.on("load", () => {});

// Layer lifecycle
renderer.on("layer:added", ({ layerId }) => {});
renderer.on("layer:removed", ({ layerId }) => {});

// Layer data (initial load and every live-data refresh)
renderer.on("layer:data-loading", ({ layerId }) => {});
renderer.on("layer:data-loaded", ({ layerId, featureCount }) => {});
renderer.on("layer:data-error", ({ layerId, error }) => {});

// Interaction events
renderer.on("layer:click", ({ layerId, feature, lngLat }) => {});
renderer.on("layer:hover", ({ layerId, feature, lngLat }) => {});

// Markers, images, and the params panel
renderer.on("markers:added", ({ count }) => {});
renderer.on("marker:click", ({ index, at }) => {});
renderer.on("marker:icon-error", ({ index, icon }) => {});
renderer.on("image:error", ({ name, url }) => {});
renderer.on("parameter:change", ({ key, value }) => {});
renderer.on("layer:visibility", ({ layerId, visible }) => {});

// fitTo framed its source's data; a classify: layer's classes as drawn
renderer.on("camera:fit", ({ source, bounds }) => {});
renderer.on("layer:classified", ({ layerId, classify }) => {});
```

## Working with Live Data

### Polling (Auto-refresh)

```yaml
# map.yaml
type: map
id: live-map
config:
  center: [-120, 37]
  zoom: 5
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"
layers:
  - id: earthquakes
    type: circle
    source:
      type: geojson
      url: "https://earthquake.usgs.gov/earthquakes/feed/v1.0/summary/all_hour.geojson"
      refresh:
        refreshInterval: 60000 # Refresh every 60 seconds
        updateStrategy: replace
    paint:
      circle-radius: 8
      circle-color: "#ef4444"
```

<Aside type="caution" title="No programmatic refresh control yet">
  Earlier versions of this page showed `renderer.pauseRefresh()`,
  `resumeRefresh()` and `refreshNow()`. Those methods are **not** exposed on
  `MapRenderer` (or on `<ml-map>`) today — calling them throws. Polling runs on
  the `refreshInterval` you declare in YAML. Exposing pause/resume/refresh is
  planned.
</Aside>

### Handling Data Updates

```javascript
renderer.on("layer:data-loading", ({ layerId }) => {
  showSpinner(layerId);
});

renderer.on("layer:data-loaded", ({ layerId, featureCount }) => {
  hideSpinner(layerId);
  updateStatus(`Loaded ${featureCount} features`);
});

renderer.on("layer:data-error", ({ layerId, error }) => {
  hideSpinner(layerId);
  showError(`Failed to load ${layerId}: ${error.message}`);
});
```

## Accessing the MapLibre Instance

For advanced use cases, access the underlying MapLibre GL map:

```javascript
import * as maplibregl from "maplibre-gl";

const renderer = MapRenderer.fromModel(container, toModel(block));

renderer.on("load", () => {
  // Access the MapLibre GL map instance
  const map = renderer.getMap();

  // Use any MapLibre GL API
  map.flyTo({ center: [-122.4, 37.8], zoom: 14 });

  // Add custom controls
  map.addControl(new maplibregl.NavigationControl());

  // Add custom event handlers
  map.on("moveend", () => {
    console.log("Map moved to:", map.getCenter());
  });
});
```

<Aside type="tip">
  The MapRenderer manages sources and layers declared in your YAML. You can add
  additional sources and layers directly via the MapLibre API, but be careful
  not to conflict with IDs defined in your YAML configuration.
</Aside>

**dashboard.js:**

```javascript
import {
  YAMLParser,
  MapRenderer,
  toModel,
} from "https://esm.sh/@maplibre-yaml/core@0.9?external=maplibre-gl";

// State
let visible = true;
let renderer = null;

// DOM elements
const statusEl = document.getElementById("status");
const toggleBtn = document.getElementById("toggle");

function showError(message) {
  statusEl.textContent = message;
  statusEl.style.color = "#ef4444";
}

// Load and initialize
async function init() {
  try {
    // Load YAML configuration
    const response = await fetch("earthquakes.yaml");
    const yamlText = await response.text();

    // Parse and validate
    const result = YAMLParser.safeParseMapBlock(yamlText);

    if (!result.success) {
      showError(`Config error: ${result.errors[0].message}`);
      return;
    }

    // Create renderer
    renderer = MapRenderer.fromModel(
      document.getElementById("map"),
      toModel(result.data),
      { onError: (error) => showError(`Error: ${error.message}`) }
    );

    // Fires on the first load and again on every 60-second refresh
    renderer.on("layer:data-loading", ({ layerId }) => {
      statusEl.textContent = `Loading ${layerId}...`;
    });

    renderer.on("layer:data-loaded", ({ featureCount }) => {
      const time = new Date().toLocaleTimeString();
      statusEl.textContent = `${featureCount} earthquakes · Updated ${time}`;
      statusEl.style.color = "#666";
    });

    renderer.on("layer:data-error", ({ error }) => {
      showError(`Error: ${error.message}`);
    });
  } catch (error) {
    showError(`Failed to initialize: ${error.message}`);
  }
}

// Button handler: show or hide the earthquake layer
toggleBtn.addEventListener("click", () => {
  if (!renderer) return;

  visible = !visible;
  renderer.setLayerVisibility("earthquakes", visible);
  toggleBtn.textContent = visible ? "Hide Earthquakes" : "Show Earthquakes";
  toggleBtn.classList.toggle("active", !visible);
});

// Initialize
init();
```

## Format v2 and Interactions

Two guides cover capabilities that apply directly to the vanilla-JS path:

- **[Format v2](/guides/format-v2/)** — the additive, opt-in `style:` / `runtime:`
  split. A v2 document parses to the same internal model as its v1 twin, so
  `YAMLParser` and `MapRenderer` consume it unchanged.
- **[Export to style.json](/guides/export/)** — how declarative
  interactions are authored, why a compiled `style.json` is inert on its own
  (the export guarantee), and how `attachInteractions` wires behavior back onto

  trusted-policy gate are documented in full.

## Troubleshooting

These problems are specific to the JavaScript API. A map with no size, an
invalid document and the other problems every page shares are in
[Troubleshooting](/troubleshooting/), for example
[the map has no height](/troubleshooting/#the-map-has-no-height) and
[an error card instead of the map](/troubleshooting/#an-error-card-instead-of-the-map),
which lists the usual YAML mistakes. With `MapRenderer` there is no error
card: `safeParseMapBlock` returns them as `errors`, each with its `path`.

### Map Shows But No Data Appears

**Symptoms:** Base map renders, but layers with URL data don't show any features.

**Common Causes:**

1. **CORS blocking the request**

   Check the browser console for CORS errors. The data URL must allow cross-origin requests.

```javascript
// Check network tab - is the request being made?
renderer.on("layer:data-error", ({ layerId, error }) => {
  console.error(`${layerId} failed:`, error);
});
```

2. **URL returns invalid GeoJSON**

   Test the URL directly in your browser to verify it returns valid GeoJSON.

3. **Data loaded but features have no geometry**

```javascript
renderer.on("layer:data-loaded", ({ layerId, featureCount }) => {
  console.log(`${layerId}: ${featureCount} features`);
  // If featureCount is 0, the GeoJSON may be empty or malformed
});
```

4. **The site is published under a subpath** (a GitHub Pages project site,
   `https://<user>.github.io/<repo>/`) and the paths in the YAML start with
   `/` (`/data/x.geojson`), so they point at the domain root. With
   `<ml-map>`, add `base="/<repo>/"`
   ([details](/guides/publishing/#html-pages-the-base-attribute)).
   With `MapRenderer`, resolve the paths before rendering, as the element
   does: `const model = applyDocumentBase(toModel(block), "/<repo>/")`, then
   build the renderer from `denormalizeConfig(model)`,
   `denormalizeLayers(model)`, `denormalizeOptions(model)` and
   `denormalizeSources(model)` (all exported by `@maplibre-yaml/core`). For a
   single URL, `resolveDocumentUrl(url, "/<repo>/")`.

### Template Literal YAML Issues

**Symptoms:** YAML works in a file but fails when inline in JavaScript.

**Cause:** A template literal keeps the indentation of your source code, so
the first line and the lines after it can end up at different depths. The
parser reports a `yaml-syntax` error such as "YAML indentation error: Line 2
is indented differently from line 1 above it".

```javascript
// ❌ WRONG - first line starts at column 0, the rest are indented with the code
function load() {
  const yaml = `type: map
    id: my-map
    config:
      center: [-74, 40]`;
}

// ✅ CORRECT - every line at the same depth (a leading newline is fine)
const yaml = `
type: map
id: my-map
config:
  center: [-74, 40]
  zoom: 10
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"
layers: []
`;
```

The same applies to inline YAML in a `<script type="text/yaml">` tag: start
the YAML on the line after the opening tag, not on the same line, and keep
every line at the same depth relative to the first.

Indent with spaces only: YAML rejects tab indentation.

**Best Practice:** Use external YAML files whenever possible.

### Events Not Firing

**Symptoms:** `renderer.on('load', ...)` callback never runs.

**Common Causes:**

1. **Event registered after map loaded**

```javascript
// ❌ Map might already be loaded
const renderer = MapRenderer.fromModel(container, toModel(block));
setTimeout(() => {
  renderer.on("load", () => {}); // Might miss the event
}, 1000);

// ✅ Register immediately
const renderer = MapRenderer.fromModel(container, toModel(block));
renderer.on("load", () => {});
```

2. **An error prevented the load**

`MapRenderer` reports errors through the `onError` option rather than an
event; pass it when you create the renderer:

```javascript
const renderer = MapRenderer.fromModel(container, toModel(block), {
  onError: (error, fatal) => {
    console.error("Map failed:", error, { fatal });
  },
});
```
