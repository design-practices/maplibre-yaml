## Polling (auto-refresh)

The simplest way to keep data current is polling - fetching data at regular intervals:

```yaml
source:
  type: geojson
  url: "https://earthquake.usgs.gov/earthquakes/feed/v1.0/summary/all_hour.geojson"
  refresh:
    refreshInterval: 60000 # Refresh every 60 seconds (milliseconds)
```

### Controlling polling

Polling runs on the `refreshInterval` you write in the YAML. There is no
method to pause, resume or force a refresh from JavaScript yet; to change the
data yourself, call `updateLayerData(layerId, geojson)` on `<ml-map>` or a
`MapRenderer`.

<Aside>
  Polling is automatically paused when the browser tab is hidden and resumes
  when visible again.
</Aside>

Live updates work on GeoJSON sources given by `url:`. A FlatGeobuf or
GeoParquet file ([Large data](/guides/cloud-native-data/)) is read once:
`refresh:` or `stream:` on one is a validation error.

## Update strategies

When new data arrives, how should it combine with existing data?

### Replace (default)

New data completely replaces old data:

```yaml
source:
  type: geojson
  url: "https://..."
  refresh:
    refreshInterval: 30000
    updateStrategy: replace # Default behavior
```

**Use for:** Complete datasets that are re-fetched in full each time.

### Merge

Update existing features, add new ones, keep features not in the update:

```yaml
source:
  type: geojson
  url: "https://api.example.com/vehicles"
  refresh:
    refreshInterval: 5000
    updateStrategy: merge
    updateKey: "vehicleId" # Match features by this property
```

**Use for:** Entity tracking where each feature has a unique ID.

**Example scenario:**

- Initial data: Vehicles A, B, C
- Update contains: A (new position), D (new vehicle)
- Result: A (updated), B (unchanged), C (unchanged), D (added)

### Append with window

Add new features while limiting total count or age:

```yaml
source:
  type: geojson
  data: { type: FeatureCollection, features: [] }   # empty until messages arrive
  stream:
    type: sse
    url: "https://stream.example.com/events"
  refresh:
    updateStrategy: append-window
    windowSize: 100 # Keep latest 100 features
    windowDuration: 3600000 # Or features from last hour
    timestampField: "time" # Property containing timestamp
```

**Use for:** Event streams, activity feeds, time-series data.

## Server-Sent Events (SSE)

For real-time push updates, use SSE streaming. A streamed source still needs
somewhere to start: a `url:` to load first, or `data:` with an empty
`FeatureCollection` to start blank (validation refuses a GeoJSON source with
only `stream:`). It also needs a `refresh:` block next to `stream:`: the
stream connects only when one is there, and its `updateStrategy` says how
each message is applied.

```yaml
source:
  type: geojson
  data: { type: FeatureCollection, features: [] }   # empty until messages arrive
  stream:
    type: sse
    url: "https://stream.example.com/events"
    reconnect: true # Auto-reconnect on disconnect
    reconnectMaxAttempts: 10 # Give up after 10 failures
    reconnectDelay: 1000 # Initial delay (doubles each retry)
  refresh:
    updateStrategy: merge
    updateKey: "id"
```

### How SSE works

1. Browser opens persistent HTTP connection
2. Server sends data as events occur
3. Browser automatically reconnects if connection drops
4. Each message updates the map

### SSE configuration options

| Option                 | Default       | Description                  |
| ---------------------- | ------------- | ---------------------------- |
| `reconnect`            | `true`        | Auto-reconnect on disconnect |
| `reconnectMaxAttempts` | `10`          | Max reconnection attempts    |
| `reconnectDelay`       | `1000`        | Initial delay (ms)           |
| `reconnectMaxDelay`    | `30000`       | Max delay between retries    |
| `eventTypes`           | `['message']` | Event types to listen for    |

## WebSocket streaming

For bidirectional communication, use WebSocket:

```yaml
source:
  type: geojson
  data: { type: FeatureCollection, features: [] }   # empty until messages arrive
  stream:
    type: websocket
    url: "wss://stream.example.com/data"
    reconnect: true
  refresh:
    updateStrategy: merge
    updateKey: "id"
```

WebSocket is useful when you need to send messages to the server (e.g., subscribing to specific data channels).

## Reacting to updates

Each poll or stream message that reaches the map fires the layer's data
events, so a page can show when the data last changed or that a request
failed:

```javascript
const mapEl = document.querySelector("ml-map");

mapEl.addEventListener("ml-map:layer-data-loaded", (event) => {
  const { layerId, featureCount } = event.detail;
  console.log(`${layerId}: ${featureCount} features`);
});

mapEl.addEventListener("ml-map:layer-data-error", (event) => {
  const { layerId, error } = event.detail;
  console.error(`${layerId} error:`, error.message);
});
```

With the [JavaScript API](/integrations/vanilla-js/), the same events are
`renderer.on("layer:data-loaded", …)` and `renderer.on("layer:data-error", …)`.
A stream reconnects by itself, as set by its `reconnect*` options; the
connection's own states (connecting, reconnecting) aren't reported as events.

## Complete example

Here's a complete live tracking example. `https://api.example.com/vehicles` is
a **placeholder**: there is no public vehicle feed behind it, so as printed the
map shows only the basemap. Point `url:` at your own endpoint that returns a
GeoJSON `FeatureCollection` of points with `vehicleId`, `vehicleName`,
`status` and `lastUpdate` properties (and allows cross-origin requests).

```yaml
type: map
id: vehicle-tracker
config:
  center: [-122.4, 37.8]
  zoom: 12
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"

layers:
  - id: vehicles
    type: circle
    source:
      type: geojson
      url: "https://api.example.com/vehicles"
      refresh:
        refreshInterval: 5000 # Poll every 5 seconds
        updateStrategy: merge # Update existing, add new
        updateKey: "vehicleId" # Match by vehicle ID
      cache:
        enabled: false # Don't cache live data
    paint:
      circle-radius: 10
      circle-color:
        - match
        - ["get", "status"]
        - "active"
        - "#22c55e"
        - "idle"
        - "#eab308"
        - "offline"
        - "#6b7280"
        - "#6b7280"
      circle-stroke-width: 2
      circle-stroke-color: "#ffffff"
    interactive:
      hover:
        cursor: pointer
      click:
        popup:
          - h3:
              - property: vehicleName
          - p:
              - str: "Status: "
              - property: status
          - p:
              - str: "Last update: "
              - property: lastUpdate

controls:
  navigation: true
```

## Best practices

1. **Choose appropriate intervals** - Don't poll more frequently than data changes
2. **Use merge for entities** - When tracking things with IDs, use merge to avoid flicker
3. **Set reasonable retry limits** - Don't retry forever if the server is down
4. **Disable cache for live data** - Ensure you're always getting fresh data
5. **Handle errors gracefully** - Show users when data isn't updating (listen for `ml-map:layer-data-error`)
