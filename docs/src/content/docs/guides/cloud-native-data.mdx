A GeoJSON file of tens of megabytes is slow to download and slow to draw.
Large-data formats (also called cloud-native) are made to be read **in
parts**: the browser asks the web server for only the bytes it needs, so a
map can show one city from a country-sized file. maplibre-yaml reads four of
them with nothing but YAML, in a plain HTML page, in Astro and under any
bundler.

## Which format?

| You have | Use | Page |
| --- | --- | --- |
| Many features that don't change (buildings, parcels, roads), any size | **PMTiles**: vector tiles cut in advance, in one file | [PMTiles](/guides/pmtiles/) |
| A file of features with properties to click, filter or classify | **FlatGeobuf** (`.fgb`) | [FlatGeobuf](/guides/flatgeobuf/) |
| A table from Python, R or DuckDB, especially one with many columns | **GeoParquet** (`.parquet`) | [GeoParquet](/guides/geoparquet/) |
| Imagery, elevation, or a grid of measurements | **Cloud Optimized GeoTIFF** (`.tif`) | [COG](/guides/cog/) |
| Raster or elevation tiles you already cut | **PMTiles** (a raster archive) | [PMTiles](/guides/pmtiles/) |
| A whole basemap with no tile server | **Protomaps** `.pmtiles` | [Host your own basemap](/guides/host-your-own-basemap/) |

Under about 10 MB, plain GeoJSON is fine ([Loading data](/guides/data-sources/)).
FlatGeobuf and GeoParquet files become ordinary GeoJSON sources, so popups,
`classify:`, clustering and `fitTo` work on them as on any GeoJSON. PMTiles
holds tiles, cut in advance, which is what keeps a huge dataset fast.

## The rule: `type:` is what MapLibre draws, the URL is what the file is

You keep writing the source type MapLibre knows (`vector`, `raster`,
`raster-dem`, `geojson`) and point `url:` at the file. The file name tells
maplibre-yaml how to read it.

- **`pmtiles://`** in front of the URL works too (`url: pmtiles://data/x.pmtiles`),
  the form MapLibre's own examples use; so does `cog://` for a COG.
- **`format:`** names the format when the URL can't, such as a signed link or
  an API endpoint with no file extension. It wins over the URL:

  ```yaml
  sources:
    parcels:
      type: geojson
      url: "https://data.example.org/api/parcels?f=fgb"
      format: flatgeobuf      # pmtiles, flatgeobuf, geoparquet or cog
  ```

<Aside type="caution" title="type: pmtiles is a mistake (with a fix)">
`type: pmtiles`, `type: flatgeobuf`, `type: geoparquet`, `type: cog` and
similar are rejected with a message that says what to write instead
(`type: vector` with the `.pmtiles` URL, `type: geojson` with the `.fgb` or
`.parquet` URL, `type: raster` with the `.tif` URL). A file on the wrong kind
of source, such as a `.fgb` file on a `vector` source, is caught the same
way, and so is a misspelt `format:` (`format: parquet` gets "did you mean
`geoparquet`?"). `mlym validate` and the Astro content loader report these
too.
</Aside>

## Hosting: range requests and CORS

These files are read in parts with HTTP **range requests**, so the server has
to support them. GitHub Pages, Netlify, Cloudflare, S3 and R2 do, and so do
`npx serve`, `astro dev` and `astro preview` on your computer;
`python -m http.server` doesn't. A file on another site also needs CORS that
allows the `Range` header. The full host list and the CORS rule are in
[Publishing › Large files](/guides/publishing/#large-files-range-requests-and-cors).

maplibre-yaml downloads the reader for a format only when a map uses it.
From the CDN that is automatic; if you host maplibre-yaml's own files, copy
the whole `dist/` folder, not only `register.js`
([Hosting the files yourself](/getting-started/installation/#hosting-the-files-yourself)).

## When something goes wrong

A problem with one file never takes down the map: the basemap and every other
layer still draw, and the map's notice ("Part of this map couldn't load")
says what happened. The common cases:

| The notice says | Fix |
| --- | --- |
| "…was served without range-request support" | Use a server with range requests (above). Locally, `npx serve` instead of `python -m http.server`. |
| "…comes from a server that compresses the parts of files it sends" | cdn.jsdelivr.net does this. Put the file on your own site, or use fastly.jsdelivr.net. |
| "The browser couldn't read …" (CORS, or unreachable) | The other server must allow your site and the `Range` header ([Publishing](/guides/publishing/#large-files-range-requests-and-cors)). |
| "…isn't a PMTiles file. A wrong path often returns a web page instead" | Check the file name and folder. |
| "…didn't load (404 Not Found)", with where the browser looked | Check the path; on a project site, set `base` ([Loading data › paths](/guides/data-sources/#relative-paths)). |
| "…is 180 MB, too large to load whole in a browser" | Add `load: viewport` ([FlatGeobuf](/guides/flatgeobuf/#whole-file-or-by-view), [GeoParquet](/guides/geoparquet/#whole-file-or-by-view)), or convert the data to PMTiles. |
| "…is in EPSG:…" | The file is in the wrong projection; the notice gives the command that converts it ([FlatGeobuf](/guides/flatgeobuf/#troubleshooting), [GeoParquet](/guides/geoparquet/#troubleshooting), [COG](/guides/cog/#troubleshooting)). |
| "The PMTiles reader (`…/chunks/pmtiles.js`) couldn't be downloaded" | Copy maplibre-yaml's whole `dist/` folder, or load it from the CDN (above). |

Problems specific to one format are on its page. More symptoms:
[Troubleshooting › Large data](/troubleshooting/#large-data-pmtiles-flatgeobuf-geoparquet-and-cog).

## Format v2

In a [format v2](/guides/format-v2/) document the URL stays in the source,
and `format:`, `load:`, `columns:` and `colorRamp:` move under the source's
`runtime:`. A Protomaps basemap is written under `style:` as
`basemap: data/nyc.pmtiles`, the same forms as `mapStyle:`.

```yaml
version: 2
type: map
id: large-data-v2
style:
  basemap: "https://tiles.openfreemap.org/styles/positron"
  center: [10.2, 42.15]
  zoom: 10
  sources:
    outlines: { type: vector, url: /gallery-assets/cloud-native/districts.pmtiles }
    points:
      type: geojson
      url: /gallery-assets/cloud-native/points.fgb
      runtime:
        load: { mode: viewport, minzoom: 11 }
    districts:
      type: geojson
      url: /gallery-assets/cloud-native/districts.parquet
      runtime:
        columns: [name, category]
  layers:
    - { id: districts, type: fill, source: districts, paint: { fill-color: "#e9c46a", fill-opacity: 0.5 } }
    - { id: outlines, type: line, source: outlines, source-layer: districts }
    - { id: points, type: circle, source: points }
```
