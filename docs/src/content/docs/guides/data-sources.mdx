maplibre-yaml supports multiple ways to provide data to your layers: inline GeoJSON, remote URLs, and streaming connections.

## Inline data

For small, static datasets, embed the GeoJSON directly:

```yaml
source:
  type: geojson
  data:
    type: FeatureCollection
    features:
      - type: Feature
        geometry:
          type: Point
          coordinates: [-74.006, 40.7128]
        properties:
          name: "New York"
```

<Aside type="tip">
  Inline data is great for prototyping and small datasets. For larger datasets
  (100+ features), use a URL instead.
</Aside>

## Remote URL

Load GeoJSON from any URL:

```yaml
source:
  type: geojson
  url: "https://earthquake.usgs.gov/earthquakes/feed/v1.0/summary/all_week.geojson"
```

The file can hold a `FeatureCollection`, a single `Feature`, or a bare
geometry (`{"type": "Polygon", …}`), as geojson.io or a copied feature gives
you; a single feature or geometry is read as a one-feature collection.

<Aside type="tip" title="Large files?">
  A GeoJSON file of tens of megabytes is slow to download and draw. For
  large datasets, imagery or elevation, use a file made to be read in parts:
  PMTiles, FlatGeobuf, GeoParquet or a Cloud Optimized GeoTIFF. See
  [Large data](/guides/cloud-native-data/).
</Aside>

### CSV and spreadsheets

CSV files (including a Google Sheet published as CSV) aren't supported: a
layer whose `url` points at one shows "CSV files aren't supported" on the map.
Convert the table to GeoJSON first, for example by opening it in
[geojson.io](https://geojson.io) or QGIS and saving it as GeoJSON, then point
`url` at the `.geojson` file.

### CORS considerations

When loading from remote URLs, the server must allow cross-origin requests (CORS). If you see errors, the API may not support browser requests.

**Solutions:**

- Use APIs that support CORS (like USGS earthquake feed)
- Set up a proxy server
- Host the data yourself

## Caching

Control how fetched data is cached:

```yaml
source:
  type: geojson
  url: "https://earthquake.usgs.gov/earthquakes/feed/v1.0/summary/all_day.geojson"
  cache:
    enabled: true # Enable caching (default)
    ttl: 300000 # Cache for 5 minutes (milliseconds)
```

### Cache behavior

| Scenario                | Behavior                           |
| ----------------------- | ---------------------------------- |
| First request           | Fetch from network, store in cache |
| Subsequent (within TTL) | Return cached data immediately     |
| After TTL expires       | Fetch fresh data, update cache     |
| `enabled: false`        | Always fetch from network          |

<Aside>
  Caching is in memory only and resets when the page reloads.
</Aside>

## Loading states

You don't need to configure anything for loading feedback. While a map
starts, `<ml-map>` marks itself busy for screen readers (`aria-busy="true"`),
and if it hasn't drawn after about a second, a small "Loading map…" appears in
its middle until the basemap draws. A data file that fails to load shows a
notice on the map ("Part of this map couldn't load"), with the reason under
"Details for the site's author"; the rest of the map still draws. See
[Troubleshooting](/troubleshooting/#reading-what-the-map-tells-you).

A source's `loading:` key (`enabled`, `message`) draws no overlay of its own:
it still validates, with a warning that it has no effect (deprecated since
core 0.9.1), so you can remove it.

### Handling errors programmatically

With the [JavaScript API](/integrations/vanilla-js/), listen for each layer's
data as it loads:

```javascript
const renderer = new MapRenderer(container, block.config, block.layers);

renderer.on("layer:data-loading", ({ layerId }) => {
  console.log(`Loading ${layerId}...`);
});

renderer.on("layer:data-loaded", ({ layerId, featureCount }) => {
  console.log(`Loaded ${featureCount} features into ${layerId}`);
});

renderer.on("layer:data-error", ({ layerId, error }) => {
  console.error(`Failed to load ${layerId}:`, error.message);
});
```

`<ml-map>` fires the same moments as DOM events (`ml-map:layer-data-loaded`
and so on): see [`<ml-map>` events](/reference/elements/#ml-map-events).

## Clustering

For point datasets with many features, enable clustering:

```yaml
source:
  type: geojson
  url: "https://earthquake.usgs.gov/earthquakes/feed/v1.0/summary/all_month.geojson"
  cluster: true
  clusterRadius: 50 # Cluster points within 50px
  clusterMaxZoom: 14 # Stop clustering at zoom 14
```

Then style clustered and unclustered points separately:

```yaml
layers:
  # Clustered points
  - id: clusters
    type: circle
    source: earthquakes
    filter: ["has", "point_count"]
    paint:
      circle-radius:
        - step
        - ["get", "point_count"]
        - 20 # Default size
        - 100
        - 30 # Larger for 100+ points
        - 750
        - 40 # Even larger for 750+
      circle-color: "#3b82f6"

  # Cluster count labels
  - id: cluster-count
    type: symbol
    source: earthquakes
    filter: ["has", "point_count"]
    layout:
      text-field: "{point_count_abbreviated}"
      text-font: ["Noto Sans Regular"] # a font the basemap's glyphs include
      text-size: 12

  # Individual points
  - id: unclustered
    type: circle
    source: earthquakes
    filter: ["!", ["has", "point_count"]]
    paint:
      circle-radius: 6
      circle-color: "#ef4444"
```

## Named Sources

Define sources at the block level and reference them by name across multiple layers. This avoids duplicating source definitions and is the recommended approach when multiple layers share the same data.

```yaml
type: map
id: earthquake-map
config:
  center: [-120, 35]
  zoom: 6
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"

sources:
  quakes:
    type: geojson
    url: "https://earthquake.usgs.gov/earthquakes/feed/v1.0/summary/all_week.geojson"
    cluster: true
    clusterRadius: 50
    clusterMaxZoom: 14

layers:
  - id: clusters
    type: circle
    source: quakes
    filter: ["has", "point_count"]
    paint:
      circle-radius:
        - step
        - ["get", "point_count"]
        - 20
        - 100
        - 30
      circle-color: "#3b82f6"

  - id: cluster-count
    type: symbol
    source: quakes
    filter: ["has", "point_count"]
    layout:
      text-field: "{point_count_abbreviated}"
      text-font: ["Noto Sans Regular"] # a font the basemap's glyphs include
      text-size: 12

  - id: unclustered
    type: circle
    source: quakes
    filter: ["!", ["has", "point_count"]]
    paint:
      circle-radius: 6
      circle-color: "#ef4444"
```

Use a named source when several layers draw the same data (a fill and its
outline, clusters and their counts); a live named source is polled once for
all of them. Inline sources on single layers still work, and the two mix
freely. The rules (`$ref`, sharing data across the pages of a multi-page
document) are in [Named source definitions](/schema/sources/#named-source-definitions).
