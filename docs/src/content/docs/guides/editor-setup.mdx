maplibre-yaml publishes its contract as **JSON Schema**, so any editor backed by
the [YAML Language Server](https://github.com/redhat-developer/yaml-language-server)
(the engine behind the Red Hat **YAML** extension for VS Code, and available in
Neovim, JetBrains IDEs, and others) gives you autocomplete, hover documentation,
and inline validation — with **zero project install**.

<Aside type="note">
The JSON Schema is authoring assistance. `mlym validate` (Zod) remains the
source of truth: it enforces cross-field rules the JSON Schema cannot express.
See [Using maplibre-yaml with an AI agent](/guides/ai-agents/).
</Aside>

## Stable schema URLs

Each block type has a stable, versioned schema URL:

| Block            | Schema URL                                                        |
| ---------------- | ----------------------------------------------------------------- |
| `map`            | `https://docs.maplibre-yaml.org/schema/latest/map.schema.json`             |
| `scrollytelling` | `https://docs.maplibre-yaml.org/schema/latest/scrollytelling.schema.json`  |
| `root` (pages)   | `https://docs.maplibre-yaml.org/schema/latest/root.schema.json`            |
| any of the above | `https://docs.maplibre-yaml.org/schema/latest/any.schema.json`             |

`latest/` always tracks the newest release, and is what the files `mlym init`
creates use.

To pin a version, use the copy that ships inside the npm package, served by a
CDN. It exists for every release from 0.4 on and never moves:

```text
https://cdn.jsdelivr.net/npm/@maplibre-yaml/core@0.7/schemas/map.schema.json
```

Change `0.7` to the version you use (`@0.7` is the newest 0.7.x; `@0.7.1` is
exactly that release). The docs site also serves the current release under
`https://docs.maplibre-yaml.org/schema/v0.7/<block>.schema.json`; addresses
for older versions there (such as `/schema/v0.6/`) redirect to the CDN copy.

## Option 1: The modeline (recommended)

Add a `yaml-language-server` **modeline** as the first line of your file. It
travels with the file, so anyone who opens it gets validation — no shared
settings required. This is the first line of every config the CLI scaffolds:

```yaml
# yaml-language-server: $schema=https://docs.maplibre-yaml.org/schema/latest/map.schema.json
type: map
id: my-map
config:
  center: [-74.006, 40.7128]
  zoom: 12
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"
```

Use the schema that matches the file's block type:

## Option 2: VS Code `yaml.schemas` settings

If you would rather not put a modeline in every file, map globs to schemas in
your project's `.vscode/settings.json` (requires the Red Hat **YAML**
extension). This is the no-modeline alternative:

```json
{
  "yaml.schemas": {
    "https://docs.maplibre-yaml.org/schema/latest/map.schema.json": [
      "**/*.map.yaml",
      "configs/**/*.yaml"
    ],
    "https://docs.maplibre-yaml.org/schema/latest/scrollytelling.schema.json": [
      "**/*.story.yaml"
    ]
  }
}
```

<Aside type="tip">
Modelines win over `yaml.schemas` when both are present, so you can set a broad
glob default and override per-file with a modeline.
</Aside>

## Offline / air-gapped

The same schemas ship inside the `@maplibre-yaml/core` npm package, as
`node_modules/@maplibre-yaml/core/schemas/<block>.schema.json` once core is
installed. A modeline can point straight at that file, relative to the YAML
file:

```yaml no-validate
# yaml-language-server: $schema=./node_modules/@maplibre-yaml/core/schemas/map.schema.json
type: map
```

(`@maplibre-yaml/core/schemas/json/<block>.schema.json` is the same file as a
package export, for tools that resolve imports, not for a modeline.) Or write
a copy next to your files with the CLI:

```bash
npx maplibre-yaml schema map --out map.schema.json
```

Then reference the local file:

```yaml no-validate
# yaml-language-server: $schema=./map.schema.json
type: map
```

`mlym schema` reads the schema from the installed core package, so it always
matches the version `mlym validate` enforces.

## What you get

- **Autocomplete** for every field, layer type, control, and source type.
- **Hover documentation** sourced from the same `.describe()` annotations that
  drive the docs.
- **Inline validation** for structure, enums, and types as you type.

Unknown top-level keys are flagged; `x-*` keys are always allowed, for
extensions. Arbitrary MapLibre GL options inside `config:` and
extra source options stay permissive, matching the runtime.
