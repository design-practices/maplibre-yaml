This page covers a layer's `interactive:` block: what happens when the
pointer moves over a feature or clicks it. The map-level parts of
interactivity have one home, [Map configuration](/schema/map-config/):

## Map controls and legends

Navigation, scale, geolocate, fullscreen, globe, terrain and attribution
controls, their default positions and attribution options are in
[Map controls](/schema/map-config/#map-controls). The legend (placement,
title, your own items, the automatic legend and `legend: false`) is in
[Legend](/schema/map-config/#legend).

## Map Interaction Settings

Whether the reader can zoom, pan, rotate and tilt the map (`interactive`,
`scrollZoom`, `dragPan`, `dragRotate`, `keyboard`, `touchPitch` …), the
keyboard shortcuts, and URL hash syncing (`hash`) are `config:` keys:
see [Interaction settings](/schema/map-config/#interaction-settings).

Most snippets on this page are fragments. One that starts with
`interactive:` or `- id:` shows a single part of a map document and goes
inside a complete one. The document under
[Complete Examples](#complete-examples), and any snippet that starts with
`type: map`, run as printed.

## Layer Interactivity

Layers declare interactivity through an `interactive:` block. These are real
schema fields handled by the renderer — not something you wire up yourself.
For a walk-through with complete maps, see
[Popups, hover & controls](/guides/popups/).
This layer entry (it goes under a document's `layers:`) reads the live USGS
earthquake feed, whose features carry `title` and `place` properties:

```yaml
- id: quakes
  type: circle
  source:
    type: geojson
    url: "https://earthquake.usgs.gov/earthquakes/feed/v1.0/summary/all_week.geojson"
    generateId: true
  paint:
    circle-radius: 8
    circle-color: "#3b82f6"
  interactive:
    hover:
      cursor: pointer
      highlight: true
    click:
      popup:
        - h3: [{ property: title }]
        - p: [{ property: place }]
      flyTo:
        zoom: 8
        duration: 600
```

### Hover

| Property | Type | Description |
|----------|------|-------------|
| `cursor` | string | CSS cursor while the pointer is over a feature |
| `highlight` | boolean | Recolour the hovered feature |
| `popup` | popup content | Same content format as `click.popup` ([Popups](/schema/layers/#popups)). Chromeless preview popup while hovering (once per feature entered, dismissed on leave). A pinned `click.popup` suppresses hover previews until dismissed; touch devices tap into `click.popup` instead |
| `emit` | object | Dispatch a named host event once per feature entered (see [Emit](#emit)) |

`highlight: true` wraps the layer's primary colour in a `feature-state` expression
for you, so no paint authoring is required. Two things follow from how
feature-state works:

- **Features need ids.** Set `generateId: true` on the source, or `promoteId` to
  use a property as the id. If neither is set, `highlight` enables `generateId`
  on a GeoJSON source for you, whether its data is inline or loaded from `url:`.
- **A [classified](/guides/thematic-maps/) layer** highlights like any other:
  the colour `classify:` generates is wrapped the same way (also after
  computed breaks land), as long as `classify:` drives that primary colour.
- **Already using your own expression for that colour?** Then `highlight`
  leaves your paint alone and warns, rather than overwriting your data-driven
  styling. Reference `["feature-state", "hover"]` yourself, as in [Custom
  highlight styling](#custom-highlight-styling) below.

Because feature-state is per *source*, two layers sharing one source share
highlight state.

### Click

| Property | Type | Description |
|----------|------|-------------|
| `popup` | array | Popup content: tags, items, links, number formats (see [Popups](/schema/layers/#popups)) |
| `flyTo` | object | Animate the camera to the clicked feature |
| `zoomToFeature` | object | Fit the camera to the clicked feature's own bounds: `padding`, `maxZoom`, `duration` (all optional) |
| `emit` | object | Dispatch a named host event with a payload projected from the feature |

`flyTo` accepts `center`, `zoom`, and `duration`. `center` defaults to the
clicked point, and `zoom`/`duration` fall through to MapLibre's defaults when
omitted:

```yaml
interactive:
  click:
    flyTo:
      zoom: 14        # optional
      duration: 600   # optional, milliseconds
```

When a layer configures both, the popup opens first and then travels with the
camera.

### Emit

`click.emit` dispatches a **named host event** carrying a declarative payload
projected from the clicked feature. Unlike `popup` and `flyTo`, which act on the
map itself, `emit` hands data to code the host wrote — so it is gated on trust
(see the caveat below).

| Property | Type | Description |
|----------|------|-------------|
| `event` | string | The event name, resolved against the host's handler map |
| `payload` | object | Named keys, each a declarative projection from the feature |

Each `payload` key is projected independently:

- `str` — a static literal value.
- `property` — read a feature property, with an optional `else` fallback.

```yaml
version: 1
type: map
id: quake-select
config:
  center: [-120, 37]
  zoom: 4
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"
layers:
  - id: quakes
    type: circle
    source:
      type: geojson
      url: "https://earthquake.usgs.gov/earthquakes/feed/v1.0/summary/all_week.geojson"
      generateId: true
    paint:
      circle-radius: 6
      circle-color: "#3b82f6"
    interactive:
      click:
        emit:
          event: select
          payload:
            id:
              property: code
            label:
              property: place
              else: "Untitled"
            kind:
              str: earthquake
```

A missing or null property yields a **defined-absent** value: the key stays in
the payload carrying its `else` value, or `null` when no `else` is declared. It
is never omitted and never throws, so a handler sees a stable payload shape
across features that carry different properties. Payload fields are data only —
`str`, `property`, and `else` — with no formatting, markup, or executable
fields; unlike `popup`, an unrecognised field is stripped as an unknown key
rather than passed through.

**`emit` needs a trusted host — it is inert under `<ml-map>` today.** It is a
*host-event* interaction: it fires only when the map is wired up with
`attachInteractions(map, projection, options)` and **both** of these hold:

- `options.policy` declares `trust: "trusted"`. The host hook is default-deny;
  an untrusted (or absent) policy shuts the gate and the interaction does
  nothing.
- `options.hostHandlers` has a **matching entry** for the event name. Resolution
  is closed-world — an unregistered name is denied, never dispatched.

Both are required: a trusted policy with no handler does nothing, and a
registered handler under an untrusted policy does nothing.

The `projection` you pass in must carry `emit` in the first place: it fires only
when `projectInteractions(model, policy)` *also* ran under a trusted policy. An
untrusted (or omitted) projection policy drops the `emit` block at projection
time — fail-closed — so `attachInteractions` never sees it, no matter how it is
configured. The [Export to style.json guide](/guides/export/) shows the
end-to-end wiring (`projectInteractions(model, { trust: "trusted" })` →
`attachInteractions`).

Because of this, `emit` is a silent no-op under the `<ml-map>` web component,
which defaults to an untrusted policy and registers no host handlers
(fail-closed). To react to clicks on an `<ml-map>` page, listen for its
`ml-map:layer-click` event instead (below).

### Deprecated: `action`

`click.action`, `mouseenter.action`, and `mouseleave.action` are accepted by the
schema but have never been dispatched at runtime. They emit a deprecation
warning and **will be removed in v2**. Listen for the corresponding event
instead:

```yaml
# Deprecated — never fired
interactive:
  click:
    action: openDetails
```

```js
// Use the event instead
map.addEventListener("ml-map:layer-click", (e) => {
  const { layerId, feature } = e.detail;
});
```

Deprecation warnings are exempt from `mlym validate --strict` by default, so
upgrading will not fail your build. Opt in with
`mlym validate --strict-deprecations`.

### Custom highlight styling

To control the highlight colour yourself, author the paint expression directly
and leave `highlight` off:

```yaml
- id: interactive-fill
  type: fill
  source:
    type: geojson
    url: "https://maplibre.org/maplibre-gl-js/docs/assets/us_states.geojson"
    generateId: true
  paint:
    fill-color:
      - case
      - ["boolean", ["feature-state", "hover"], false]
      - "#3b82f6"  # Blue when hovered
      - "#e5e7eb"  # Gray otherwise
    fill-opacity:
      - case
      - ["boolean", ["feature-state", "hover"], false]
      - 0.8
      - 0.5
  interactive:
    hover:
      cursor: pointer
```

## Cursor Styling

MapLibre shows its own cursors: the default arrow over the map and a grab
hand while dragging. A layer's features get a different cursor only when the
layer asks for one with `interactive.hover.cursor` (usually `pointer`); a
`click:` block alone does not change the cursor.

A complete document: save it as a `.yaml` file and load it with
`<ml-map src="…">`. Complete maps that limit or turn off interaction are

### Fully Interactive Map

```yaml
type: map
id: interactive-map
config:
  center: [-98, 39]
  zoom: 3
  hash: true
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"
layers:
  - id: states
    type: fill
    source:
      type: geojson
      url: "https://maplibre.org/maplibre-gl-js/docs/assets/us_states.geojson"
      generateId: true
    paint:
      fill-color:
        - case
        - ["boolean", ["feature-state", "hover"], false]
        - "#3b82f6"
        - "#cbd5e1"
      fill-opacity: 0.7
    interactive:
      hover:
        cursor: pointer
      click:
        popup:
          - h3:
              - property: STATE_NAME
controls:
  navigation: true
  geolocate: true
  scale: true
  fullscreen: true
legend:
  title: "US states"
  position: top-right
  items:
    - color: "#cbd5e1"
      label: "State"
      shape: square
    - color: "#3b82f6"
      label: "Hovered"
      shape: square
```

## Best Practices

### Performance

1. **Limit interactive features**: Too many interactive features can impact performance
2. **Use feature-state**: Prefer feature-state for hover/select styling over re-rendering
3. **Throttle updates**: Limit update frequency for real-time data sources

### User Experience

1. **Provide visual feedback**: Use hover states to indicate clickable features
2. **Clear controls**: Position controls logically and consistently
3. **Mobile-first**: Disable complex gestures like pitch on mobile
4. **Accessibility**: Include keyboard navigation and clear visual indicators
