The maplibre-yaml schema is built on [Zod](https://zod.dev), providing type-safe configuration with automatic validation and TypeScript type inference.

## Three kinds of document

| Document | Starts with | Shown by |
|---|---|---|
| A map | `type: map` | `<ml-map src="…">`, the Astro `<Map>` and `<FullPageMap>` components |
| A story | `type: scrollytelling` | `<ml-scrollytelling src="…">`, the Astro `<Scrollytelling>` component |
| A multi-page document | `pages:` (no `type:`) | Your own site code, which renders each block (see [root](/schema/root/) and [pages & blocks](/schema/pages/)) |

A map or story can also carry a `title:` and `description:`, which name and
describe it for screen readers ([Accessibility & languages](/guides/accessibility-languages/)).
Every page outside *Advanced* uses format v1, the default;
[format v2](/guides/format-v2/) is an opt-in alternative layout of the same
map. Check any of these files with `npx maplibre-yaml validate file.yaml`
([The CLI](/cli/getting-started/)).

## Architecture

The schema follows a hierarchical structure:

```
RootSchema
├── GlobalConfig (optional)
├── Layers (optional, named definitions)
├── Sources (optional, named definitions)
└── Pages (array, required)
    └── PageSchema
        ├── path
        ├── title
        └── blocks (array)
            ├── ContentBlock
            ├── MapBlock
            ├── MapFullPageBlock
            ├── ScrollytellingBlock
            └── MixedBlock
```

## Core Concepts

### Type Safety

All configuration is validated at parse time:

```typescript
import { YAMLParser } from '@maplibre-yaml/core';

const result = YAMLParser.safeParse(yaml);
if (result.success) {
  // result.data is fully typed
  console.log(result.data.pages[0].title);
} else {
  // result.errors contains detailed validation errors
  console.error(result.errors);
}
```

### Schema Composition

Schemas are composed from smaller, reusable schemas:

- **Base schemas**: LngLat, ZoomLevel, Color, Expression
- **Source schemas**: GeoJSON, Vector, Raster, Raster DEM, Image, Video (PMTiles, FlatGeobuf, GeoParquet and COG files use these types with a `url:` to the file; see [Sources](/schema/sources/#cloud-native-files-pmtiles-flatgeobuf-geoparquet-cog))
- **Layer schemas**: Circle, Line, Fill, Symbol, Heatmap, etc.
- **Block schemas**: Content, Map, Map (full page), Scrollytelling, Mixed
- **Page schemas**: Page, Root, GlobalConfig

### Default Values

Many properties have sensible defaults:

```yaml
config:
  center: [0, 0]
  zoom: 2
  # pitch defaults to 0
  # bearing defaults to 0
  # interactive defaults to true
```

### Optional vs Required

Required properties will cause validation errors if missing:

```yaml
# ✅ Valid - all required fields present
type: map
id: my-map
config:
  center: [0, 0]
  zoom: 2
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"
```

```yaml no-validate
# ❌ Invalid - missing required 'center' and 'zoom'
type: map
id: my-map
config:
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"
```

`mapStyle` is not a required key in the schema, because the Astro map builders can fill it in from a global `defaultMapStyle`. A map without one gets a validation warning (in `mlym validate` too), and the standalone `<ml-map>` element shows an error card instead of the map.

## Validation

### Error Messages

The schema provides detailed, human-readable error messages:

```typescript
const result = YAMLParser.safeParse(invalidYaml);
if (!result.success) {
  result.errors.forEach(err => {
    console.log(`${err.path}: ${err.message}`);
  });
}
```

Example errors:

```
pages.0.blocks.0.config.zoom: Expected number, got string
pages.0.blocks.1: Unknown layer type "invalid". Valid types: circle, line, fill, symbol, raster, fill-extrusion, heatmap, hillshade, color-relief, background.
```

### Custom Validation

Some schemas include custom validation rules:

```typescript
// Zoom level must be 0-24
zoom: z.number().min(0).max(24)

// LngLat must be [lon, lat] where lon is -180 to 180, lat is -90 to 90
center: z.tuple([
  z.number().min(-180).max(180),
  z.number().min(-90).max(90)
])
```

## Reference Resolution

The schema supports `$ref` pointers to reuse layers and sources:

```yaml
# Define once
layers:
  myLayer:
    id: shared-layer
    type: circle
    source:
      type: geojson
      url: "https://earthquake.usgs.gov/earthquakes/feed/v1.0/summary/all_week.geojson"

# Reference multiple times
pages:
  - path: "/"
    title: "Home"
    blocks:
      - type: map
        id: map1
        config:
          center: [-100, 40]
          zoom: 3
          mapStyle: "https://tiles.openfreemap.org/styles/liberty"
        layers:
          - $ref: "#/layers/myLayer"
      - type: map
        id: map2
        config:
          center: [140, 36]
          zoom: 4
          mapStyle: "https://tiles.openfreemap.org/styles/liberty"
        layers:
          - $ref: "#/layers/myLayer"
```

The rules (named layers, root-level sources, and the object form `$ref`
must take) are in [Reference resolution](/schema/root/#reference-resolution);
within one map, prefer [named sources](/schema/sources/#named-source-definitions).

## Type Inference

Use Zod's type inference for TypeScript projects:

```typescript
import { RootSchema, type z } from '@maplibre-yaml/core/schemas';

type RootConfig = z.infer<typeof RootSchema>;
type PageConfig = RootConfig['pages'][number];
type MapBlock = Extract<PageConfig['blocks'][number], { type: 'map' }>;
```
