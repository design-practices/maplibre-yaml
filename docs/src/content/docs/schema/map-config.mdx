Map configuration defines the initial view, interaction settings, controls, and legends for map blocks. All configuration follows the [MapLibre GL JS API](https://maplibre.org/maplibre-gl-js/docs/API/).

## Map Config Structure

```yaml
- type: map
  id: my-map
  title: "..."         # The map's name for screen readers (optional)
  description: "..."   # What it shows, in a sentence or two (optional)
  config:              # Map configuration
    center: [lng, lat]
    zoom: 12
    mapStyle: "..."
    pitch: 0
    bearing: 0
    # ... additional options
  state: {...}         # Runtime-tunable values (optional)
  parameters: {...}    # Control metadata for state keys → params panel (optional)
  markers: [...]       # Standalone DOM pins (optional)
  images: {...}        # Named images for icons and patterns (optional)
  light: {...}         # Style-spec light for fill-extrusion shading (optional)
  layers: [...]        # Map layers
  controls: {...}      # Map controls (optional)
  legend: {...}        # Legend (optional)
```

## Required Properties

| Property | Type | Description |
|----------|------|-------------|
| `center` | [number, number] | Initial map center [longitude, latitude] |
| `zoom` | number | Initial zoom level (0-24) |
| `mapStyle` | string \| object | MapLibre style URL or style object |

### Example

```yaml
config:
  center: [-74.006, 40.7128]
  zoom: 12
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"
```

### What goes inside `config:`

`config:` holds the camera and map options on this page and any other
[MapLibre map option](https://maplibre.org/maplibre-gl-js/docs/API/type-aliases/MapOptions/)
(`cooperativeGestures`, `zoomSnap`, …), which are passed to MapLibre as they
are. Everything else is a document-root key, a sibling of `config:`:
`layers`, `sources`, `markers`, `legend`, `controls`, `state`, `popups`,
`images`, `terrain`, and (in a story) `theme` and `chapters`. Validation warns
when one of those is nested inside `config:`, where it does nothing
(`"markers" belongs at the top level, next to config:, not inside it`), and
when `config:` has a key that is neither (`Unknown key "fooBar" in config`).

Coordinates are always `[longitude, latitude]`, longitude first (map sites
often show latitude first). When a `center:` (or a story chapter's `center:`)
looks swapped -- written the other way round, it would land among the
document's own data, markers or other centers -- validation and the map's
notice say so: `center is [40.75, -73.98] — coordinates are [longitude,
latitude]; did you mean [-73.98, 40.75]?`. A latitude beyond about ±85, which
a web map can't show, warns too.

## Runtime state and parameters

`state:` declares runtime-tunable values a map can change after it loads, read
from expressions via `global-state`. It is a document-root key — a sibling of
`config:`, not nested inside it — and it uses the MapLibre style spec's own
shape, `{ key: { default: value } }`:

```yaml
type: map
id: massing
state:
  scenario:
    default: built
parameters:
  scenario:
    label: Massing scenario
    type: enum
    values: [built, flat]
config:
  center: [-73.985, 40.748]
  zoom: 15.5
  pitch: 55
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"
sources:
  omt:
    type: vector
    url: "https://tiles.openfreemap.org/planet"
layers:
  - id: buildings
    type: fill-extrusion
    source: omt
    source-layer: building
    paint:
      fill-extrusion-color: "#9ca3af"
      fill-extrusion-height:
        - case
        - ["==", ["global-state", "scenario"], "built"]
        - ["coalesce", ["get", "render_height"], 10]
        - 3
```

`parameters:` carries the presentation metadata a control UI needs to render a
picker for a state key — the library owns the parameter's shape, the host owns
how it looks. It holds no `default`; the value lives in `state:`.

```yaml
parameters:
  scenario:
    label: Massing scenario
    type: enum
    values: [built, flat]
```

Declaring `parameters:` renders the built-in **params panel** (top-right, in
the same corner system as the legend): each entry becomes a control writing
its state key via `setGlobalStateProperty`, seeded from the key's `state:`
default. Each entry:

| Property | Type | Description |
|----------|------|-------------|
| `label` | string | Control caption (defaults to the state key) |
| `type` | string | `range`, `select` (alias `enum`), or `toggle`; unrecognized types render a labeled read-only row. Omitted: inferred — `values` present → select, boolean default → toggle |
| `values` | array | The options, for `select` — authored value types survive (a numeric enum writes numbers) |
| `min` / `max` | number | Bounds, for `range` (both required — a range without them renders read-only) |
| `step` | number | Increment, for `range` |

The panel also lists a **visibility checkbox for every layer with an
authored `label:`** (set `toggleable: false` to opt a labeled layer out).
The label is the opt-in on purpose: `toggleable` defaults to `true` on
every layer, so it cannot signal intent by itself. Layer toggles write
plain layout visibility and work on every supported runtime; parameter
controls need maplibre-gl ≥ 5.6 and degrade to one notice below it. Panel
writes are observable as `ml-map:parameter-change` and
`ml-map:layer-visibility` events.

:::note
`state` and `global-state` require **maplibre-gl 5.6.0 or later**, and are
supported on maplibre-gl JS only. When a document is compiled with `mlym emit`
for an older runtime — or for cross-renderer portability — the emitter inlines
each state key's default and drops the `state` block.
:::

## Markers

`markers:` places standalone DOM pins (`maplibregl.Marker`) — a document-root
key, a sibling of `config:`. Each entry:

| Property | Type | Description |
|----------|------|-------------|
| `at` | [number, number] | Marker position [longitude, latitude] (required) |
| `color` | color | Pin color (default pin only; ignored when `icon` is set) |
| `size` | number | Scale multiplier over MapLibre's default pin (1 = default) |
| `icon` | string | Image URL replacing the default pin |
| `popup` | popup content | Popup opened by clicking the marker — same structured content as [layer popups](/schema/interactivity/) |

```yaml
type: map
id: pins
config:
  center: [-73.98, 40.75]
  zoom: 12
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"
markers:
  - at: [-73.985, 40.748]
    color: "#e63946"
    popup:
      - h3:
          - str: Empire State Building
```

Markers **export with a fallback** (class `exports-with-fallback`): `mlym emit
--with-fallbacks` lowers them to a symbol layer with generated pin sprites
(the pins render; dragging and popup content do not compile), and `--strict`
refuses marker documents. `icon:` URLs are fetched into the document sprite
at compile time, so exported icon markers keep their images. See the [export
classes reference](/guides/export-classes/).

## Popups

`popups:` opens standalone popups at coordinates: a popup with no layer
under it and no marker above it (MapLibre's `new Popup().setLngLat(...)
.addTo(map)`). It is a document-root key, a sibling of `config:`. Each entry:

| Property | Type | Description |
|----------|------|-------------|
| `at` | [number, number] | Popup anchor [longitude, latitude] (required) |
| `content` | popup content | Same structured content as [layer popups](/schema/interactivity/) (required) |
| `closeButton` | boolean | Show the close button (MapLibre default: `true`) |
| `closeOnClick` | boolean | Close when the map is clicked (MapLibre default: `true`) |
| `maxWidth` | string | CSS max-width, e.g. `"300px"` (MapLibre default: `240px`) |

```yaml
type: map
id: hello
config:
  center: [-96, 37.8]
  zoom: 3
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"
popups:
  - at: [-96, 37.8]
    closeOnClick: false
    content:
      - h1:
          - str: Hello World!
```

Popups are open from load. Content runs through the same trust gate as every
other popup: tags are allowlisted, `str:` values are escaped, and there is no
feature, so `property:` lookups resolve empty. A marker with its pin hidden
can't stand in for this. A marker's popup opens on a click on the pin, so a
pinless marker's popup could never open.

Popups don't export (class `no-export`). `mlym emit` reports them as a
contract warning, and the emitted style has no popups.

## Images

`images:` declares named images for symbol layers and patterns — a
document-root key, a sibling of `config:`. Each entry is a URL string or an
options object:

| Property | Type | Description |
|----------|------|-------------|
| `url` | string | Image URL (required; a bare string is shorthand for `{ url }`) |
| `sdf` | boolean | Treat as a signed-distance-field icon (tintable via `icon-color`) |
| `pixelRatio` | number | Source density — `2` means the file is @2x its CSS size |

```yaml
type: map
id: iconic
config:
  center: [-73.98, 40.75]
  zoom: 12
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"
images:
  logo: "https://maplibre.org/maplibre-gl-js/docs/assets/osgeo-logo.png"
  pin:
    url: "https://maplibre.org/maplibre-gl-js/docs/assets/custom_marker.png"
    sdf: true
sources:
  pts:
    type: geojson
    data:
      type: FeatureCollection
      features:
        - type: Feature
          geometry: { type: Point, coordinates: [-74.0, 40.76] }
          properties: { kind: logo }
        - type: Feature
          geometry: { type: Point, coordinates: [-73.96, 40.74] }
          properties: { kind: pin }
layers:
  - id: logos
    type: symbol
    source: pts
    filter: ["==", ["get", "kind"], "logo"]
    layout:
      icon-image: logo
      icon-size: 1.5
      icon-allow-overlap: true
  - id: pins
    type: symbol
    source: pts
    filter: ["==", ["get", "kind"], "pin"]
    layout:
      icon-image: pin
      icon-allow-overlap: true
    paint:
      icon-color: "#e63946"   # sdf: true makes the image tintable
```

Live, every image loads **before** layers are added, so references resolve
on first render. Images load with `crossOrigin="anonymous"` (a WebGL
texture must be untainted), so the host **must allow cross-origin access**
on every response in the chain, redirects included — a host that serves
plain `<img>` tags fine can still fail here. A failed image warns once and
the document keeps rendering. On export the construct fully compiles (class `exports`):
`mlym emit` fetches each URL into the document sprite and rewrites literal
references (`icon-image`, `fill-pattern`, `line-pattern`,
`background-pattern`, `fill-extrusion-pattern`) to `mlym:<name>` —
`--strict` accepts image documents. Dynamic references
(`["image", ["get", "icon"]]`) resolve live but cannot be rewritten at
compile time; emit reports them, and runtime values naming declared images
must spell `mlym:<name>` themselves. A `*-pattern` (or `icon-image`) may be
an expression that *selects* among declared names —
`fill-pattern: [match, [get, class], sand, earth, landuse]` — and every
literal output is rewritten, with no warning. Relative URLs render live but cannot
be fetched at compile time — emit reports them as lossy, so `--strict`
refuses them.

:::caution
`mlym emit` performs a network request for **every** `images:` entry and
marker `icon:` URL in the document (bounded: 30s timeout, 20MB and
1024px-per-image ceilings). Only emit documents whose URLs you trust — the
fetched bytes are embedded verbatim into the sprite files you publish.
:::

## Terrain, sky & projection

Three document-root keys, siblings of `config:`, author the map-level 3D
scene. Each one is the style spec's own root property, in the spec's own
shape, so what you write is exactly what an exported `style.json` carries. In
a format-v2 document they live under `style:` instead
(`style.terrain`, `style.sky`, `style.projection`).

```yaml
type: map
id: alps
config:
  center: [11.39, 47.27]
  zoom: 12
  pitch: 70
  maxPitch: 85
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"
sources:
  terrainSource:
    type: raster-dem
    url: "https://tiles.mapterhorn.com/tilejson.json"
    encoding: terrarium
terrain:
  source: terrainSource
  exaggeration: 1.5
sky:
  sky-color: "#199EF3"
  horizon-color: "#ffffff"
  fog-color: "#ffffff"
  fog-ground-blend: 0.1
  atmosphere-blend: ["interpolate", ["linear"], ["zoom"], 0, 1, 5, 1, 7, 0]
projection:
  type: globe
controls:
  navigation: true
  globe: true
  terrain: true
```

### `terrain:`

| Property | Type | Description |
|----------|------|-------------|
| `source` | string | Name of a `raster-dem` source: one in `sources:`, or one the basemap supplies (required) |
| `exaggeration` | number ≥ 0 | Vertical exaggeration (spec default `1`) |

Declare the DEM as a **named** source. Give a `hillshade` layer its own DEM
source rather than sharing the terrain's; one source serving both renders at
reduced quality. A `source` that names nothing, or a non-DEM source, warns
once and the map renders flat.

### `sky:`

| Property | Type | Description |
|----------|------|-------------|
| `sky-color` | color or expression | The sky above the horizon |
| `horizon-color` | color or expression | The band where sky meets fog |
| `fog-color` | color or expression | Fog over distant 3D terrain |
| `sky-horizon-blend` | 0–1 or expression | How far the horizon color blends up into the sky |
| `horizon-fog-blend` | 0–1 or expression | How far the horizon color blends down into the fog |
| `fog-ground-blend` | 0–1 or expression | Where fog starts: `0` at the camera, `1` at the horizon |
| `atmosphere-blend` | 0–1 or expression | Globe atmosphere opacity; draws under globe projection only |

`sky: {}` turns on MapLibre's default sky. The sky is only visible when a
pitched camera can see the horizon, and fog only affects 3D terrain.

### `projection:`

| Property | Type | Description |
|----------|------|-------------|
| `type` | `mercator` \| `globe` | `mercator` is the default |

### Runtime requirements

The live map applies each key with its MapLibre setter. Each setter is
feature-detected: on a runtime that lacks one, the document logs one console
warning naming the minimum version and keeps rendering without that effect.
It never throws.

| Key | Needs maplibre-gl | On an older runtime |
|-----|-------------------|---------------------|
| `terrain:` | 2.2.0 (`setTerrain`) | Every supported peer version has it |
| `sky:` | 4.5.0 (`setSky`) | Renders without sky or fog |
| `sky.atmosphere-blend` | 5.0.0 (draws under globe only) | No atmosphere (there is no globe) |
| `projection: globe` | 5.0.0 (`setProjection`) | Renders in mercator |
| `controls.globe` | 5.0.0 (`GlobeControl`) | The control is omitted |

The minimums come from the maplibre-gl changelog: 3D terrain arrived in
2.2.0, the spec `sky` in 4.5.0, and globe projection with its atmosphere in
5.0.0.

### On export

All three keys are class `exports`. `mlym emit` copies them verbatim to the
style.json root. When the basemap also defines one, the document's value
replaces the basemap's wholesale, as it does live, and emit notes the
override. A `terrain.source` that resolves to no `raster-dem` source, after
the basemap merge, is dropped with a lossy warning rather than shipped as a
style MapLibre would reject. With `--target` below a key's floor, emit keeps
the key (it still validates on 4.x) and reports the visual difference as
lossy, so `--strict --target 4.7.1` refuses a globe document. See the
[export classes reference](/guides/export-classes/).
## Light

`light:` is the style-spec root [light](https://maplibre.org/maplibre-style-spec/light/)
— the single light that shades `fill-extrusion` faces. A document-root key,
a sibling of `config:` (in format v2 it lives in the `style:` half). Every
property is optional and accepts a zoom expression:

| Property | Type | Default | Description |
|----------|------|---------|-------------|
| `anchor` | `map` \| `viewport` | `viewport` | `map` fixes the light to the map, so shading stays put as the map turns; `viewport` fixes it to the screen |
| `position` | `[radial, azimuthal°, polar°]` | `[1.15, 210, 30]` | Distance from the base of an object, direction clockwise from north (at `anchor: map`), and angle from overhead |
| `color` | color | `white` | Light color |
| `intensity` | number 0–1 | `0.5` | Higher is more extreme contrast between faces |

```yaml
type: map
id: lit
config:
  center: [-74.0118, 40.7075]
  zoom: 15.9
  pitch: 60
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"
light:
  anchor: map
  position: [1.15, 239, 30]
  intensity: 0.5
sources:
  omt:
    type: vector
    url: "https://tiles.openfreemap.org/planet"
layers:
  - id: buildings
    type: fill-extrusion
    source: omt
    source-layer: building
    paint:
      fill-extrusion-color: "#e5e7eb"
      fill-extrusion-height: ["coalesce", ["get", "render_height"], 10]
```

The object is closed: an unknown key is a validation error, not a silently
ignored setting. Live, the renderer applies it with `map.setLight` once the
style loads. On export it compiles through verbatim to the style's `light`
(class `exports`), replacing any light the basemap carried. The
[crosshatch classic](/examples/gallery/crosshatch/) uses it to shade its
hatched buildings.

## View Options

Control the camera position and orientation.

| Property | Type | Default | Range | Description |
|----------|------|---------|-------|-------------|
| `pitch` | number | `0` | 0-85 | Camera tilt angle in degrees |
| `bearing` | number | `0` | -180 to 180 | Camera rotation in degrees |
| `bounds` | array | - | - | Fit map to geographic bounds: `[west, south, east, north]` or `[[west, south], [east, north]]` |
| `fitTo` | object \| string | - | - | Fit the initial camera to a GeoJSON source's data (see below); a source name is shorthand for `{ source: name }` |

### Examples

#### 3D Perspective View

```yaml
config:
  center: [-122.4194, 37.7749]
  zoom: 15
  pitch: 60
  bearing: 30
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"
```

#### Fit to Bounds

```yaml
config:
  center: [-74.006, 40.7128]  # Fallback center
  zoom: 12                     # Fallback zoom
  bounds: [-74.3, 40.5, -73.7, 40.9]  # [west, south, east, north]
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"
```

`bounds` takes either of MapLibre's two forms, so a value copied from
MapLibre's docs works as written:

```yaml
bounds: [-74.3, 40.5, -73.7, 40.9]        # four numbers: west, south, east, north
bounds: [[-74.3, 40.5], [-73.7, 40.9]]    # two corners: [west, south], [east, north]
```

Both are **longitude first**, like `center`. A value in neither form gets an
error that spells out the order. When the numbers only make sense with
latitude and longitude swapped (the order many map sites show), the message
gives the swapped value to copy: `bounds [34, -118.5, 34.1, -118.2] has a
latitude outside -90 to 90 … Did you mean [-118.5, 34, -118.2, 34.1]?`. A
swap that is still in range (`[40.6, -74.0, 40.8, -73.9]` for New York) is
caught by comparing the box with the map's own places (`center`, inline
data, markers) and shown as a warning with the same did-you-mean.
Longitudes past ±180 are allowed, for bounds that cross the antimeridian
(`[100, -50, 290, 62]` frames the Pacific). `maxBounds`, format v2's
`runtime.map.bounds` / `runtime.map.maxBounds`, and a story chapter's
`fitBounds` action take both forms too.

#### Fit to a Source's Data

`fitTo` is the data-driven sibling of `bounds`. Instead of literal
coordinates it names a GeoJSON entry in `sources:`, and the camera frames
whatever that source holds.

| Property | Type | Description |
|----------|------|-------------|
| `source` | string | Name of a GeoJSON entry in `sources:` (required) |
| `padding` | number | Padding in pixels around the fitted bounds |
| `maxZoom` | number | Upper zoom limit for the fit. Without it, a single point zooms all the way in. |

```yaml
type: map
id: alpine-countries
config:
  center: [0, 20]   # Before the data arrives, and the fallback
  zoom: 2
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"
  fitTo:
    source: countries
    padding: 20
sources:
  countries:
    type: geojson
    url: "https://docs.maplibre-yaml.org/gallery-assets/alpine-countries.geojson"
layers:
  - id: borders
    type: line
    source: countries
    paint:
      line-color: "#e63946"
      line-width: 1.5
```

- **Inline `data:`**: the map is constructed already framed, with no camera jump.
- **`url:`**: also framed from the first frame, with no jump. `<ml-map>`
  starts fetching the file as soon as it reads the document, while the rest
  of the page starts up, and builds the map with the data's bounds. The file
  is requested once: the map's source uses the same download (and the
  source's `cache:` settings). If the file takes longer than 1.5 seconds,
  the map is built at `center`/`zoom` anyway and frames the data when it
  lands, so a slow file never holds up the basemap for long
  (`MLMap.fitToWaitMs` changes the wait; `0` turns it off). Story maps and
  the Astro components (`src` or `config`) get the same, and `base` applies
  to the URL as everywhere else. Refreshes don't re-fit, because the user
  owns the camera after load. An `ml-map:camera-fit` event fires when the
  fit applies.
- **vector / raster / raster-dem**: not supported. Tiled sources have no
  client-side extent. The renderer warns once and keeps `center`/`zoom`.
- `fitTo: countries` (just the source name) is shorthand for
  `fitTo: { source: countries }`.
- `fitTo` wins over `bounds` when both are set. In format v2 it lives at
  `runtime.fitTo`.

On export `fitTo` **exports with a fallback** (class `exports-with-fallback`). `mlym emit --with-fallbacks`
computes the fitted `center`/`zoom` from an inline source for a 1024×768
reference viewport. That's lossy, because a live map fits its own container.
For a fetched source the authored camera stands in, also reported as lossy.
`--strict` refuses `fitTo` documents.

## Constraints

Limit user interaction to specific zoom levels, pitch angles, or geographic areas.

| Property | Type | Description |
|----------|------|-------------|
| `minZoom` | number | Minimum zoom level (0-24) |
| `maxZoom` | number | Maximum zoom level (0-24) |
| `minPitch` | number | Minimum pitch angle (0-85) |
| `maxPitch` | number | Maximum pitch angle (0-85) |
| `maxBounds` | array | Maximum geographic bounds: `[west, south, east, north]` or `[[west, south], [east, north]]` |

### Example

```yaml
config:
  center: [-74.006, 40.7128]
  zoom: 12
  minZoom: 8
  maxZoom: 18
  maxBounds: [-74.3, 40.5, -73.7, 40.9]
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"
```

## Interaction Settings

Control user interaction capabilities.

| Property | Type | Default | Description |
|----------|------|---------|-------------|
| `interactive` | boolean | `true` | Enable all map interactions |
| `scrollZoom` | boolean | `true` | Enable scroll to zoom |
| `boxZoom` | boolean | `true` | Enable shift+drag box zoom |
| `dragRotate` | boolean | `true` | Enable right-drag to rotate |
| `dragPan` | boolean | `true` | Enable drag to pan |
| `keyboard` | boolean | `true` | Enable keyboard shortcuts |
| `doubleClickZoom` | boolean | `true` | Enable double-click zoom |
| `touchZoomRotate` | boolean | `true` | Enable touch zoom/rotate |
| `touchPitch` | boolean | `true` | Enable two-finger touch pitch |

### Non-Interactive Map

Create a static map for presentation:

```yaml
config:
  center: [-74.006, 40.7128]
  zoom: 12
  interactive: false
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"
```

### Custom Interaction

Disable specific interactions:

```yaml
config:
  center: [-74.006, 40.7128]
  zoom: 12
  dragRotate: false      # Disable rotation
  touchPitch: false      # Disable pitch on mobile
  doubleClickZoom: false # Disable double-click zoom
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"
```

## Display Options

Control map display and behavior.

| Property | Type | Default | Description |
|----------|------|---------|-------------|
| `hash` | boolean | `false` | Sync map state with URL hash |
| `attributionControl` | boolean | `true` | Show attribution control |
| `logoPosition` | string | `"bottom-left"` | MapLibre logo position |
| `fadeDuration` | number | `300` | Fade duration in milliseconds |
| `crossSourceCollisions` | boolean | `true` | Check for cross-source symbol collisions |

### Example

```yaml
config:
  center: [-74.006, 40.7128]
  zoom: 12
  hash: true                      # Enable URL hash syncing
  attributionControl: false       # Hide attribution
  logoPosition: bottom-right      # Move logo
  fadeDuration: 500               # Slower fade
```

## Localization

Customize UI text for different languages. One `locale:` table covers
MapLibre's own controls (keys like `NavigationControl.ZoomIn`) and the text

header). Keys you leave out stay in English.

```yaml
config:
  center: [-74.006, 40.7128]
  zoom: 12
  locale:
    "FullscreenControl.Enter": "Pantalla completa"
    "GeolocateControl.FindMyLocation": "Buscar mi ubicación"
    "NavigationControl.ResetBearing": "Restablecer orientación"
    "NavigationControl.ZoomIn": "Acercar"
    "NavigationControl.ZoomOut": "Alejar"
    "maplibre-yaml.Legend.Title": "Leyenda"
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"
```

[Accessibility & languages](/guides/accessibility-languages/) lists every
key, and shows how to give the map a name and description for screen
readers (`title:` and `description:`).

## Map Controls

Configure which controls are displayed and where.

### Controls Structure

```yaml
controls:
  navigation: true | { enabled: true, position: "top-right" }
  geolocate: true | { enabled: true, position: "top-right" }
  scale: true | { enabled: true, position: "bottom-left" }
  fullscreen: true | { enabled: true, position: "top-right" }
  attribution: true | { enabled: true, position: "bottom-right" }
```

### Available Controls

| Control | Default Position | Description |
|---------|------------------|-------------|
| `navigation` | `top-right` | Zoom and rotation controls |
| `geolocate` | `top-right` | User geolocation button |
| `scale` | `bottom-left` | Distance scale indicator |
| `fullscreen` | `top-right` | Fullscreen toggle |
| `attribution` | `bottom-right` | Attribution text |
| `globe` | `top-right` | Globe/mercator projection toggle (maplibre-gl ≥ 5.0.0; older runtimes warn and omit it) |
| `terrain` | `top-right` | 3D terrain on/off toggle for the document's [`terrain:`](#terrain-sky--projection) (warns and is omitted when the document declares none) |

- `top-left`

## Legend

Display a map legend showing layer information.

A map with a [`classify:`](/guides/thematic-maps/) layer gets a legend even
without a `legend:` block — the default one below (top-left, open, headed
"Legend"), listing each classified layer's classes. Write `legend: false` to
turn it off, or a `legend:` block to place and title it yourself.

### Legend Structure

```yaml
legend:
  title: "Map Legend"
  position: top-left
  collapsed: false
  items:
    - color: "#ff0000"
      label: "Category 1"
      shape: circle
    - color: "#00ff00"
      label: "Category 2"
      shape: square
```

### Legend Properties

| Property | Type | Default | Description |
|----------|------|---------|-------------|
| `position` | string | `"top-left"` | Legend position |
| `title` | string | - | A heading inside the legend panel (the toggle above it always reads "Legend") |
| `collapsed` | boolean | `false` | Start collapsed |
| `items` | array | - | Custom legend items |

The legend is a collapsible panel whose header — the part you click to open
or close it — always reads **Legend**, so a screen reader announces "Legend,
expanded" on every map. Your `title:` is a heading inside the panel, above
the entries; a `title` of "Legend" (or none) adds no heading, so the word is
never shown twice. Story legends work the same way. To show the header in
another language, set `maplibre-yaml.Legend.Title` in `config.locale` (see
[Accessibility & languages](/guides/accessibility-languages/)).

:::note[Changed in 0.9]
Before 0.9 a plain map's `title:` replaced "Legend" in the header. Your
document needs no change: the title now appears as the panel's heading.
:::

### Legend Item Properties

| Property | Type | Required | Default | Description |
|----------|------|----------|---------|-------------|
| `color` | string | Yes | - | Item color (CSS color) |
| `label` | string | Yes | - | Item label text |
| `shape` | string | No | `"square"` | Symbol shape: `circle`, `square`, `line`, `icon` |
| `icon` | string | No | - | Icon name or URL (when `shape: icon`) |

### Examples

#### Automatic Legend

If `items` is not provided, legend items are extracted from layers with legend configuration:

```yaml
legend:
  title: "Earthquake Magnitude"
  position: top-left
```

#### Custom Legend Items

```yaml
legend:
  title: "Features"
  position: top-right
  collapsed: false
  items:
    - color: "#e74c3c"
      label: "High Priority"
      shape: circle
    - color: "#f39c12"
      label: "Medium Priority"
      shape: circle
    - color: "#2ecc71"
      label: "Low Priority"
      shape: circle
```

#### Line Legend

```yaml
legend:
  title: "Routes"
  position: bottom-left
  items:
    - color: "#3b82f6"
      label: "Highway"
      shape: line
    - color: "#10b981"
      label: "Local Road"
      shape: line
```

#### Icon Legend

```yaml
legend:
  title: "Points of Interest"
  position: top-left
  items:
    - color: "#000000"
      label: "Restaurant"
      shape: icon
      icon: "restaurant"
    - color: "#000000"
      label: "Hotel"
```

## Using Global Default Style

Define a default map style once in global config:

```yaml
config:
  defaultMapStyle: "https://tiles.openfreemap.org/styles/liberty"

pages:
  - path: "/"
    title: "Home"
    blocks:
      - type: map
        id: map1
        config:
          center: [-74, 40]
          zoom: 12
          # mapStyle inherited from global config

      - type: map
        id: map2
        config:
          center: [139, 35]
          zoom: 12
          # mapStyle inherited from global config
```
