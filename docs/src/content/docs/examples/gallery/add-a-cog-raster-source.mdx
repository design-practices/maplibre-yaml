A [Cloud Optimized GeoTIFF](https://cogeo.org/) (COG) is one image file laid out so the browser can read just the tiles it draws. Since 0.9 a `.tif` URL on a `raster` source is all it takes: maplibre-yaml reads the file with the COG protocol, so there is no tile server and no page JavaScript. Here one COG is the imagery, and a second holds elevation, which shades the hills and lifts the map into 3D.

## What to notice

- `type: raster` stays the MapLibre source type; the `.tif` file name tells maplibre-yaml to read it as a COG. For a URL without the extension, add `format: cog`.
- `type: raster-dem` reads the same kind of file as elevation: it feeds the `hillshade` layer and `terrain:`. No `encoding:` or `tileSize:` is needed; maplibre-yaml sets what the COG reader produces.
- `fitTo` frames the imagery file's own extent, read from the file.
- COGs must be in Web Mercator (EPSG:3857). A file in another projection is refused with the `gdalwarp` command that converts it.
- The files are read with HTTP range requests, so they need a host that supports them (GitHub Pages, Netlify, S3, R2; not `python -m http.server`).
- Data: synthetic and public domain (a fictional island), generated by `scripts/fixtures/cog.py`.
