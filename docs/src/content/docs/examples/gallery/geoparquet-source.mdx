[GeoParquet](https://geoparquet.org/) stores features as a columnar table. A `.parquet` URL on a `geojson` source is all it takes: maplibre-yaml reads the file into the source, so layers, popups, `classify:`, the legend and `fitTo` behave exactly as for a `.geojson` file — and it reads only the columns the document uses. Click a district; zoom in past 11 to see the stations, which are read **by view**.

## What to notice

- `type: geojson` stays the MapLibre source type; the `.parquet` file name tells maplibre-yaml to read it as GeoParquet. For a URL without the extension, add `format: geoparquet`.
- Only the columns this document references are read: `name`, `category` and `population` from the districts (the popup and `classify:`), `kind` from the stations (the colour). Set `columns:` to choose yourself, or `columns: all`.
- `districts` is read whole (the default, `load: all`), so `classify:` computes its quantile classes from every district.
- `points` uses `load: { mode: viewport, minzoom: 11 }`: only the rows in view are read, using the file's `bbox` column and its location-sorted row groups, and re-read as the map moves. Below zoom 11 nothing is read. This needs a host with HTTP range requests (GitHub Pages, Netlify, S3, R2; not `python -m http.server`).
- `fitTo` frames the decoded districts.
- Data: synthetic and public domain (a fictional sea area), generated by `scripts/fixtures/cloud-native.py`.

More: [Cloud-native data](/guides/cloud-native-data/#geoparquet) — making a GeoParquet file, sizes, hosting, and what the map says when a file can't be read.
