import { Badge } from '@astrojs/starlight/components';

The [MapLibre GL JS examples gallery](https://maplibre.org/maplibre-gl-js/docs/examples/) is the shared vocabulary of web mapping. This page tracks all **139** of its examples against maplibre-yaml — which ones the format expresses today, which need a documented escape hatch, and which point at gaps we're tracking. It doubles as an honest capability matrix: badges flip as features land.

- <Badge text="Pure YAML" variant="success" /> — replicated as a single YAML document; the title links to our version.
- <Badge text="Escape hatch" variant="caution" /> — reachable with YAML plus a documented hatch (`mapReady()`, the `@maplibre-yaml/core/maplibre` module, `updateLayerData()`, an inline style object, raw expressions, or a protocol plugin). Each page shows the YAML, the page markup (controls ride `<ml-map>`'s corner slots) and the JS side by side; the JS shown is the JS the browser suite runs.
- <Badge text="Gap" variant="danger" /> — a missing YAML surface, tracked in the issue ledger.
- <Badge text="Extension" variant="note" /> — in reach of the experimental [effects API](/guides/effects/) (`registerEffect()`): the document names a registered extension on an ordinary layer, and that layer stays the fallback. **No backend for these rows ships in 0.7.** Each needs one that is tracked in the issue ledger; until it lands, follow the upstream link.
- <Badge text="JS territory" variant="default" /> — deep imperative work (game loops, 3D Tiles streaming, renderers that read MapLibre internals, constructor-only callbacks) that a declarative format shouldn't chase; follow the upstream link.

Every construct these examples use also carries a declared **eject class** — what `mlym emit` does with it (ejects / ejects via fallback / declared absence). See [Eject Classes](/guides/eject-classes/).

Unlinked titles point at the upstream original; a badge-only row carries its reasoning after the title.
