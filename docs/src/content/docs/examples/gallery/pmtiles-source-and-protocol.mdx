## What to notice

- `type: vector` stays the MapLibre source type; the URL says the file is a PMTiles archive. `url: https://…/firenze.pmtiles` (no scheme) works the same — and so does a file on your own site, `url: data/firenze.pmtiles`.
- No page JavaScript, no import-map entry: the PMTiles reader is part of `@maplibre-yaml/core` (CDN build and npm package alike).
- The archive is read in parts (range requests), so the host must support them — GitHub Pages, Netlify, S3 and R2 do; `python -m http.server` doesn't. See [Cloud-native data](/guides/cloud-native-data/#hosting-range-requests-and-cors).
- Data: [Protomaps](https://protomaps.com/) Florence sample extract (ODbL).

## Register the protocol yourself \{#registering-the-protocol-yourself-still-supported}

Register the protocol in page JavaScript when you need custom headers or a custom `Source`; a page that registers `pmtiles` itself keeps its registration. Register through `@maplibre-yaml/core/maplibre`, so the protocol lands on the same maplibre-gl module `<ml-map>` renders with:

```js
import { addProtocol } from "@maplibre-yaml/core/maplibre";
import { Protocol } from "pmtiles";

addProtocol("pmtiles", new Protocol().tile);
```

It is also how to use PMTiles inside a *basemap style* loaded from a URL (a Protomaps basemap): maplibre-yaml can't see inside that style before MapLibre loads it.
