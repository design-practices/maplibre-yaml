Replicates the MapLibre example [PMTiles source and protocol](https://maplibre.org/maplibre-gl-js/docs/examples/pmtiles-source-and-protocol/). Protocol plugins register on the maplibre-gl *module*, not a map instance — which is why this was an unreachable gap until 0.7: `@maplibre-yaml/core/maplibre` re-exports the exact module `<ml-map>` renders with, so `addProtocol` lands where the document's requests actually go.

## The escape hatch

```js
import { addProtocol } from "@maplibre-yaml/core/maplibre";
import { Protocol } from "pmtiles";

const protocol = new Protocol();
addProtocol("pmtiles", protocol.tile);
```

## What to notice

- The YAML stays purely declarative — `pmtiles://` in the source URL is the only trace of the plugin. Validation and eject treat it as an ordinary vector source.
- The import path matters: registering `addProtocol` from a *separately loaded* maplibre-gl (a CDN copy, a second bundle) registers on a module the map never consults, and the source fails with no obvious cause. The `@maplibre-yaml/core/maplibre` subpath guarantees module identity with the renderer.
- The same hatch covers COG, custom tile transforms, and any other `addProtocol` plugin.
