There are two ways to load maplibre-yaml:

- **From a CDN, in a plain HTML page.** No install and no build step: you
  write an HTML file and a YAML file and serve the folder. Start here if you
  are new. See [Browser usage (CDN)](#browser-usage-cdn).
- **From npm, with a bundler** such as Vite. See
  [Using a bundler (Vite)](#using-a-bundler-vite).

## Browser usage (CDN)

For prototypes, small sites and simple pages, you can use
maplibre-yaml directly from a CDN: no install, no build tools. An
[import map](https://developer.mozilla.org/en-US/docs/Web/HTML/Element/script/type/importmap)
tells the browser where to find `maplibre-gl`, which the register bundle keeps
external (not bundled). Leave it out and the page stays blank, with
*Failed to resolve module specifier "maplibre-gl"* in the console.

```html
<!DOCTYPE html>
<html lang="en">
  <head>
    <meta charset="utf-8" />
    <!-- Without this line, phones lay the page out at desktop width and the map looks tiny -->
    <meta name="viewport" content="width=device-width, initial-scale=1" />
    <title>My map</title>
    <link
      href="https://unpkg.com/maplibre-gl@6/dist/maplibre-gl.css"
      rel="stylesheet"
    />
    <style>
      ml-map {
        display: block;
        height: 400px;
      }
    </style>
    <!-- Tell the browser where to find maplibre-gl -->
    <script type="importmap">
      { "imports": { "maplibre-gl": "https://unpkg.com/maplibre-gl@6/dist/maplibre-gl.mjs" } }
    </script>
    <!-- Register the <ml-map> web component -->
    <script
      type="module"
      src="https://unpkg.com/@maplibre-yaml/core@0.9/register.js"
    ></script>
  </head>
  <body>
    <ml-map src="./map.yaml"></ml-map>
  </body>
</html>
```

Save this next to it as `map.yaml` (the file `src="./map.yaml"` loads):

```yaml title="map.yaml"
type: map
id: my-map
config:
  center: [-74.006, 40.7128]
  zoom: 11
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"
layers:
  - id: marker
    type: circle
    source:
      type: geojson
      data:
        type: FeatureCollection
        features:
          - type: Feature
            geometry: { type: Point, coordinates: [-74.006, 40.7128] }
            properties: { name: "New York" }
    paint:
      circle-radius: 10
      circle-color: "#e63946"
```

Serve the folder with `npx serve .` and open the address it prints. (Another
static server works too if it supports range requests, which PMTiles,
FlatGeobuf, GeoParquet and COG files need; `python -m http.server` doesn't.) Opening the HTML file directly (a `file://`
address) does not work: the browser blocks the page from fetching `map.yaml`.

### Versions in CDN URLs

The version in `@maplibre-yaml/core@0.9` names a release line: the URL loads
the newest release in that line, so bug fixes arrive automatically, and the
next line, which may change behaviour, never arrives by surprise. Change the
number on purpose when you upgrade; these docs always show the current line.
`maplibre-gl@6` works the same way for MapLibre.

### Hosting the files yourself

To serve maplibre-yaml from your own site instead of a CDN, copy the
package's **whole `dist/` folder** (from `node_modules/@maplibre-yaml/core/`,
or the package on unpkg) and load `dist/register.browser.js` from it:

```html
<script type="module" src="/js/maplibre-yaml/dist/register.browser.js"></script>
```

Some parts of maplibre-yaml load on demand, only for maps that use them, and
the browser fetches them from `dist/chunks/` next to the script: the readers
for [PMTiles, FlatGeobuf, GeoParquet and COG files](/guides/cloud-native-data/)
(`pmtiles.js`, `flatgeobuf.js`, `geoparquet.js` and `geoparquet-brotli.js`,
`cog.js` with its image codecs `cog-deflate.js`, `cog-jpeg.js`, `cog-lerc.js`
and `cog-zstd.js`) and the [Protomaps basemap](/guides/cloud-native-data/#host-your-own-basemap)
style generator (`protomaps-basemap.js`). A copy of only `register.browser.js` works for every
other map; a map that needs a missing reader shows a notice naming the file.

### JavaScript API from a CDN

To use the JavaScript API (`YAMLParser`, `MapRenderer`) from a CDN instead of the web component, import the package from esm.sh, which resolves `yaml` and `zod` for you. Keep the same import map and add `?external=maplibre-gl` so the library uses the maplibre-gl you pinned, not a second copy chosen by esm.sh:

```html
<script type="importmap">
  { "imports": { "maplibre-gl": "https://unpkg.com/maplibre-gl@6/dist/maplibre-gl.mjs" } }
</script>
<script type="module">
  import {
    YAMLParser,
    MapRenderer,
  } from "https://esm.sh/@maplibre-yaml/core@0.9?external=maplibre-gl";

  // Your map code here
</script>
```

## Supported maplibre-gl versions

maplibre-yaml works with maplibre-gl **v4, v5 and v6** (v6 recommended for new
projects); the peer range is `^3.0.0 || ^4.0.0 || ^5.0.0 || ^6.4.1`. Every
example on this page pins major 6 (`maplibre-gl@^6` for npm, `maplibre-gl@6` for the
CSS and the import map). Pin whichever supported major your project uses, and
keep the CSS on the same major as the JS. Cloud Optimized GeoTIFF (COG)
sources need maplibre-gl 4.5 or later
([Large data](/guides/cloud-native-data/)).

maplibre-gl v6 is ESM-only: the browser entry is `dist/maplibre-gl.mjs` (there
is no `maplibre-gl.js` UMD file any more), so an import map points at that file
directly. It loads its worker (`maplibre-gl-worker.mjs`) from next to its own
module, which works as-is from a CDN or any static server.

**Bundlers (Vite, webpack, …) on v6:** inside a bundle MapLibre cannot find its
worker, and every map fails with *"Worker failed to load"* (maplibre-yaml's
`ml-map:error` then spells out this fix). Tell MapLibre where the worker is
in the same entry file that imports maplibre-yaml. With Vite:

```ts
import { setWorkerUrl } from "maplibre-gl";
import workerUrl from "maplibre-gl/dist/maplibre-gl-worker.mjs?worker&url";

setWorkerUrl(workerUrl);
```

The full setup is under [Using a bundler (Vite)](#using-a-bundler-vite). The
`@maplibre-yaml/astro` components do this for you. v4 and v5 need nothing.

**Upgrading an existing project.** Before 1.0, a range such as `^0.8.1` in
`package.json` stays within 0.8.x, so a newer minor release never installs on
its own. Run `npm install @maplibre-yaml/core@latest` (add
`@maplibre-yaml/astro@latest` in an Astro project, see
[Astro](/integrations/astro/#upgrading-an-existing-project)) to move to the
current release. [Upgrading to 0.9](/getting-started/upgrading/) lists what
changes, for npm and CDN pages alike.

## Using a bundler (Vite)

With npm and a bundler, your entry file does three things: point maplibre-gl 6
at its worker, register `<ml-map>`, and load MapLibre's CSS. Starting from a
new Vite project:

```bash
npm create vite@latest my-map -- --template vanilla
cd my-map
npm install @maplibre-yaml/core maplibre-gl@^6
```

Replace the contents of `src/main.js` with:

```javascript
// src/main.js
// maplibre-gl 6 loads its worker from a separate file. Inside a Vite bundle it
// cannot find that file by itself, so tell it where it is.
import { setWorkerUrl } from "maplibre-gl";
import workerUrl from "maplibre-gl/dist/maplibre-gl-worker.mjs?worker&url";
import "@maplibre-yaml/core/register";
import "maplibre-gl/dist/maplibre-gl.css";

setWorkerUrl(workerUrl);
```

Replace the `<body>` of `index.html` with:

```html
<body style="margin: 0;">
  <ml-map src="./map.yaml" style="display: block; height: 100vh;"></ml-map>
  <script type="module" src="/src/main.js"></script>
</body>
```

Put `map.yaml` in the **`public/`** folder (`public/map.yaml`), together with
any data files it loads. Vite serves `public/` at the site root during
`npm run dev` and copies it into `dist/` on `npm run build`.

<Aside type="caution" title="YAML next to index.html works in dev, then breaks">
A `map.yaml` next to `index.html` loads in `npm run dev`, but `npm run build`
does not copy it: Vite only bundles files your code imports. The built site
then answers the request with `index.html`, and the map shows
*YAML syntax error … `<!doctype html>`*. Keep every file that `src=` or a
`url:` in your YAML points at in `public/`.
</Aside>

`npm run dev` shows the map; `npm run build` then `npm run preview` serves
the production build. On maplibre-gl 4 or 5, delete the two worker lines and
the `setWorkerUrl` call (there is no worker file to import, and the build
fails if you keep them).

The same entry-file setup applies to other bundlers and frameworks: see
[Framework Compatibility](/integrations/web-components/#framework-compatibility).

## Web component registration

To use the `<ml-map>` web component, import the registration module:

```javascript
import "@maplibre-yaml/core/register";
```

Then use it in your HTML:

```html
<ml-map
  style="display: block; width: 100%; height: 400px;"
  config='{"type":"map","id":"my-map","config":{"center":[-74,40.7],"zoom":10,"mapStyle":"https://tiles.openfreemap.org/styles/liberty"},"layers":[]}'
>
</ml-map>
```

## TypeScript

maplibre-yaml is written in TypeScript and includes type definitions. No additional `@types` packages are needed.

```typescript
import { YAMLParser, MapRenderer } from "@maplibre-yaml/core";
import type { MapBlock } from "@maplibre-yaml/core";

// For a single `type: map` document:
const mapBlock: MapBlock = YAMLParser.parseMapBlock(yamlString);
```

## Verify installation

Check that the parser loads and validates a document (this checks parsing
only; a map still needs a page to render in):

```javascript
import { YAMLParser } from "@maplibre-yaml/core";

const yaml = `
type: map
id: test
config:
  center: [0, 0]
  zoom: 2
  mapStyle: "https://tiles.openfreemap.org/styles/liberty"
layers: []
`;

const result = YAMLParser.safeParseMapBlock(yaml);

if (result.success) {
  console.log("✓ maplibre-yaml parsed the document");
  console.log("  Map ID:", result.data.id);
} else {
  for (const error of result.errors) {
    console.error(`✗ ${error.path}: ${error.message}`);
  }
}
```
