maplibre-yaml draws a web map from a YAML file: you describe the map, its
data and its styling, and a script on the page does the rest. Pick the row
that matches what you want to make. Each one says where to **start**, what to
read **next**, and where to **look things up**. New to the library? Read
[What is maplibre-yaml?](/getting-started/introduction/) first.

## Try it in the browser first

The fastest way to see what a map document does is the
[playground](/playground/): edit a map in the browser and watch it change as
you type, with nothing to install or save. Mistakes are explained where you
make them. When you like the map, download it as a folder that works, or
share it as a link.

## Already know MapLibre?

A map document's layers are MapLibre style layers: `paint:`, `layout:`,
`filter:` and expressions follow the
[style spec](https://maplibre.org/maplibre-style-spec/) unchanged. What
maplibre-yaml adds is data loading, popups, legends, controls and stories,
written in the same file.

- **Start:** [How it works](/getting-started/introduction/#how-it-works), then
  the [MapLibre examples in YAML](/examples/gallery/): every official MapLibre
  example, and which ones the format expresses on its own
- **Then:** [Export to style.json](/guides/export/): `mlym emit` turns a map
  document into a plain `style.json`, and
  [Export classes](/guides/export-classes/) lists what each part becomes
- **Look up:** [JavaScript API](/integrations/vanilla-js/) ·
  [TypeScript API](/reference/api/)

## Looking something up

Every key a map document or story file takes, with its type and default, is

`<ml-scrollytelling>` attributes, events and styling hooks are in
[Elements](/reference/elements/), and the command-line tool's commands are in
the [CLI reference](/cli/reference/).
