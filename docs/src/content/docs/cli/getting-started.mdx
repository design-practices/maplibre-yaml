The maplibre-yaml CLI provides command-line tools for starting a project,
validating and previewing your YAML map configurations, and exporting them to
`style.json`. It helps catch errors early and enables rapid development with
hot reload.

The commands on this page use `npx maplibre-yaml`, which works without
installing anything (you need [Node.js](https://nodejs.org/) 20.9 or later;
the current LTS, 22 or 24, is recommended).
`maplibre-yaml` is a small package that runs `@maplibre-yaml/cli`;
`npx @maplibre-yaml/cli` is the same program under its full name.
If you install the CLI, the shorter `mlym` does the same; see
[Short Alias](#short-alias).

## Installation

### Global Installation

Install the CLI globally to use it anywhere:

```bash
npm install -g @maplibre-yaml/cli
```

Or with pnpm:

```bash
pnpm add -g @maplibre-yaml/cli
```

### Using npx

You can use the CLI without installing it:

```bash
npx maplibre-yaml <command>
```

### Short Alias

Once the CLI is installed, it also answers to the shorter `mlym`:

```bash
mlym validate config.yaml
```

`mlym` is a command name inside `@maplibre-yaml/cli`, not a package of its
own, so `npx mlym` without an install fails with a 404. For a one-off run
without installing, use `npx maplibre-yaml validate config.yaml` (a small
package that runs the CLI) or the full name, `npx maplibre-yaml validate
config.yaml`. Or install the CLI into your project first and then use the
short name through npx:

```bash
npm install --save-dev @maplibre-yaml/cli
npx mlym validate config.yaml
```

## Start a Project

`init` creates a folder with a working map in it:

```bash
npx maplibre-yaml init my-map
cd my-map
npx serve .
```

Open the address `serve` prints (usually http://localhost:3000). The `basic`
template (the default) is a plain HTML page and a `map.yaml`, loaded from a
CDN, so there is nothing to install or build. Edit `map.yaml` and reload the
page. Opening `index.html` by double-clicking it does not work: browsers block
a `file://` page from loading `map.yaml`.

Other templates: `--template astro` (an Astro site) and `--template story` (a
scrollytelling document). Run `npx maplibre-yaml init --list` to see
them, and see the [init reference](/cli/reference/#init) for details.

## Validate Configuration

Validate your YAML configuration files to catch errors before runtime.

### Basic Validation

Validate a single file:

```bash
npx maplibre-yaml validate my-map.yaml
```

Output for valid configuration:

```
✓ my-map.yaml

✓ 1 file(s) valid
```

Output for invalid configuration:

```
✗ my-map.yaml
  error config: The document is missing config: — add a config: block with center:, zoom: and mapStyle:.

✗ 1 file(s) with issues: 1 error(s)
```

### Glob Patterns

Validate multiple files using glob patterns:

```bash
# Validate all YAML files in a directory
npx maplibre-yaml validate "configs/**/*.yaml"

# Validate specific patterns
npx maplibre-yaml validate "maps/*.yaml"

# Multiple patterns
npx maplibre-yaml validate "src/**/*.map.yaml" "configs/*.yaml"
```

Output with progress indicator (for >10 files):

```
Validating [████████████████████] 100% (25/25)
✓ Validated 25 files

✓ 23 file(s) valid
✗ 2 file(s) with issues: 3 error(s)
```

### Output Formats

Choose from multiple output formats:

#### Human-Readable (default)

```bash
npx maplibre-yaml validate my-map.yaml
```

#### JSON for CI/CD

Get structured JSON output:

```bash
npx maplibre-yaml validate my-map.yaml --format json
```

Output:

```json
{
  "valid": true,
  "files": [
    {
      "file": "my-map.yaml",
      "valid": true,
      "errors": [],
      "warnings": []
    }
  ],
  "summary": {
    "total": 1,
    "valid": 1,
    "invalid": 0,
    "errorCount": 0,
    "warningCount": 0
  }
}
```

#### SARIF for GitHub Code Scanning

Generate SARIF format for GitHub Advanced Security:

```bash
npx maplibre-yaml validate my-map.yaml --format sarif
```

#### VSCode Problem Matcher

Output format compatible with VSCode's Problem Matcher:

```bash
npx maplibre-yaml validate my-map.yaml --format vscode
```

Output:

```
/path/to/config.yaml:5:10: error: [config.center] Expected array, got string
/path/to/config.yaml:12:3: warning: [layers[0]] Deprecated property
```

See [VSCode Integration](/cli/vscode) for setup instructions.

### Watch Mode

Continuously validate files as they change:

```bash
npx maplibre-yaml validate "configs/**/*.yaml" --watch
```

Features:

- **Intelligent Caching**: Only re-validates changed files
- **Fast**: Cached validations complete in less than 1ms
- **Real-time Feedback**: Shows errors immediately on save

### Strict Mode

Treat warnings as errors. Strict mode is on by default when the `CI`
environment variable is set (CI services set it) and off on your own machine;
`--strict` and `--no-strict` override that:

```bash
npx maplibre-yaml validate my-map.yaml --strict
```

### Exit Codes

The validate command uses specific exit codes for automation:

| Code | Meaning             |
| ---- | ------------------- |
| 0    | Valid configuration |
| 1    | Errors found, including YAML syntax errors |
| 2    | No file matched the pattern |
| 4    | Unexpected internal error |

### Performance

The CLI is highly optimized for speed:

- **100 files**: Validated in ~80ms
- **Single file**: Validated in ~1ms
- **Watch mode**: Cached validations in ~1ms
- **Parallel processing**: Configurable concurrency (default: 10)

Example CI usage:

```yaml
# .github/workflows/validate.yml
name: Validate Maps
on: [push, pull_request]
jobs:
  validate:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
      - run: npx maplibre-yaml validate "configs/**/*.yaml" --format json
```

GitHub Code Scanning with SARIF:

```yaml
# .github/workflows/code-scanning.yml
name: Code Scanning
on: [push, pull_request]
jobs:
  analyze:
    runs-on: ubuntu-latest
    permissions:
      security-events: write
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
      - run: npx maplibre-yaml validate "**/*.yaml" --format sarif > results.sarif
      - uses: github/codeql-action/upload-sarif@v2
        with:
          sarif_file: results.sarif
```

## Preview Your Map

Start a local development server with hot reload to preview your map as you edit.

### Basic Preview

```bash
npx maplibre-yaml preview my-map.yaml
```

This renders the YAML document on a page of its own (to see your own HTML page
around the map, serve your folder with `npx serve .` instead). It will:

- Start a Vite development server on port 3000
- Open your browser automatically
- Watch the YAML file for changes
- Reload the map when you save edits

### Custom Port

Use a different port:

```bash
npx maplibre-yaml preview my-map.yaml --port 8080
```

### Don't Open Browser

Start the server without opening the browser:

```bash
npx maplibre-yaml preview my-map.yaml --no-open
```

### Preview Features

The preview server includes:

- **Hot Reload**: Automatically refreshes when you edit the YAML file
- **Error Overlay**: Shows configuration errors with helpful messages
- **Status Bar**: Displays connection state and file path
- **Live Validation**: Validates configuration on every change
- **MapLibre Integration**: Full support for all MapLibre features

### Error Handling

If your configuration has errors, the preview will show:

- A dark overlay with the error message
- Red status indicator
- Specific error details (the field path and message)
- No map render (prevents confusion)

Example error display:

```
Configuration Error
━━━━━━━━━━━━━━━━━
config: The document is missing config: — add a config: block with center:, zoom: and mapStyle:.
```

### Development Workflow

1. Start the preview server:

   ```bash
   npx maplibre-yaml preview my-map.yaml
   ```

2. Edit your YAML file in your editor

3. Save the file

4. Preview automatically reloads with changes

5. Fix any errors shown in the overlay

6. Repeat!

npx maplibre-yaml --version
