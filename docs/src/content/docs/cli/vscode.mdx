Run maplibre-yaml's validator from VS Code and see its errors, warnings and notes in the Problems panel, next to the lines they belong to.

## Quick Start (No Extension Required)

You can use maplibre-yaml with VS Code immediately using the built-in **Tasks** feature:

### Step 1: Add Task Configuration

Create or update `.vscode/tasks.json` in your project:

```json
{
  "version": "2.0.0",
  "tasks": [
    {
      "label": "maplibre-yaml: Validate Current File",
      "type": "shell",
      "command": "npx",
      "args": [
        "@maplibre-yaml/cli",
        "validate",
        "${file}",
        "--format",
        "vscode"
      ],
      "problemMatcher": {
        "owner": "maplibre-yaml",
        "fileLocation": "absolute",
        "pattern": {
          "regexp": "^(.+):(\\d+):(\\d+): (error|warning|info): (.*)$",
          "file": 1,
          "line": 2,
          "column": 3,
          "severity": 4,
          "message": 5
        }
      },
      "presentation": {
        "reveal": "silent",
        "panel": "shared"
      },
      "group": "build"
    }
  ]
}
```

### Step 2: Run the Task

1. Open a `.yaml` file
2. Press `Cmd+Shift+P` (Mac) or `Ctrl+Shift+P` (Windows/Linux)
3. Type "Run Task"
4. Select **maplibre-yaml: Validate Current File**

### Step 3: View Errors

Errors appear in the **Problems** panel (`Cmd+Shift+M` / `Ctrl+Shift+M`),
each with its file, line and column: click one to jump to it. Warnings (for
example a map with no basemap, or a style value starting with the reserved
`=`) appear as warnings, and notes, which explain how a valid value is read
(such as a basemap written as just a `.pmtiles` file), appear as information.

## Configuration Files

### Complete tasks.json

Download the complete configuration with all tasks:
[tasks.json example](https://github.com/design-practices/maplibre-yaml/blob/main/docs/examples/vscode/tasks.json)

It includes three tasks, whose problem matchers pick up errors, warnings and
notes (`info`):

- **Validate Current File**: Validates the open file
- **Validate All Configs**: Validates all YAML files
- **Watch and Validate**: Continuous validation

### YAML Schema Settings

For autocomplete, hover docs and as-you-type checks, install the Red Hat
**YAML** extension (`redhat.vscode-yaml`) and add to `.vscode/settings.json`:

```json
{
  "yaml.schemas": {
    "https://docs.maplibre-yaml.org/schema/latest/map.schema.json": [
      "configs/**/*.yaml",
      "**/*.map.yaml"
    ],
    "https://docs.maplibre-yaml.org/schema/latest/scrollytelling.schema.json": [
      "**/*.story.yaml"
    ]
  },
  "files.associations": {
    "*.map.yaml": "yaml",
    "**/configs/**/*.yaml": "yaml"
  }
}
```

Or skip the settings and put a modeline on the first line of each file, as
the files `init` creates do:

```yaml no-validate
# yaml-language-server: $schema=https://docs.maplibre-yaml.org/schema/latest/map.schema.json
```

[Editor Setup](/guides/editor-setup/) covers both, the other block schemas,
and offline use.

[Download complete settings.json](https://github.com/design-practices/maplibre-yaml/blob/main/docs/examples/vscode/settings.json)

## Usage Examples

### Validate on Save

Set up a keyboard shortcut:

1. Press `Cmd+K Cmd+S` (Mac) or `Ctrl+K Ctrl+S` (Windows/Linux)
2. Search for "Run Task"
3. Add keybinding (e.g., `Cmd+Shift+V`)
4. Configure to run **maplibre-yaml: Validate Current File**

### Batch Validation

Run **maplibre-yaml: Validate All Configs** to validate all files in your project.

Output appears in the Problems panel grouped by file.

### Watch Mode

Run **maplibre-yaml: Watch and Validate** for continuous validation:

- Runs in background
- Updates Problems panel on file save
- Shows real-time errors

## Problem Matcher

VS Code's problem matcher parses CLI output in the format:

```
file:line:column: severity: [path] message
```

Example:
```
/Users/you/project/config.yaml:4:11: error: [config.center] center needs square brackets: center: [0, 0]
```

This enables VS Code to:
- Parse error locations
- Underline errors in the editor
- Display in Problems panel
- Provide quick navigation

## Output Format

The `--format vscode` flag produces Problem Matcher-compatible output:

```bash
npx maplibre-yaml validate config.yaml --format vscode
```

Output (one line per problem; `severity` is `error`, `warning`, or `info`
for a note):
```
/path/to/config.yaml:4:11: error: [config.center] center needs square brackets: center: [0, 0]
/path/to/config.yaml:3:1: warning: [config.mapStyle] No mapStyle: this map has no basemap. …
/path/to/other.yaml:6:3: info: [config.mapStyle] mapStyle: "data/nyc.pmtiles" names a .pmtiles file, so it is read as a Protomaps basemap …
```

## Checking as you type

There is no maplibre-yaml extension for VS Code. As-you-type checking,
autocomplete and hover documentation come from the Red Hat **YAML** extension
reading maplibre-yaml's JSON Schema (see [YAML Schema Settings](#yaml-schema-settings)
above and [Editor setup](/guides/editor-setup/)). The task on this page adds
what the schema can't check: the validator's own rules, such as a layer
naming a source the document doesn't declare (with a "did you mean"), a
misspelt `fitTo` source, or a map with no basemap.

## Troubleshooting

### Errors Don't Appear in Problems Panel

1. Check that the task includes `problemMatcher`
2. Verify `--format vscode` is in the args
3. Check that `fileLocation` is `"absolute"`: the CLI prints full paths
4. Check Problems panel filter settings
5. Notes missing? The `regexp` must match `info` as well as `error` and `warning`

### Task Not Found

1. Ensure `.vscode/tasks.json` exists in project root
2. Reload VSCode window
3. Check JSON syntax is valid

### Permission Errors

On first run, VSCode may ask to allow task execution. Click "Allow" to proceed.
